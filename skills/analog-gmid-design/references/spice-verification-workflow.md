# SPICE 검증 워크플로우 — 폐루프 수렴 + LUT↔SPICE 교차검증 (정본)

> SKILL.md §5 체크리스트가 가리키는 두 필수 절차의 상세 정본. SKILL.md는 이 문서를 재서술하지
> 않고 존재와 위치만 가리킨다.

## 1. 폐루프 SPICE 수렴 워크플로우 (필수 — 이 skill의 헤드라인 발견)

2단 이상 OTA, CMFB가 있는 회로 등 **여러 소자가 전기적으로 얽힌 폐루프**를 SPICE로 바이어스
검증할 때, "전체 회로를 한 번에 자기일관되게 수렴시키는 바이어스 조합을 찾는다"는 접근은
자유도가 실제 미지수 개수보다 부족해 잘 안 풀리는 경우가 많다(실측: 2개 자유도로 12개 소자
얽힌 2단 OTA를 풀려다 실패). **대신 다음 순서로 소자 단위로 분해해서 풀 것**:

```
1. §1~§5 sizing이 가정한 각 노드의 전압 배분(예: 스택 전체 VDD를 소자 수만큼 나눈 예산)을
   "경계조건"으로 명시적으로 고정한다(자기일관되게 흐르도록 두지 않는다).
2. 그 경계조건 하에서, 소자마다 게이트 전압 "하나만" 이분탐색으로 풀어 목표 ID를 맞춘다
   (단일소자 검증과 동일한 방식 — 그 소자만 떼어 W/L/경계전압 고정, 게이트만 미지수).
3. 이분탐색 방향(게이트를 올리면 전류가 느나 주나)은 가정하지 말고, 탐색 시작 전 양끝값에서
   먼저 측정해 실측으로 방향을 정한다 — 극성별로 방향이 반대라 가정이 자주 틀린다.
4. 실제로 같은 물리적 바이어스 노드를 공유하는 소자들(예: 두 tail 소자가 같은 기준전류를
   미러링)은 하나의 방정식으로 묶지 말고, 각각 독립적으로 푼 뒤 그 결과를 사후 대조한다
   (차이가 작으면 "거의 자기일관적"이라는 검증 신호, 크면 설계 결함 신호).
5. 소자 하나가 목표 전류에 못 미치면 두 가지를 구분한다:
   - **경계조건(전압 배분) 문제**라면 — 그 경계조건 자체를 재조정(예: 균등 배분이 아니라
     소자별 필요 여유에 맞게 재분배)해서 다시 푼다.
   - **경계조건을 아무리 조정해도 안 풀리는 구조적 문제**(다음 단 게이트가 실제 신호 노드에
     묶여 있어 그 값을 임의로 못 바꾸는 경우 등)라면 — 억지로 다른 파라미터를 조작해 수렴시키지
     말고, **이것 자체를 회로의 실제 한계(발견)로 보고**한다(예: 이전 단 출력 DC 레벨과 다음
     단이 필요로 하는 게이트 전압이 근본적으로 안 맞는 경우 — CMFB가 전류뿐 아니라 그 노드의
     절대 전압까지 능동 제어해야 성립하는 구조라는 뜻이며, gm/ID 사이징만으로는 못 잡아낸다).
```

이 워크플로우의 핵심은 **"안 풀리는 문제"를 계속 파라미터를 바꿔가며 억지로 수렴시키려 하지
않고, 분해 가능한 부분(경계조건 재조정)과 분해해도 안 되는 부분(구조적 한계, 그대로 보고)을
구분하는 것**이다 — 후자를 전자처럼 다루면 시행착오만 늘어나고, 전자를 후자처럼 포기하면
고칠 수 있는 문제를 놓친다.

## 2. LUT↔SPICE 교차검증 절차 (필수 — 어기면 실제로 40분을 날린 실수)

`SemiEmpiricalGmIdLUT.gm_id_to_id_density()`의 반환값(`IDu`)을 "LUT가 맞는지 SPICE로
확인해보자"며 SPICE 실측치와 직접 비교하고 싶어질 때마다, **바로 비교하지 말고 반드시 이
순서를 따를 것**:

```
❌ 하지 말 것 (WRONG — 실제로 저지른 실수):
   IDu = lut.gm_id_to_id_density(gm_id, L, VDS)
   SPICE에 W=W_ref(예 5µm)짜리 소자를 그 gm_id에 해당하는 VGS로 인스턴스화 → 전류 측정
   IDu와 그 SPICE 전류를 직접 비교
   → 정확히 W_ref/L배 차이가 나는 게 정상인데, 이걸 "LUT가 SPICE보다 N배 틀렸다"고 오판하게 됨
     (IDu는 "W=L 기준" 전류이지 "W=W_ref에서 잰 전류"가 아니기 때문 — 서로 다른 정규화)

✅ 반드시 이렇게 할 것:
   1. IDu = lut.gm_id_to_id_density(gm_id, L, VDS)
   2. W = L * ID_target / IDu                         (이 skill이 항상 쓰는 사이징 공식 그대로)
   3. 그 W로 SPICE 인스턴스화 → 전류 측정
   4. 측정된 전류가 ID_target과 일치하는지 확인 (일치해야 정상 — 정규화가 계산 안에서 상쇄됨)
```

이 절차를 건너뛰고 IDu를 직접 비교하면, 멀쩡한 LUT를 "버그"로 오판해 불필요한 재작업(전체
LUT 재스윕 ~40분)을 하게 된다 — `check_box_shape()`를 건너뛰고 SPICE로 바로 갔다가 재작업했던
실수와 같은 종류다. 자세한 사고 경위는 `sky130-worked-example.md` §3, 원리 설명은
`assets/sizing_recipe.py`의 `gm_id_to_id_density()` docstring 참고.

## 3. sympy 폐형식(closed-form) 대신 수치 MNA를 기본으로 삼을 것 (세션21, CMRR/PSRR 최대 49dB 오차 사고)

CMFB/class-AB처럼 **여러 소자가 상호 연결된 서브회로**(floating battery, 캐스코드 임피던스와
병렬로 물리는 저컨덕턴스 바이어스 싱크 등)를 포함한 회로의 소신호 응답(CMRR/PSRR/gain)을
sympy로 **정확해(exact closed-form)**를 구해서 풀려는 시도는 하지 말 것 — 이 프로젝트에서
실제로 큰 대가를 치르고 폐기된 접근이다.

**증상**: `current_reuse_telescopic_ota`의 캐스코드 임피던스 폐형식 기반 `psrr_estimate_db`가
실제(31소자 exact) 값과 최대 **49dB** 어긋남(폐형식 −41.5~−9.6dB vs 실제 −8.6~+20.4dB).

**시도했다가 실패한 것(순서대로)**:
1. 31소자/18노드를 sympy `linsolve()`로 통짜로 풀기 — fraction-free Gaussian elimination의
   중간식이 지수적으로 폭발, 수 분간 2.8GB+ 메모리, 진행 없음.
2. 5노드 서브회로를 먼저 **정확해**로 풀어 8노드에 대입 — 그 정확해 자체가 200항 넘는 유리식이
   되어 다시 폭주(3.3GB+). raw 분자가 6,000~16,000항까지 확인됨.
3. leading-order 근사를 그대로 구현 — exact 대비 worst 12.02dB 오차, 이 프로젝트 기준(worst
   2.36dB) 미달.
4. "추가 저컨덕턴스 소자(M10/M19)를 기존 Rout에 그냥 병렬로 얹기" 가설 — Adm은 근접했지만
   Acm/Ann은 부호까지 반대, 최대 1100배 오차.

**근본원인**: `M10`/`M19`(class-AB 바이어스 싱크, 캐스코드가 아니라 출력컨덕턴스 O(eps¹))가
캐스코드 임피던스(O(eps²), 훨씬 높음)와 병렬로 물리면 **컨덕턴스가 낮은 쪽이 회로를 지배**하는데,
옛 폐형식은 애초에 이 소자의 존재 자체를 모델링하지 않았다. sympy **정확해**는 이런 소자가
하나 추가되는 순간 다항식 크기가 감당 불가능해진다 — 이건 근사식이 부정확했던 게 아니라
"정확해 자체를 구하는 접근"이 소자 수에 지수적으로 못 버틴다는 구조적 문제다.

**해결**: `_mna_solve_smallsignal()`(`assets/sizing_recipe.py:2395`, 순수 Python Gaussian
elimination·부분피벗, 외부 의존성 없음) 신설 — 정확해가 아니라 **수치**로 풀면 노드 개수(18개든
51개든)와 무관하게 즉시 끝난다. connectivity는 `load_topology()`로 그대로 읽어(손타이핑 없음)
topology.json이 나중에 바뀌어도 solver가 조용히 어긋나지 않게 했다(`_full_circuit_devices()`/
`_full_circuit_response()`, 같은 파일 :2815/:2850).

**검증**: 완전히 다른 두 솔버(자체 Gaussian elimination vs ngspice AC 시뮬레이션)로
교차검증해 오차 0.0001~0.0002%(부동소수점 잡음 수준)까지 확인 — **새 numeric solver를 실전
배치 전 반드시 독립 시뮬레이터로 재검증**할 것(§2의 LUT↔SPICE 교차검증과 같은 정신).

**일반 원칙**: 회로가 상호 연결된 서브회로(floating battery, CMFB, 저컨덕턴스 바이어스 싱크가
캐스코드와 병렬로 물리는 구조 등)를 포함하면 **sympy 정확해는 처음부터 포기하고 수치 MNA를
기본으로 삼을 것** — leading order를 손으로 미리 적용해도 소자가 하나만 추가되면(위 사례의
M10/M19) 다시 실패할 수 있다.
