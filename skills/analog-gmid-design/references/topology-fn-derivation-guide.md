# topology_fn 유도 가이드 — 새 토폴로지를 topology_library.py에 추가하는 법

`assets/topology_library.py`의 각 `topology_fn` 팩토리는 논문/원문의 위상보상 방정식을 그대로
옮긴 게 아니라, "스펙(GBW, PM, CL 등) -> 각 스테이지 gm" 관계로 **역산**한 결과다. 이 문서는
그 역산 절차와, 이미 만든 3개 토폴로지(Miller 2단, NMCNR 3단, NGCC 3단)의 실제 유도 과정을
기록한다 — AI가 새 토폴로지를 추가할 때 코드 주석을 다시 역산하는 대신 이 문서를 먼저 참조하고,
같은 절차로 새 유도를 진행한 뒤 이 문서에 이어서 기록하라.

## 0. 원칙 — 왜 이 내용이 코드 주석이 아니라 여기 있는가

`topology_library.py`의 docstring은 "무엇을 검증했고 무엇이 근사인가"라는 **결론**만 짧게
남긴다. 그 결론에 이르는 **유도 과정**(어느 방정식을 어느 방정식에 대입해서 gm1이 gm2와
소거되는지, 어떤 항이 자유도로 남는지)은 이 문서에 남긴다 — 코드를 읽는 사람은 결론만 알면
되지만, 다음 토폴로지를 추가하는 AI/사람은 과정을 알아야 같은 방법으로 새 유도를 할 수 있다.
과정을 코드 주석에 욱여넣으면 파일이 비대해지고, 반대로 아무 데도 안 남기면(이번 세션처럼
대화 안에서만 유도하고 파일에 안 쓰면) 세션이 끝나는 순간 그 추론이 사라진다.

## 1. 일반 절차 — 논문 방정식 -> topology_fn

1. **헤드라인 성능식 수집**: 그 토폴로지의 GBW, PM(위상마진), slew rate 등 핵심 성능이
   gm_i(각 스테이지 트랜스컨덕턴스)와 보상 커패시터/부하 커패시터로 어떻게 표현되는지 원문에서
   그대로 가져온다(근사/재현이 아니라 원문 수식 그 자체).
2. **연립방정식으로 놓고 gm_i에 대해 푼다**: 스펙(GBW_target, PM_target 등)을 알고 있다고
   가정하고, 위 방정식들을 gm_1..gm_n에 대해 대수적으로 정리한다. 이때 흔히 발생하는 패턴:
   - 어떤 gm_i가 다른 항들과 **소거**되어 스펙만으로 유일하게 결정된다(아래 NMCNR의 gm3처럼).
   - 남은 gm_i는 이미 구한 gm_i에 대한 비율/차분식으로 유일하게 결정된다(Miller OTA의 gm2=Z*gm1).
   - 원문 자체가 이 지점에서 **비용함수 최적화**(수치 최적화, MATLAB contour, ellipse-line 접점
     등)로 넘어가서 닫힌해가 없는 경우(NGCC의 gm1/gm2 split) — 이건 이 스킬의 한계가 아니라
     회로 이론/원문 자체의 한계다.
3. **결정 안 되는 자유도는 숨기지 말고 파라미터로 노출**: 2번에서 유일해가 안 나오면, 그 자유도
   비율(예: gm2/gm1, kg=gm2/gm3)을 `topology_fn` 팩토리의 키워드 인자로 받게 하고 "원문 특정
   예제에서만 유효한 근사"라고 명시한다. 기본값을 그럴듯하게 박아넣고 검증된 것처럼 문서화하지
   않는다 — 이게 이 스킬 전체를 관통하는 "정직한 한계" 원칙이다.
4. **prev_cggs 의존 여부 판단**: 방정식에 다음 스테이지의 게이트 커패시턴스(또는 다른 노드
   기생 커패시턴스)가 들어가면(Miller OTA의 C1, C2), `topology_fn(prev_cggs)`는 `prev_cggs`를
   실제로 써야 하고 `optimize_multistage()`의 반복 수렴에 의존한다. 안 들어가면(NMCNR, NGCC)
   `prev_cggs`를 무시해도 되며 첫 반복에 이미 수렴한 값이 나온다 — 엔진 수정은 어느 경우에도
   필요 없다(§2 참고, `optimize_multistage()`가 두 경우를 이미 동일하게 처리).
5. **원문 수치 예제와 대조**: 원문에 Table/수치 예제가 있으면 유도한 식에 그 숫자를 넣어 원문
   결과와 맞는지 확인한다(NGCC의 경우 0.7507 vs 0.754mS로 대조, 반올림 오차 내 일치 확인).
   대조 못 하면(NMCNR처럼 이 세션에서 독립 수치 예제가 없었던 경우) "물리적 타당성만 있는 근사"
   라고 명시하고 SPICE 재확인을 요구한다.
   ⚠️ **"닫힌해가 없다/OCR이 손상됐다"고 결론 내리기 전에**: PDF 텍스트 추출(`get_text()` 등)은
   분수·위첨자·2단 컬럼이 섞인 수식에서 토큰 순서를 뒤섞기 쉽다 — 이걸 "원문 자체가 훼손됐다"로
   오판하지 말 것. 의심되는 페이지는 `page.get_pixmap(dpi=300)`으로 이미지 렌더링해서 직접 읽고
   나서 최종 판단하라(§4 NGCC 사례: 처음엔 "OCR 손상으로 재현 불가"라고 잘못 결론 내렸다가,
   같은 페이지를 이미지로 다시 보고 Eq 8.a/8.b를 완전히 판독해 정정했다).
6. **실측 LUT로 sizing까지 실증**(가능하면): `optimize_multistage()`에 real LUT를 넣어 실제
   L/VDS/W가 나오는지 확인한다 — gm 산출식만 맞고 sizing 결과가 물리적으로 말이 안 되면(예:
   §9에서 반복 확인된 "gm/ID가 격자 최대치로 발산" 현상) `w_max` 등 제약을 같이 문서화한다.

## 2. Miller 2단 OTA (§6.4/§10.2) — 완전 결정 케이스

원문 검증된 식(gm-id-methodology.md §6.4/§10.2, Eq 8.13/8.14/8.15):
```
gm1 = wT * Cm                                          (8.13)
gm2 = Z * gm1                                            (8.14)
Cm = (NDP/Z) * [C1+C2 + sqrt((C1+C2)^2 + 4*C1*C2*Z/NDP)] (8.15)
```
여기서 `wT=2*pi*GBW`, `Z`(pole-zero 비), `NDP`(damping factor 관련 상수)는 설계자가 지정하는
값이라, `Cm`은 C1(노드1 기생, 다음 스테이지 게이트 커패시턴스로 근사)과 C2(노드2 기생, CL로
근사)만 알면 바로 계산된다. 즉 **gm1, gm2가 스펙만으로 유일하게 정해진다** — 유도가 아니라
원문 대입 그 자체다. `C1`이 다음 스테이지의 실제 Cgg에 의존하므로 `prev_cggs`를 쓰는
유일한 케이스다(초기 반복엔 `C1=0.1*CL` 추정치로 시작, 이후 반복은 직전 stage2 Cgg로 갱신).

## 3. NMCNR 3단 RHP-zero 완전제거 (§10.4) — gm3 소거 케이스, 원문 페이지 이미지로 확인 완료

**원문**: Ka Nang Leung, Philip K. T. Mok, Wing-Hung Ki, "Right-Half-Plane Zero Removal Technique
for Low-Voltage Low-Power Nested Miller Compensation CMOS Amplifier" (IEEE, 1999) — 원문 p.601
(논문 3쪽) Eq (6)~(11) 직접 이미지 판독으로 아래 식 전부 확인:
```
Rm = 1/gm3                                          (본문, Structure 4 조건)
kg := gm2/gm3                                       (본문 정의)
Cm1 = 4*(gm1/gm3)*CL                                (Eq 8)
Cm2 = [2/(1-kg)]*(gm2/gm3)*CL                       (Eq 9)
GBW = gm1/Cm1 = (1/4)*(gm3/CL)                      (Eq 10)
PM = 60deg + arctan(zLHP/GBW) > 60deg, zLHP=gm3/Cm1  (Eq 11)
```
이번 세션에서 이미지로 원문을 직접 읽어 이전에 유도했던 식(아래 그대로)이 **정확히 일치**함을
확인했다 — 별도 수정 불필요.

**유도**: `GBW = gm1/Cm1 = gm1 / [4*(gm1/gm3)*CL] = gm3/(4*CL)` — gm1이 분자·분모에서 소거되어
GBW는 gm1과 무관, gm3만으로 결정된다. 스펙 GBW_target을 주면:
```
gm3 = 4 * (2*pi*GBW_target) * CL
```
다음, `zLHP/GBW = [gm3/Cm1] / [gm3/(4*CL)] = 4*CL/Cm1 = 4*CL / [4*(gm1/gm3)*CL] = gm3/gm1`.
PM 식에 대입하면 `PM - 60deg = arctan(gm3/gm1)`, 즉:
```
gm1 = gm3 / tan(radians(PM_target - 60deg))
```

**자유도(원문으로 확정 확인)**: 원문은 Eq (8),(9)로 결정되는 Cm1/Cm2가 "3차 Butterworth
극점 배치"를 이룬다고 설명하지만, 그건 **Cm1/Cm2를 그렇게 잡으면 얻어지는 결과에 대한 설명이지,
`kg`(=gm2/gm3) 자체를 결정하는 별도 방정식이 아니다** — 원문 전체(Eq 6~11, 실험 결과 Table 1
포함)에 `kg`의 수치 예제나 추가 결정식이 전혀 없다. `kg`는 `Cm2` 식(Eq 9)에만 등장하고, `Cm2`는
GBW(Eq 10)·PM(Eq 11) 어디에도 나타나지 않는다(2차 이상 극점 배치에만 관여). 즉 **"OCR이 손상돼서
kg 결정식을 놓쳤다"가 아니라 "원문 자체가 kg를 설계자 자유도로 남겨뒀다"는 것을 원문 이미지로
직접 확인했다** — NGCC(§4)와 달리 이건 재구성 실패가 아니라 확정된 사실이다. 기본값 0.5는
`Cm2>0` 조건(`kg<1` 필요, Eq 9 분모)을 만족하는 물리적으로 타당한 임의값일 뿐 원문에 없는
수치이니, 실사용 시 SPICE로 PM/GBW를 재확인해서 설계자가 직접 정할 것.

## 4. NGCC 3단 (§10.2, Lee et al.) — 완전 결정 케이스 (Eq 8.a/8.b 판독으로 해결)

원문 검증된 식(Lee et al., JSTS 2007, "A Design Guide of 3-stage CMOS OP amp with Nested Gm-C
Frequency Compensation", 원문 p.23 Eq 5~8.b):
```
w1 = 2*pi*GB,  w3 = k*w1,  gm3 = w3*CL                          (Eq 2, 식 그대로)
gm1*k + gm2*k^2/(1+2k) = alpha*gm3                              (Eq 7, 선형 제약)
gm1 = [alpha*(1+2k)^2 / (k*((mu_n/mu_p)*k^2 + (1+2k)^2))] * gm3 (Eq 8.a)
gm2 = [alpha*(1+2k)      / (k^2 + (mu_p/mu_n)*(1+2k)^2)]    * gm3 (Eq 8.b)
```
`gm3`는 `k`·`GB`만으로 유일하게 결정된다. `gm1, gm2`는 원문이 **면적 비용함수
`H=(W/L)1+(W/L)2 = gm1²/(2·μp·Cox·ID1) + gm2²/(2·μn·Cox·ID2)`**(Eq 5)를 Eq 7의 선형 제약
아래 최소화하는 문제로 풀며, (gm1,gm2) 평면에서 H=const는 타원, Eq 7은 직선이라 그 접점이
유일한 최적해가 된다(Lagrange 승수법) — 그 닫힌해가 바로 Eq 8.a/8.b다. 즉 **`mu_n/mu_p`(해당
공정의 NMOS/PMOS 이동도 비)만 알면 gm1, gm2, gm3 전부 스펙만으로 유일하게 결정된다.**
`mu_n/mu_p`는 설계 자유도가 아니라 **공정 파라미터**(BSIM UO_n/UO_p 비 등)다.

⚠️ **이전 세션 기록 수정**: 처음에는 이 문서(및 코드)에 "이 세션에서 원문 OCR 손상으로 Eq
8.a/8.b를 재현하지 못했다"고 적고, 대신 `gm2/gm1` 비율을 자유도로 노출하는 근사(기본값
0.186/0.105≈1.771)를 썼다. 이건 **틀린 판단이었다** — 실제로는 `fitz`의 텍스트 추출(`get_text()`)
결과가 수식의 분수/위첨자를 시각적 순서와 다르게 뽑아내 토큰이 뒤섞였을 뿐이고, 해당 페이지를
**300dpi 이미지로 렌더링해서 직접 읽으니 Eq 8.a/8.b가 완벽하게 또렷했다**. `mu_n/mu_p≈3.9775`로
역산하면 Eq 8.a/8.b 양쪽에서 독립적으로 원문 Table 4(`gm1=0.105mS, gm2=0.186mS`, k=4, GB=10MHz,
CL=10pF, α=0.3)와 정확히 일치했다(Eq 7 선형 제약도 동시에 만족 — 삼중 교차검증).
**교훈**: 수식이 포함된 PDF 페이지에서 텍스트 추출이 뒤섞이면 "원문이 손상됐다"고 단정하지
말고, 그 페이지만 이미지로 렌더링해서(`page.get_pixmap(dpi=300)`) 직접 눈으로 읽어라 —
텍스트 추출 실패와 원문 손상은 다른 문제다.

**구현**:
```python
gm1 = alpha*(1+2*k)**2/(k*(r*k**2+(1+2*k)**2))*gm3    # r = mu_n/mu_p
gm2 = alpha*(1+2*k)/(k**2+(1+2*k)**2/r)*gm3
```
`mu_ratio` 기본값 `3.9775`는 원 논문의 그 특정 0.18µm 공정 예제를 역산한 값일 뿐이다 — 자신의
공정으로 sizing할 때는 반드시 실제 `mu_n/mu_p`로 교체할 것.

## 5. 검증 상태 요약표

| 토폴로지 | 헤드라인 식 검증 | 자유도 | 자유도 검증 상태 | 실측 LUT sizing 실증 |
|---|---|---|---|---|
| Miller 2단 | 완전 검증(원문 수식 대조) | 없음(완전 결정) | — | 검증됨(§11, sky130-worked-example.md) |
| NMCNR 3단 | 완전 검증(원문 p.601 이미지 판독, Eq 6~11 전체 대조) | `kg=gm2/gm3` | **원문 확정**: 원문 자체가 kg를 자유도로 남김(추가 결정식 없음 확인) — 기본값 0.5는 임의값, SPICE 재확인 필요 | 안 됨 |
| NGCC 3단 | 완전 검증(Eq 8.a/8.b+Eq 7 삼중 대조, Table 4 재현) | `mu_n/mu_p`(공정 파라미터, 설계 자유도 아님) | 원 논문 0.18µm 예제 역산값(3.9775)이 기본값 — 자기 공정 값으로 교체 필요 | 안 됨(§6에서 square-law로만 교차검증) |

새 토폴로지를 추가할 때마다 이 표에 행을 추가하라 — "뭘 검증했고 뭘 안 했는지"를 한눈에 보이게
유지하는 것이 이 라이브러리가 커져도 신뢰성을 유지하는 핵심 장치다.
