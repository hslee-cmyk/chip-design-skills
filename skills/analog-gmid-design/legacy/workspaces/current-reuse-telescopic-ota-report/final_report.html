gm/ID Design Report

Independent redesign of Xie & Chen, "A 126uW Current-Reuse Telescopic OTA with Class-AB Output Stage" -- full circuit (current-reuse telescopic input stage + Class-AB output + biasing generator + CMFB), sky130, analog-gmid-design skill methodology
Scope & methodology. Topology was independently re-transcribed device-by-device from the paper's Fig.1-5 (verified against the rendered PDF pages, not assumed from generic OTA knowledge) before any sizing began. Every table/stick-diagram/SPICE number below is a real function-call output (sizing_recipe.py's SemiEmpiricalGmIdLUT + stick_diagram.py + ngspice/sky130_fd_pr), serialized straight from JSON written by the scripts in this report's workspace directory into the REPORT object at the bottom of this file -- nothing here was hand-retyped or shortened. gm/ID operating points are a fresh design choice for sky130, not copied from the paper's own 0.18µm appendix numbers.
Real mistakes caught and fixed during this pass (kept visible, not silently corrected away): (1) the LUT's L grid is stored in meters already (e.g. 1.5e-07 == 0.15µm) -- an initial *1e-6 unit-conversion bug corrupted every sizing result by putting L queries outside the LUT's real grid; caught only because single-device ngspice cross-checks came back wildly inconsistent (0.03x-41x of target, no pattern) and the root cause was traced by hand. (2) the first per-device VDS choices for the 6-transistor Stage-1 series stack (M6-M1a-M2a-M3a-M4a-M5) summed to 3.2V under a 1.8V rail -- physically impossible; corrected to a headroom budget that sums to exactly 1.80V (see section 3). (3) sky130's pfet_01v8/nfet_01v8 ngspice subckt declares a mult parameter but never wires it into the internal device line -- a controlled mult=1 vs mult=10 SPICE test at identical bias returned identical current, so wide devices (M15, W=200µm) are instead realized in SPICE as real parallel unit-width instances (see section 6).
