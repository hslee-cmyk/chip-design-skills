# oracle-portability 계획 입력 초안 -- offset-trim v0.5에서 옮긴 '오라클 능력 확인' 초안 (2026-10-16)

> 출처: offset-trim 계획 v0.5 작성 중(브랜치 trim-plan-r1) 쓴 N3.9 초안이다. 코디네이터 지시(T-33, 'T-31 절차·PDK 기술자·확인 test 정의는 oracle-portability 계획이 소유')에 따라 offset-trim 계획에서 빼고 여기 보관한다. 승인된 내용이 아니다. oracle-portability 계획 작성자가 근거로 쓰거나 버린다.
> offset-trim v0.5가 이 계획에 기대하는 것(의존 계약)은 offset-trim 계획 N3.9에 있다: 범위 판정·보정 루프는 유효한 '오라클 능력 기록'이 있는 PDK·시뮬레이터 조합에서만 허용하고, 없으면 fail-closed. 능력 기록이 확인해야 할 항목(offset-trim 쪽 요구)은 아래 C1~C6이다.
> 경로 `O/` = `skills/analog-gmid-design/tools/spice_oracle/`, 줄 번호는 base `d783efe`.

## 1. 지금 코드의 공정 결합 사실(읽기 확인)

- 오라클 넷리스트의 코너·온도는 LUT npz 메타(`corner`, `temp_c`)에서만 온다. LUT와 다른 온도 입력이 없다(`O/oracle_netlist.py:32-33, :77, :112-120, :314-316`).
- 오라클 MC는 한 PDK의 관례를 코드에 담는다: (a) 변수 이름 패턴 `<subckt>__*_slope_spectre`를 모델 파일 머리 300줄(리터럴)에서 찾음 (b) l·w µm 가정에 따른 1e-6·1/√m 배율 (c) 표준정규 가정(`O/oracle_offset_mc.py:18-23, :52-66, :145-153`).
- 모델 파일이 없거나 패턴이 안 맞으면 소자 변수 0개로 그대로 진행해 분산 0이 오류 없이 나올 수 있다(`O/oracle_offset_mc.py:57-58, :147-153`).
- 엔진 PDK 선언 `gmid_pdk_decl/1`(`assets/sky130_pdk_decl.json`, `E/core/pdk_decl.py:585`)이 원천 파일 경로·sha256의 정본이고, 오라클은 이것을 읽지 않으며 모델 경로를 오라클 입력 `process.models[kind].includes`에 따로 둔다.

## 2. PDK 기술자 항목 초안(값은 사용자가 PDK 문서에서 선언)

| 항목 | 내용 | 지금 위치 |
|---|---|---|
| 시뮬레이터 | 실행 파일, 버전 읽는 방법, 배치 실행 방식 | 오라클 실행 인자 |
| 모델 경로 | kind마다 모델 파일 포함 방식(include·lib 섹션), 코너 선택 방법, 파일 sha256 | 오라클 입력 `process.models`, 엔진 PDK 선언 `sources` |
| 소자 모델 이름 | kind → subckt·모델 이름, 인스턴스 기하 단위 | 오라클 입력 `subckt` |
| MC 불일치 켜는 방법 | 방식(소자별 변수 덮어쓰기, 시뮬레이터 내장 MC 함수, 불일치 전용 lib 섹션 등), 변수 이름 규칙, 기대 분포, 면적 배율, 병렬 소자(m) 처리 | `oracle_offset_mc.py` 리터럴 |
| 온도 지정 방법 | 회로 온도 지정 구문, 모델 기준 온도 위치, 실제 쓴 온도를 결과에서 읽는 방법 | `.temp` = LUT `temp_c` |
| 공정 문서 불일치 계수 | kind(와 bin)마다 계수와 출처(웹 링크·로컬 PDF·쪽) | 엔진 PDK 선언 mismatch slope 원천 |
| 코너 목록 | 선언 코너 이름 | 엔진 PDK 선언, LUT 메타 |

위치 안: 엔진 PDK 선언 파일에 오라클 절을 더해 원천 경로·해시를 한 곳에 둔다(단일 정본). 오라클은 JSON을 직접 읽는다. 엔진 로더의 모르는 키 처리·스키마 버전 영향은 design에서 잰다.

## 3. 확인 절차 초안(PDK·회로 이름 없음, 새 상수 없음)

확인 벤치 = 소자 하나·쌍의 최소 회로. 기하는 PDK bin 경계·LUT 격자에서 고른다.

| # | 확인 | 합격 규칙 | 일부러 깨진 기술자에서 거부해야 하는 것 |
|---|---|---|---|
| C1 | 시뮬레이터 동작 | 공칭 op 수렴, 버전·쓴 모델 해시를 결과에서 읽어 기술자와 맞춤 | 모델 경로 오류 |
| C2 | MC 불일치가 실제로 분산을 만드는가 | 켠 표본의 ΔVGS(같은 ID) 분산 ≠ 0, 끈 표본은 비트 동일 | 변수 이름 규칙 오류(변수 0개) |
| C3 | 크기가 선언 계수와 일관한가 | 기하 둘 이상에서 σ̂와 계수 예측 σ의 차가 MC 신뢰 구간(배수 = 소비 요구의 k, 표준오차 σ̂/√(2(n−1))) 안, 면적 의존도 같음 | 면적 배율 오류 |
| C4 | 온도가 동작점을 실제로 바꾸는가 | 범위 끝점과 T_j의 ID(같은 바이어스) 차 > 허용오차 전파 폭, 읽은 온도 = 요청 온도 | 온도 구문 무시 |
| C5 | 표본 정체가 온도 사이에 보존되는가 | 같은 표본의 T_j 값이 단독 실행과 온도 sweep 실행에서 비트 동일 | 온도마다 난수 재추출 |
| C6 | LUT와 같은 모델인가 | 모델 sha256 = LUT 메타 `model_files_sha256`, 공칭 값이 LUT 점과 허용오차 안 | 다른 모델 파일 |

거부를 먼저 확인한다(게이트는 '실제로 거부'를 먼저 증명).

## 4. 능력 기록 초안

- 내용: 기술자 지문, 시뮬레이터 버전, 모델 sha256 묶음, 확인 코드 지문, C1~C6 측정값·판정, 쓴 n·k·온도 점, 날짜. 판정 기록이므로 확인 코드 작성자가 아닌 검증자가 만든다.
- 유효성: 지문 묶음 하나라도 다르면 무효.
- fail-closed: 유효 기록 없는 조합에서 범위 판정·보정 루프·오라클 MC 판정 요청 → 거부(`oracle_capability_unverified`/`..._stale` 후보). T_j 한 조건 판정도 MC를 쓰므로 C1·C2·C3·C6이 전제.
