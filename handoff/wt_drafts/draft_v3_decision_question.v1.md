# 사용자 결정 질문 -- V3 뮤테이션 대상 범위 (B26-1·B34 착수 조건)

## 먼저 알릴 것(결정 없이 진행 -- 강화)

V3 면제 기록이 승인한 코드에 묶이지 않는 **결함**을 고친다(`draft_v3_exempt_binding.spec.md`). 지금은 한 card에서 승인한 변이 id 면제가 뒤 card의 같은 경로 변이를 조용히 면제한다
(실측: B26-1용 면제 목록이 B34 변이 1,402개 중 619개를 미리 면제, 옛 C8 면제 14개 중 4개는 def가 바뀐 뒤에도 적용 중). 면제 원소를 `변이 id@def 해시`로 묶고, 해시가 없거나 다르면
적용하지 않고 출력에 싣는다. 기존 C8 면제 14개는 더는 적용되지 않지만 잃는 것이 없다(그 def를 다시 바꾸는 순간 어차피 해시가 달라진다 -- 실측). 게이트 변경이라 승인 기록 한 건은 필요하다.

## 질문

V3는 지금 **AST가 바뀐 def의 본문 전체**를 변이한다. 엔진 def가 커서 몇 줄을 고친 card도 그 def의 기존 문장 전부를 죽여야 병합된다. 어떻게 할까요?

| | 선택지 | B26-1 변이 수 / 실행 시간(직렬, 하한~상한) | card가 떠안는 것 | 약화 |
|---|---|---|---|---|
| 1 | **지금 규칙 유지**(def 전체) | 2,472 / 3.4 h ~ 122 h | 어떤 test도 실행하지 않는 줄의 변이 **298개는 반드시 생존** → 레일과 무관한 기존 코드의 test를 새로 쓰거나 id 면제 승인. B34도 75개(1,395 중) | 아니오 |
| 2 | **바뀐 문장 + 감싸는 제어문 + 새 def 전체**(권고) | 176 / 15분 ~ 8.8 h | 이 card가 쓴 코드의 test만. 대상 밖 변이 수는 출력(`not_targeted`) → 기존 test 공백 백로그 | **예**(판정 범위 축소) |
| 3 | **2 + 바뀐 문장과 이름 한 단계로 이어진 기존 문장**(데이터 의존) | 506 / 42분 ~ 25 h | 2 + 바뀐 값을 쓰거나 대 주는 기존 문장의 test | 예(2보다 작음) |

P9는 어느 쪽이든 작다(24 / 3 / 4개). B34의 2·3 수치는 패치를 시뮬레이션하지 않아 미측정이다(착수 시 도구가 잰다).

## 권고: 2

* V3의 목적은 "이 변경을 위해 쓴 test가 이 변경의 코드를 판정하는가"(DEC-38)다. 바뀌지 않은 문장의 생존은 card의 test가 아니라 기존 test 공백을 잰다 -- 그중 298개(B26-1)는 어떤 test도 그 줄을
  실행하지 않아 card마다 확정 FAIL이다. 1은 이 공백 메우기를 엔진 card마다 병합 조건으로 만든다(B26-1·B34·B26-2·B35가 같은 큰 def를 다시 바꾸므로 매번 반복).
* 2가 놓치는 것: 바뀐 값이 흘러드는 **바뀌지 않은** 문장의 test 공백. 3이 이름 한 단계까지 덮지만 비용이 3배이고 그 몫도 대부분 기존 공백이다. 2의 대상 밖 수를 출력·백로그로 남겨 공백을
  조용히 버리지 않는다.
* 1의 시간 문제는 약화 없는 가속(줄 커버리지 선택·병렬)으로 줄일 수 있지만(실측 상한 122 h → 약 70 h 이하), 확정 생존 298개는 가속으로 없어지지 않는다.
* 권고하지 않는 중간안: 표본 추출·예산(약화인데 빠지는 변이가 임의), 자동 기준선 차분(결과는 2와 비슷하고 비용은 1 이상).

## 선택하면 일어나는 일

* **2 또는 3**: 게이트 변경 card `20260930-v3-changed-stmt-scope`(`draft_v3_scope_policy.spec.md`, 3이면 대상 정의만 D1) + 승인 기록(`target_kind: diff`, 범위 설명에 **"판정 기준 적용
  범위 축소(약화) 승인"** 명시). 순서: 면제 누수 수정 → 이 card → B26-1.
* **1**: 이 card는 쓰지 않는다. B26-1은 V3 전수로 가고, 확정 생존 298개(와 추가 생존)는 test 보강 또는 card별 면제 승인(해시에 묶인)으로 처리한다.
