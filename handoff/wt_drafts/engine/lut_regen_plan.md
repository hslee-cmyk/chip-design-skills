### 1.1 PDK L bin 경계 (모델 파일 파싱)

- `sky130_fd_pr__{nfet,pfet}_01v8__tt.pm3.spice`의 `.model` bin `lmin` 집합은 {0.15, 0.18, 0.25, 0.5, 1.0, 2.0, 4.0, 8.0, 20.0} µm, `lmax` 집합은 {0.18, …, 20, 100}이다. nfet bin은 180개, pfet은 108개다. `bins.csv`의 L 열 집합도 같다.
- bin이 실제로 측정된 (W, L)은 폭마다 다르다(`bins.csv`). W=5 µm에서는 0.15·0.18·0.25·0.5·1·2·4·8 µm이다(nfet W=0.42에는 20도 있음). 기준 폭 5 µm에서 bin 하한값(측정점)은 전부 위 집합 안에 있다.
- 현재 앵커와 비교하면 0.15·0.25·0.5·1.0·4.0은 정렬되어 있고 **0.18·2.0·8.0·20.0이 없다**. 0.20·0.30·0.35·0.425·0.70·1.5·2.5는 bin 내부 점이다(bin 공식 P0 + PL/L … 로 이어지는 구간이라 경계 불연속은 없다).

### 1.2a ngspice가 경계값 L에서 고르는 bin과 실제 전환점 점프 (2026-10-07 추가 실측)

- 방법: 임시 경로 scratchpad `bincheck/`. ngspice-46, 기준 LUT와 같은 인스턴스(`xdut … w=5u ad=2.5p as=2.5p pd=7u ps=7u nf=1`, lod·mismatch 포함)를 썼다. 고른 bin은 `showmod m.xdut.msky130_fd_pr__<dev> : lmin lmax wmin wmax`로 읽었다.
- **소속**: nfet·pfet 모두 L = 0.15, 0.18, 0.25, 0.5, 1, 2, 8 µm에서 lmax = L인 bin(아래 bin)을 고른다. W도 같다: W = 5 µm에서 [3, 5] bin, W = 0.42 µm nfet에서 [0.39, 0.42] bin을 고른다. pfet W = 0.42는 더 아래 bin이 없어서 [0.42, 0.55]를 고른다. 전환점은 경계 위 약 1 nm다(0.1809 → 아래, 0.181 → 위. 2.001 → 위. W 5.001 → 아래, 5.01 → 위). 제조 격자 0.005 µm 위에서는 **bin i = (lmin_i, lmax_i]**이고, 가장 아래 bin만 [0.15, 0.18]이다.
- 교차 확인: 모델 파일에서 W=5 bin [0.15, 0.18)과 [0.18, 0.25)을 하나씩 지운 복사본으로 L = 0.175·0.17999·0.18·0.185를 돌렸다. 결과가 원본과 비트 단위로 같았다. W=5에서 쓰이는 bin이 [3, 5) 쪽이라는 뜻이고, 위 `showmod` 결과와 맞는다.
- **영향 1 (L 격자)**: 경계값 b는 아래 bin의 위 끝점이다. 위 bin의 아래 끝점은 b + 0.005다. 0절의 0.185·0.255가 이것이다.
- **영향 2 (기존 메타)**: 폭 슬라이스 생성기 `bin_for()`(Python `lmin ≤ L < lmax`)가 쓴 `model_bin_per_L`은 경계 L에서 틀렸다. 예: pfet W=0.42, L=0.25에서 메타는 model.105([0.25, 0.5])를 적었지만 ngspice는 [0.18, 0.25] bin을 썼다. 또 '특성화 폭 = bin wmin'으로 고른 슬라이스 W는 더 아래 W bin이 있으면 그 bin의 wmax 끝점으로 계산된다. 값은 결정론적이고 틀린 값이 아니다. 다만 **'그 W bin의 측정점'이라는 E5·LY2 전제와, 메타에 적힌 bin 이름이 실제와 다르다.** 고치는 방법은 생성기가 점마다 `showmod`로 실제 bin을 읽어 메타에 적는 것이다(5절 항목 11). 폭 키 선택을 바꿀지는 이 문서 범위 밖이다(보고만 한다).
- **전환점 점프**: b + 0.0009 → b + 0.0011 µm(0.2 nm 차이)에서 W=5, VDS 0.9 V, VGS {0.6, 0.9, 1.5} V × VB {0, 0.9, 1.8} V로 쟀다. 'ID 1/L 기대'는 같은 0.2 nm의 bin 안 변화다.

## 2. L 격자 규칙 (사용자 결정 2026-10-07 반영, 새 상수 없음)

L = bin 선택(이산) + bin 안 연속(선형 보간)이다. LUT L 격자는 아래 K1·K1b·K3로 정한다. 보간 오차는 K2'가 tol_V로 잰다. 옛 K2(밀도로 앵커를 더 넣기)는 대체됐다.

**K1 경계 (PDK에서 읽음)**: 격자는 설계 범위 [L_min, L_max] 안의 bin 경계(모델 파일 `.model` 블록의 `lmin`/`lmax` 집합)를 모두 포함한다. 생성기는 폭 슬라이스 생성기의 `parse_bins()`처럼 모델 파일에서 이 집합을 읽고 `bins.csv`와 교차 확인한다. 손으로 적지 않는다. 결과: 0.15·0.25·0.5·1·4는 이미 있고, **0.18·2·8·20을 더한다.**

**K1b 경계 소속과 반대쪽 끝점**: 각 LUT L 점의 bin은 **시뮬레이터가 실제로 고른 bin**이다. 생성기가 `showmod`(lmin·lmax·wmin·wmax)로 읽어 메타에 적는다. Python 규칙으로 추정하지 않는다(1.2a: ngspice-46에서 경계값은 아래 bin). 경계 b가 **불연속**(전환점 점프의 VGS 환산값 > 그 셀 tol_V)이면, b가 들지 않은 쪽 bin에 제조 격자 한 칸 옆 점을 끝점으로 더한다. ngspice-46에서는 b + 0.005다(`MANUFACTURINGGRID`는 tlef에서 읽는다). 연속 경계의 b는 두 bin의 공통 끝점으로 쓴다. tol_V가 정해지기 전의 기본안은 0.18·0.25를 불연속으로 두는 것이다(1.2a). 결과: **0.185·0.255를 더한다.**

**K2' bin 안 L 방향 LOO (tol_V에 더함)**: bin 안의 내부 L 점마다 그 점을 빼고, 같은 bin 안 양옆 L 점으로 L 축 선형 보간한 값을 뺀 점의 LUT 값과 비교한다. 값 변환은 열별 규칙 그대로다(ID는 ln). 지표는 tol_V의 두 지표(gm/ID 역산 VGS 차, ID 환산 `|Δln ID|/(gm/ID)`)다. 셀은 (kind, w_key, L 구간, VDS)이고, L 쿼리의 tol_V는 그 L을 감싸는 두 L 점 셀의 VGS·VDS·VS 축 LOO 값과 그 bin의 L 방향 값 중 최댓값이다. **점이 2개뿐인 bin**(18점 격자에서 [0.15, 0.18], (4, 8], (8, 20])은 LOO가 정의되지 않는다. 그래서 생성 때 bin 안 중점(제조 격자에 맞춘 0.165, 6.0, 14.0)을 검증 전용으로 시뮬레이션하고, 그 보간 오차를 그 bin의 L 방향 값으로 쓴다. 이 값이 봉인을 무력하게 할 만큼 크면 점을 더할지는 사용자에게 보고한다(점을 더하는 규칙은 결정되지 않았다). 1.2(옛) 표의 큰 bin 안 변화(pfet 0.175→0.18에서 ID 최대 49 %)를 보면, 단채널 bin [0.15, 0.18]의 L 방향 값이 가장 클 것으로 예상된다[추측, G1에서 잼].

**K2 밀도 (구간마다) -- 대체됨(2026-10-07, bin 안 보간 + K2'). 옛 제안으로 남긴다**: 인접 앵커 (L_i, L_{i+1})에 대해, 같은 설계점(kind, w_key, gm/ID, VDS, VS, 포화)에서 L만 L_i → L_{i+1}로 바꿀 때 지표 M이 바뀌는 크기 ΔM을 잰다. 이것을 엔진이 같은 L에서 이미 구분하지 못하는 크기 ε_M과 비교한다.
- R = ΔM / ε_M > 1이면 그 구간에는 엔진이 구분할 수 있는데 고를 수 없는 선택지가 있다. 즉 부족하다. 넣을 점 수는 n = ⌈R⌉ − 1이고, 로그 등간격으로 두고 제조 격자(tlef `MANUFACTURINGGRID` 0.005 µm)에 맞춘다. 같은 bin 안에만 넣는다(경계는 K1이 이미 앵커로 둔다).
- R ≤ 1이면 충분하다. 이웃 구간 R의 합이 1 이하면 그 사이 내부 앵커(K1 점은 제외)는 엔진이 구분하지 못하는 중복이다. 지우는 것은 사용자 결정이고, 옛 격자점 대조 때문에 기본은 유지다.
- 지표 M과 해상도 ε의 출처:

| 지표 | ΔM | ε (정본) | ε (지금 대용, 이 문서의 수치) |
|---|---|---|---|
| VGS(gm/ID 고정, 오른쪽 분지 근) | \|VGS_{i+1} − VGS_i\| | 그 셀의 tol_V(N3.6, (kind, w_key, L 앵커, VDS) 셀별 -- L 보간 금지 뒤의 정의는 VGS·VDS·VS 축 LOO) | LUT VGS 격자 한 칸 h = 37.5 mV(축에서 유도) |
| 고유이득 ln(gm/gds) | \|Δln A\| | `model_error_gain`(DEC-72, 미측정) | 같은 앵커에서 VGS·VDS ±1칸 상자 안의 \|Δln A\| 최댓값(엄격함) |
| fT = gm/(2πCGG) | \|Δln fT\| | `model_error_<bw>`(DEC-72, 미측정) | 같은 상자 안의 \|Δln fT\| |
| (참고) ID(같은 W, gm/ID 고정) | \|Δln ID\| | tol_I/ID = tol_V·gm/ID | 표에만 싣고 판정에는 쓰지 않음(≈ ln(L_{i+1}/L_i), 정보가 없음) |

- 통계: 정본은 점마다 R_p = ΔM_p/ε_p로 계산하고 구간 최댓값을 쓴다. 이때 분위수 같은 상수가 없다. ΔM과 tol_V는 둘 다 gm/ID 정점 근처에서 함께 커지므로 비율이 안정적이다. 대용 ε(고정값 h)을 쓰는 동안에는 정점 근처의 조건수 문제(tol_v_measurement.md 2절) 때문에 최댓값이 무의미하다. 그래서 이 문서는 **중앙값으로 판정**하고 p90을 함께 싣는다. 대용으로 낸 수치는 tol_V가 확정되면 다시 계산한다.
- 'VDsat' 지표: gm/ID 방법론의 근사 VDsat = 2/(gm/ID)는 gm/ID가 고정이면 L과 무관하다. 그래서 L 선택지 판정에는 VGS(헤드룸)와 VTH 변화를 쓴다. 새 LUT에 BSIM `vdsat` 열이 생기면 그 ΔVDSAT도 같은 표에 넣는다.

**K3 범위**: L_min은 PDK 최소 L(모델 `lmin` 최솟값 0.15)이다. L_max는 다음 특성화 L로 늘렸을 때 고유이득 변화 R_A가 1 이하가 되는 첫 특성화 L이다. 이득이 포화하면 더 긴 L은 면적만 늘리는 중복이 된다. 레이아웃 상한 같은 다른 제약은 PDK 선언(U-30)에서 읽는다.

**상한 (과밀 방지)**: 제조 격자보다 촘촘하게는 두지 않는다. L이 bin 안에서 연속이 되었으므로, 이산 격자(LR5·DP)의 후보는 LUT L 점이고 bin 안 연속 값은 외층·역산이 쓴다(계획 LR3 개정).

### 3.3 관찰

1. **전압 지표(K2-VGS)**:
   - R_V 중앙값이 1을 넘는 구간은 0.15~0.425 µm 단채널뿐이다.
   - pfet이 특히 크다. 0.15~0.18에서 ΔVGS 199 mV, ΔVTH 159 mV이고, 같은 gm/ID에서 ID가 248 % 바뀐다. 1/L 기대치는 −17 %이므로 bin 불연속과 단채널 효과가 겹친 결과다.
   - 0.5 µm 이상은 중앙값이 0.06~0.83으로 충분하다. p90은 대부분 구간에서 5~14다. 정점 근처의 조건수 때문이며(2절 통계), tol_V 셀값으로 정규화하면 줄어들 것으로 예상한다. [추측, tol_V 확정 뒤 재계산]
2. **이득 지표**:
   - 인접 앵커 사이 ΔA는 중앙 0.4~6.3 dB다.
   - 대용 해상도 δA는 0.07~1.1 dB다. pfet 단채널은 이득이 바이어스에 둔감해 0.07 dB까지 내려간다.
   - 그래서 R_A가 대부분 1을 넘는다. 고유이득을 조절하는 손잡이는 사실상 L 하나뿐이라는 뜻이고, 이득 해상도를 얼마로 볼지(D3)가 앵커 수를 결정한다.
3. **fT**: 인접 앵커 사이 fT 변화는 중앙 32~183 %이고, R_fT는 1.5~5다. 같은 L에서는 gm/ID로 fT를 연속 조정할 수 있으므로, 이 R은 이득·fT를 동시에 맞출 때에만 의미가 있다. 이득 기준과 같이 D3로 보낸다.
4. **폭 의존**: R_V 판정(중앙 1 초과)은 32폭에서 거의 같다. 1을 넘는 구간은 nfet 0.15~0.2(폭 사이 1.07~2.64)와 0.2~0.25(일부 폭 1.28), pfet 0.15~0.35(1.0~7.9)다. 예외는 pfet 0.7~1 하나로, 대부분의 폭에서는 0.40~0.6이지만 한 폭에서만 1.40이다. R_A의 결론은 폭과 무관하게 '대부분 1 초과'다. 3.1의 [최소~최대] 범위를 보라. 따라서 앵커 집합은 폭마다 따로 두지 않고 하나로 둔다. kind별로 따로 둘지는 D8이다.
5. **범위(K3)**:
   - nfet 4→8은 1.62 dB(R_A 2.6)이라 8이 필요하다. 8→20은 0.08 dB(R_A 0.26)라 포화했다.
   - pfet 4→8은 2.49 dB, 8→20은 0.88 dB(R_A 2.0)라 아직 포화하지 않았다.
   - 같은 gm/ID에서 ID 변화는 8→20에서 150 %로, 거의 1/L 그대로다. 면적은 2.5배 늘어난다.

1. K1 정렬은 데이터로 확인된 요구다. 단채널 경계 불연속이 있고, 그 L은 측정점이다.

3. 이득·fT 기준은 해상도 정본(model_error)이 아직 측정되지 않았다. 대용(같은 L 상자)은 엔진이 실제로 구분하는 것보다 훨씬 엄격하다. 이 대용으로 89점을 확정하면, 상수 대신 '모르는 해상도'로 밀도를 정하는 셈이 된다.
4. 생성이 1시간 안으로 줄었으므로 '재스윕을 두 번 하지 않는다'는 옛 제약(계획 163행 잡음 묶음의 이유)이 비용 면에서 사라졌다. model_error를 측정한 뒤 이득 기준으로 앵커를 더 넣는 재생성은 약 1~2 h다. 다만 LUT 지문이 바뀌므로 S0·실패 캐시가 무효가 된다. 이것이 남는 비용이다.
5. 옛 12점을 그대로 포함하므로 U-27 선행 조건 (3) '옛 격자점 대조'를 그대로 할 수 있다. 수정 생성기는 1.3절에서 이미 차이 0을 보였다.

## 5. U-27 요구 열과 생성 방식

축:
- L: S1b 18점. 생성기가 K1 집합(모델 파일)과 K1b 판정(전환점 점프, `showmod` 소속)에서 만든다. 손 목록을 쓰지 않는다. 2점 bin의 검증 중점(K2')은 LUT 축이 아니라 별도 검증 파일에 넣는다.

1. 점마다 `destroy all`을 넣는다(1.3절, 결과 동일 실측).
2. stdout과 stderr를 분리한다(파싱 결함 실측).
3. 소스 노드를 `vsrc`로 분리하고 AC 4회(g·d·s·b)를 `imag`/`real`로 부호째 기록한다.
4. op 값으로 gmbs·vth·vdsat를 추가한다.
5. noise를 2주파수로 재고 단위를 정리한다(D5).
6. 체크포인트 이름을 VS **값** 기반으로 바꾼다(현재 `_VS{iVS}` 인덱스. VS 축을 늘리면 앞 5점은 우연히 값이 같지만 L 이름과 같은 이유로 값 기반이 맞다).
7. ngspice `Error`·`Fatal` 줄을 검사한다(슬라이스 생성기와 같게).
8. 병렬 실행을 넣는다(ThreadPool, 조합 단위).
9. L 축을 모델 파일(K1)과 K1b 판정에서 읽는다.
10. 메타 `w_ref_m`·sha·단위를 기록한다.
11. (2026-10-07 추가) 점마다 ngspice `showmod … : lmin lmax wmin wmax`로 실제 bin을 읽어 메타 `model_bin_per_L`에 적는다. Python `lmin ≤ L < lmax` 규칙은 쓰지 않는다(1.2a). 폭 슬라이스 생성기 `bin_for()`도 같은 결함이 있다.

시제품의 `.control` 핵심(점마다; `/c/g479/newnet.py`에서 실측, 그 파일은 삭제함):

```
op ; echo P ; print @m.xdut.msky130_fd_pr__<dev>[id|gm|gds|gmbs|vth|vdsat]
for src in vgs vds vsrc vb:  alter src ac=1 ; ac lin 1 100meg 100meg ; print imag(i(vgs)) real(i(vgs)) ; alter src ac=0
alter lchoke=1e9 ; alter vgs ac=1 ; noise v(d) vgs dec 1 1 1 ; print inoise_spectrum onoise_spectrum
noise v(d) vgs dec 1 100meg 100meg ; print inoise_spectrum onoise_spectrum ; alter vgs ac=0 ; alter lchoke=1e-15
destroy all
```

## 8. 이 문서가 기대는 가정과 확인 안 한 것

- [추측] 병렬 효율이 낮은 원인이 I/O(점마다 수십 줄의 stdout)라는 것은 확인하지 않았다. 출력을 줄이면 처리량이 더 오를 수 있다.
- 시제품은 nfet L=0.5 VS=0 한 조합에서 열을 검증했다. 병렬 16조합(nfet·pfet, L 0.15~4, VS 0·1.8)은 점 수와 오류만 확인했다. 전 범위의 행합 검사는 G0에서 한다.
- 3절의 R 값은 대용 해상도(격자 한 칸)로 계산한 옛 밀도 판정용이다. 2026-10-07 결정으로 그 판정은 쓰지 않는다. 계획 N3.6 tol_V는 VGS·VDS·VS 축 LOO에 **bin 안 L 방향 LOO**를 더한 정의로 바뀐다(K2').
- 경계 전환점 점프(1.2a)는 W=5, VDS 0.9 V, VGS 3점 × VB 3점에서만 쟀다. 전 격자 판정은 G1에서 한다. L 경계 집합은 모든 W bin에서 같다(모델 파일 실측). 다만 ngspice는 경계 W에서 아래 W bin을 쓴다(1.2a). 그래서 폭 슬라이스는 슬라이스 W를 wmin으로 갖는 bin이 아니라 wmax = W인 bin으로 계산된다. 슬라이스 메타 `model_bin_per_L`(Python 규칙)은 경계 L·W에서 실제 bin과 다르다.
