# LUT 폭·VS 커버리지 조사 (2026-10-07)

범위: `sky130_nfet_pfet_lut_sample.npz`(W=5 um 단일 폭, VS 0~0.8 V)가 엔진 해의 SPICE 대조 오차(engine_current_capability.md 4.3절: finger 실현 시 ID 오차 중앙값 19.5 %, W<2 um +60~106 %, vsb 축 밖 -50~-98 %)를 얼마나 설명하는지, 무엇으로 고칠지.
실측 환경: ngspice-46 `ngspice_con.exe -b`, PDK `C:\pdk\sky130_fd_pr`(tt, 27 C). include 세트는 LUT 생성기와 같다(`__tt.pm3.spice` + `__mismatch.corner.spice`, pfet은 `lod.spice` 추가). 임시 경로 `/c/g457`(작업 뒤 삭제). 메인 저장소·gmid-light는 읽기만 했다.

하네스 검증: W=5 um, L=0.5, VDS=0.9, VS=0에서 LUT 격자점과 비교하면 nfet·pfet ID가 비트 수준으로 같다(VGS 0.45·0.75 V에서 비 1.0000000, 격자 반올림 차가 있는 1.125 V에서 0.997/0.990). 그래서 아래 차이는 하네스 차가 아니라 폭 W 자체의 효과다.

## 1. 방법론: 폭 의존을 다루는 표준 방법

1. **전류밀도 정규화의 전제.** gm/ID 방법론(Jespers·Murmann 계열)은 gm/ID, ID/W, gm/gds, fT를 W와 무관한 밀도 함수로 보고 LUT를 기준 폭 W_ref 하나로 만든다. 이 전제는 (i) 협폭 효과(STI 가장자리 Vth 이동, 유효폭 dW)가 무시될 만큼 W가 크고 (ii) 모델 파라미터가 W에 연속일 때만 성립한다. 프로젝트 체크리스트도 같은 요구를 적어 두었다(`lut-generation-checklist.md` 139행 "기준 소자 W/L이 충분히 큰가", 7.4절 4단계 "W/L 스윕하며 Vth 안정 구간 확인"). sky130에서 4단계를 한 기록은 없다(이번이 처음).
2. **표준 대응 세 가지.**
   * (가) 단위 finger 폭 고정: 레이아웃 finger 폭을 LUT 특성화 폭과 같게 두고 총폭은 finger 수의 정수배로만 바꾼다. 가장 흔한 실무 방식이고, 프로젝트 레이아웃 문서도 unit cell(고정 finger 폭)을 전제로 한다(`stick-diagram-euler-layout.md` 98·510행).
   * (나) 폭 축을 가진 LUT: 실제로 쓸 finger 폭 몇 개에서 따로 특성화하고 설계는 그 격자에서 고른다. 격자 사이 보간은 bin 경계 불연속 때문에 위험하다(2절).
   * (다) 협폭 보정: 큰 폭 LUT + 유효폭(Weff = W - dW)·Vth 이동 보정. 물리 모델이 매끈한 공정용이다.
3. **sky130의 특수성 -- binned 모델.** BSIM4 모델카드가 (L, W) 구간마다 따로 있다(실측, `__tt.pm3.spice`의 lmin/lmax/wmin/wmax).
   * nfet_01v8: 180 bin. W 경계(um) 0.36, 0.39, 0.42, 0.52, 0.54, 0.55, 0.58, 0.60, 0.61, 0.64, 0.65, 0.74, 0.84, 1.0, 1.26, 1.68, 2.0, 3.0, 5.0, 7.0, 100.
   * pfet_01v8: 108 bin. W 경계(um) 0.42, 0.55, 0.64, 0.84, 1.0, 1.26, 1.65, 1.68, 2.0, 3.0, 5.0, 7.0, 100.
   * L 경계(두 소자 같음, um) 0.15, 0.18, 0.25, 0.5, 1.0, 2.0, 4.0, 8.0, 20, 100.
   * 현재 W_ref 5.0 um는 bin 경계(3~5 / 5~7) 위다. 다만 4.9 um와 5.0 um 차는 0.0~2.6 %로 이 경계는 거의 연속이다(표 A).
   * **"충분히 넓으면 평탄" 전제가 nfet에서 성립하지 않는다.** nfet은 W=5 um 대비 넓어질수록 같은 gm/ID의 ID/W가 계속 커져 W=40~100 um에서 포화한다(gm/ID 12, W=100: L=0.15/0.5/1.0 = +34.5/+25.7/+18.2 %, W=40과 1~2 % 차). pfet은 W>=5 um에서 대체로 ±2 % 안으로 평탄하다(L=1.0 gm/ID 20 제외). 즉 sky130 nfet에는 W_ref 하나로 모든 폭을 덮는 영역이 없다 -- **정규화는 측정한 폭 근처에서만 맞는다.**
4. **finger 실현 방식(nf 대 m)도 폭 문제다**(표 E). ngspice는 bin을 총폭 w로 고르고 BSIM4는 크기 의존식을 w/nf로 계산한다. 그래서 `w=10u nf=10` nfet은 7~100 um bin 계수를 1 um로 외삽해 BSIM4 파라미터 검사에서 Fatal(u0 < 0, Pclm < 0)로 죽고, `w=10u nf=2`도 L=0.15에서 -15.6 % 틀린다. `w=5u m=2`는 W=5 단일과 같다(0.0 %). **7a의 `write_spice_netlist`는 finger를 `nf`가 아니라 `w=finger_w m=n_fingers`로 써야 한다**(계획서에 이 규칙 없음).

### 2절 해석

1. **W=5 um 근처(4~6 um)만 맞는다.** 4.0~6.0 um 구간 중앙값 0.2 %, 최악 14 %(nfet L=0.15, W=6 -- 5~7 um bin 안에서도 변한다). 3~7 um로 넓히면 최악 25 %(nfet L=0.15, W=7).
2. **L=0.15 nfet가 가장 나쁘다**: 협폭 쪽 -10~-30 %, 넓은 쪽(W 10~20) gm/ID 16~20에서 +20~+171 %.
3. **L>=0.5에서도 nfet은 넓은 쪽으로 단조 증가**(W=10: +5~+31 %, W=20: +7~+57 %). 엔진 `max_finger_w` 40 um까지 쓰면 이 오차가 그대로 들어간다.
4. **협폭(W<=2 um)**: 같은 gm/ID 8~12에서 nfet -27~+2 %, pfet -22~+5 %(약반전 쪽 gm/ID 16~20은 pfet +99 %~-89 %까지 -- 협폭 소자의 gm/ID 곡선 모양이 다르다, 표 C). 같은 VGS 강제(표 B)로는 pfet 협폭이 +6~+661 % -- 4.3절의 "W<2 um +60~106 %"와 같은 방향·크기다.
5. **4.3절 오차의 설명**: 엔진 finger_w(1~40 um, `assign_finger_geometry` min/max_finger_w 기본 1·40 um, `sizing_recipe.py` 9272행)로 실현하면 표 B 수준(중앙값 15~37 %)의 오차가 나고, 5 um finger로 맞추면 사라진다(4.3절 19.5 % -> 3.2 %와 일치). **4.3절 finger 오차의 주원인은 LUT가 한 폭(5 um)에서만 특성화된 것**이고, 엔진 W 계산 오류가 아니다.
6. **VS 축 밖에서도 폭 의존은 비슷하다**(표 F: W=1 대 5 비가 VS 0 -> 1.6에서 nfet -11 -> -7 %, pfet -12 -> -5 %). 폭 문제와 VS 문제는 독립이라 둘 다 고쳐야 한다.

## 6. 추천안

1. **(b)를 기본 정책으로 즉시**: finger 폭 = LUT 특성화 폭. 값은 상수로 박지 않고 LUT npz 메타 `w_ref_m`(#26 G4가 이미 계획)에서 읽어 `min_finger_w`/`max_finger_w`를 유도한다(지금은 `run_harness._W_REF` 하나뿐). 재생성 없이 4.3절 finger 오차 19.5 % -> 약 3 %. 미러 쌍 finger 폭이 같아져 미러 비 오차도 없어진다. 엔진 공유 코드(사이징 W의 W_ref 정수배 양자화, `assign_finger_geometry` 입력) 변경이므로 사용자 승인 대상. 면적 증가(양자화)는 4회로 실행으로 재야 한다(미측정).
2. **U-27 범위에 DC 전용 협폭 슬라이스 추가(a-DC)를 사용자 결정으로 올린다**: W < W_ref 단일 finger 소자(4.3절 folded M3/M4 1.02 um, M10 1.12 um, current_reuse M58 1.69 um)용. 폭 격자는 지어내지 말고 PDK 특성화 폭(`bins.csv`의 W 값 중 W_ref 이하, 두 소자 공통 0.42·0.55·0.64·0.84·1.0·1.26·1.68·2.0·3.0 um)에서 고르고, 협폭 소자 W는 그 격자 값 중에서만 고르게 한다(격자 사이 보간 금지 -- bin 불연속). 비용 약 20~30 분(2D `.dc`, 실측 0.55 s/회). 용량·잡음은 W_ref 값 W 비례(±9 %, 표 M). 22 h AC 루프에는 폭 축을 넣지 않는다(66~110 h).
3. **(c) 보정계수는 쓰지 않는다**(표 J: L·gm/ID 의존이 커 상수로 안 됨, 같은 측정이 먼저 필요).
4. **7a 넷리스트 규칙으로 기록**: finger는 `w=finger_w m=n_fingers`. `nf`는 ngspice + sky130에서 bin을 총폭으로 골라 틀리거나 Fatal(표 E).
5. **VS**: U-27 VS 0~1.8 V는 계획대로(VGS 100 mV급 오차 때문). folded·current_reuse M2a/M2b의 축 밖 vsb는 LUT가 아니라 F27 엔진 오류이므로 #53·#54가 먼저다.
6. 남는 위험: (b)도 W_ref 자체가 nfet의 "넓은 폭 극한"과 18~35 % 다른 지점이라, 레이아웃이 W_ref와 다른 finger 폭을 강제하는 경우(stack 공유 finger 폭, LR8)에는 오차가 돌아온다. 같은 stack의 finger 폭 공유 규칙이 W_ref 고정과 충돌하는지는 4회로 실행으로 확인해야 한다(미측정).
