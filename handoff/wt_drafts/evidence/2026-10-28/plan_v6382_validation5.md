## 2. 새 결함

### V5-1 (중간) oracle 실행 설정 reader(OP-3)가 기존 LUT 선언 writer(OP-7)보다 앞선다

**사실**

- op :506 OP-3(다섯째 커밋 추가): '실행마다 LUT bin 경계 선언(D-4·G-14)의 호환 모드로 시뮬레이터를 실행하고 다르면 거부'.
  - 선언이 **없을 때**의 동작은 적혀 있지 않다(OP-3 칸에 '선언이 없' 0건).
  - D-4 :575의 `bin_tie_undeclared`는 엔진 규칙이다.
- op :510 OP-7: writer 가운데 '기존 LUT = 이 card의 옆 선언 파일'. 선행 칸 = 'OP-3(…), XRUN-F1 card C 병합 뒤'.
  - 따라서 OP-3이 병합될 때 지금 공유 LUT(기존 LUT)의 선언은 아직 없다.
  - 새 LUT meta writer(OP-8)는 OP-6 뒤라 더 늦다(op :511).
- OP-3 자신의 병합 조건 (c)(op :506)는 '그 선언으로 첫 조합의 공칭 실행이 (i)~(iii)을 통과'를 요구한다. 검증자 실행 기록 (b)·(c)도 같은 실행이다.
- 계획 자신의 선례(op :310): 역할 옆 선언은 '자동 대조가 처음 배선되는 OP-3보다 먼저 있어야 하므로 OP-3 병합 조건 (c)로 둔다'. 즉 이 계획은 'reader가 처음 배선되는 card보다 writer가 먼저'를 이미 규칙으로 쓰고 있다. bin 경계 선언에는 그 규칙이 적용되지 않았다.

**막히는 경로**

- (a) OP-3이 fail-closed로 구현되면(선언 없음 = 거부), OP-3 병합 조건 (c)의 공칭 실행이 통과하지 못한다.
  - OP-7은 OP-3을 기다린다.
  - EO-1(gb :1226, 선행 OP-3)과 그 뒤 모든 동작 변경 card의 SPICE 다리도 막힌다.
- (b) OP-3이 '선언 없으면 어댑터 기본 모드'로 구현되면, 호환 모드의 둘째 출처(어댑터 기본값)가 생긴다.
  - 이것은 DEC-105 (2) '둘째 정본 금지'(gb :304)와 fail-closed에 어긋난다.
  - 계획이 정하지 않은 우회 규칙이기도 하다.
- 어느 쪽이든 OP-3 design이 as-built 결정을 해야 한다. 브리핑 규칙('as-built 결정 금지, 멈추고 보고')상 OP-3 design 착수에서 멈춘다.

### V5-2 (중간) 'W는 graph 필드 아님·반올림 차 출력 전용'이 DEC-23·DE-1의 ΔW 기준과 충돌하고, `DeviceOp.W` 소비자 처리가 범위에 없다

## 3. 경미

- **V5-3 OP-7 범위 변경의 낡은 문언 4곳**
  - op :345 표 '엔진 `bin_index` | … OP-7에서 LUT 생성 실행에 묶은 선언으로'. 지금은 WB-1 범위 0이다.
  - op :550 완료 조건 8 '**엔진**(OP-7, D-4): 9회로 결과 비트 동일'. OP-7은 이제 엔진을 고치지 않는다. 엔진 경계 규칙 변경은 WB-1(동작 변경, O-34)이라 '비트 동일'과도 맞지 않는다. 행 주체와 기준을 다시 적는다.
  - op :510·:522 OP-7의 '9회로 비트 동일 확인'과 'XRUN-F1 card C 뒤(기준선 흔들림 방지)'. 엔진을 고치지 않으므로 근거가 사라졌다. 남길 거면 근거를 다시 적는다.
  - gb :2360 '경계 규칙의 정본은 … 선언으로 옮긴다 -- card OP-7'. 지금은 OP-7(선언 기록)·WB-1(엔진 구현)이다.
- **V5-4 CPG-1 재측정 기록의 묶음**(gb :2275)
  - 기준선 재측정(C′ 판정 전)과 C′ 판정이 **같은 고친 사본**(같은 sha256)을 쓴다는 문언이 없다. 사본 sha256은 '판정 기록에 고정'인데, 재측정은 판정 기록보다 먼저 생긴다.
  - '아카이브 zip 옆 sha256 파일 꼴'이 `wt/_archive`에 새 파일을 쓰라는 뜻인지, 꼴만 따르라는 뜻인지 모호하다.
  - CPG-1 판정 기록이 재측정 기록의 sha256을 인용한다는 문장 하나면 닫힌다.
- **V5-5 V5-1 고침과 함께 Status 정리**: gb :11, op :18의 'reader(… oracle OP-3 실행 설정 …)'는 V5-1 고침을 따라 함께 바꾼다(지금 판에서는 본문과 일치).
- **V5-6 파일 겹침의 반대쪽 표기**: gb :1239·:2251은 OS-2·TR-6과의 `iv_matching_l.py` 겹침을 적었다. 그러나 offset-strategy·offset-trim 계획에는 WB-1 언급이 0이다(grep). 한쪽 표기로도 규칙('나중 card가 rebase')은 성립하므로 경미다. 그 계획을 다음에 개정할 때 넣는다.
