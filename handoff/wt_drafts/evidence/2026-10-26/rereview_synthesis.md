## 종합 권고 (오케스트레이터 판단 -- agent 권고를 원칙으로 다시 판정)

### S1. 계단·출력 범위 값의 자리 하나로 (A·F·oracle U-a/U-b·C 대 F 충돌)
- 판정
  - nmcnr·ngcc의 [0.65,1.15]·[0.14,0.54]는 원문의 과도 측정 계단이다. 출력 범위 요구가 아니다.
  - 같은 값이 출력 범위(O-154 Q4)와 정착 계단(O-145) 두 자리에 있다(⚠ graph 규칙 1).
  - SR 판정 계단은 follower 전 폭(O-120)이라 정착 계단과 다른 양을 잰다.
- 권고
  - (1) 계단은 spec `.tran` 항목의 step 한 자리에만 둔다. nmcnr·ngcc의 출력 범위 선언(O-154 Q4)은 철회한다.
  - (2) SR 판정 계단도 원문 계단이 있으면 같은 step을 쓴다(O-120 수정, 원래 취지와 다름). 원문 계단이 없는 회로는 기존 follower 전 폭을 쓴다.
  - (3) 과도 측정 유효성 조건으로 '계단 입력 구간 ⊆ follower 사용 범위(N3.8 (3))'를 둔다(oracle U-a). 새 measure는 없다. B87 결합이 여기서 판정된다.
  - (4) R10 동적 항의 창 = spec step의 20-80 %. 엔진이 spec 선언을 READS하는 것이라 층 역전이 아니다. E 실측에서 참 창 필요조건 위반(−0.7 µA)이 oracle FAIL과 일치했다. 레일 창(N-1)은 nmcnr에서 항등 성립해 무동작이었다. 그래서 N-1을 수정한다.
- 대안
  - (가) 지금 그대로 둔다(출력 범위 + 계단 + follower 전 폭). ⚠ P2, N-1 무동작.
  - (나) 출력 범위로만 둔다(oracle U-b 가). ⚠ 정의 축이 바뀜(F·oracle 판정).
- nmcnr 계단 위치
  - C는 0.65→1.15를 유지했다.
  - F는 0.4→0.9를 권고했다. 근거는 상단 1.15 V가 β=1에서 입력쌍 gm/ID 29~31.5(LUT 최대 근처)를 강제하고 SR 상한과 충돌한다는 것이다(DC 결론이라 F-1과 무관).
  - 권고는 0.4→0.9(확신도 중). 원문에 위치 근거가 없으므로 사용자가 정한다.

### S2. current_reuse 출력 범위 정의 (사용자 질문 "gain에 맞춰 결정되는 양")
- 사실
  - 원문 ±1.2 V는 '3 dB 이득 저하'로 정의된 양이다.
  - 우리 판정은 '범위 끝 포화'다. 이것이 더 약하다(oracle 실측: 포화 창 ±1.71 대 3 dB 창 ±1.52, 범위 끝 이득 −17 dB). 그래서 값과 정의가 어긋난다(⚠ P0).
- 권고 (나): 원문 정의를 따른다.
  - 범위 끝의 증분 DC 이득(.dc 기울기, DC 양)이 Vod = 0 기울기의 −3 dB 이상인지로 판정한다. 임계는 원문 정의에서 온다(상수 발명 아님).
  - 원래 취지와 다르다: 새 요구 꼴이다. 엔진 쪽은 R8 포화 + 범위 끝 gm/gds 손계산 행이 필요하다(LA-1·DE-1 범위).
- 대안 (가): 포화 기준(oracle 권고)을 유지하고 '원문 3 dB 값을 포화 기준으로 차용'이라고 표지한다. ⚠ P0 정의 불일치를 기록으로만 남긴다.
- 차동 Vod + CM 선언과 S0 노드 범위 유도(O-154 Q2)는 유지한다.
