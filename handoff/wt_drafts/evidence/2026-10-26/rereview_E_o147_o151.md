### 1.3 실현 가능성(확인한 것 / 미확인)
- (C) 'oracle 실행 수'의 출처: 계획에 엔진 쪽 oracle 호출 계수 필드 정의 없음(N6.30 grep). → 감사 agent가 S3 기록·oracle 로그에서 센다고 평가 절차 문서에 적어야 한다(**미확인**: 지금 기록 형식에 점 단위 oracle 판정 수가 남는지).
- (C)의 비교점: front는 점 집합이다. '통과점의 전력·면적'을 무엇과 무엇으로 비교할지(비지배 집합 대 집합 지배 관계 등)가 없다 → 평가 절차 문서 몫이라고 명시(N6.30 착수 조건 '기록 형식'에 포함).
- spec 통과 판정 가능 여부: nmcnr·ngcc의 SR은 oracle 슬루 벤치(OP-10)와 추종 판정(§7) 뒤에야 판정된다(N3.8 순서 조건). current_reuse 정착은 AP-1 대기. LA-1 병합만으로는 (C)·(A) 모두 이 항목이 '판정 불능'이다(실측: as-built oracle 슬루 `.tran` 0 -- `sr_start_bound_feedback.md` §0).

### 1.4 원칙 점검
- ⚠ 원칙 경고: 논문 값 인용 금지·독립성 -- library 회로는 원문 논문에 사이징 표가 있다(`assets/library/sources/*/paper.md`). (A) agent가 이를 읽으면 '손계산 출발'이 아니라 원문 값 복사가 된다 -- 독립성 조항에 '원문 사이징 표·엔진 증거(`_drafts/evidence`, `_scratch_*`의 봉인 θ) 열람 금지'가 없다.
- ⚠ 원칙 경고: heldout 금지 -- library 전부를 쓰는 것은 맞다. 그러나 엔진은 이 회로들로 개발·조정됐다(in-sample). 결과를 '엔진 방향 결정'에 쓰려면 이 편향을 보고에 적어야 한다(원래 취지 '의미를 숫자로 확인'에 필요한 단서).
- 작성자≠검증자·게이트 아님·엔진 코드 0: 옛 안 그대로 ○.
- graph 단일 정본: 엔진 변경 0이라 해당 없음 ○.

## 4. DK2 -- R10 셀 전류 'R9 조회 함수를 블록 안에서 계산'

**결정**: R9 조회 = 함수 하나(정의 하나), 출발 구간 블록·층 0 블록이 '그 스냅샷 θ에서 블록 안 계산', 봉인 스냅샷에서는 R9 필드 READS(O-155 m-2), 구현 card SB-1.

### 4.1 코드 흐름 확인(특히 볼 것 3)
1. **층 0 후보 θ = 봉인 θ.** as-built `kernel.evaluate(sctx, theta, …)`(search/kernel.py 머리)는 받은 θ를 그대로 `size_and_seal`로 봉인한다. 계획 DEC-71 (3)·(4)(c)도 층 0 국소 문제가 θ(S·F gm/ID·L·θ 전류)를 정하고 커널에 넘긴다. 수리·R6 재파생은 종속 성분만 바꾼다(R6). 그래서 **층 0 후보의 θ 독립 성분과 그 점 봉인 θ는 같다**. 계획 근거 문장 'θ가 다르면 값이 달라 둘째 생산자가 아니다'는 이 경우에 성립하지 않는다.
2. **그런데 값은 같지 않다 -- 다른 축은 동작점이다.** 바이어스 구동 레일 source 셀의 I_cell(V_DS 끝) = (W/L)·IDu(V_GS, V_DS 끝). W = θ에서 바로 정해지지만 V_GS는 ln IDu 좌표를 **그 소자의 동작점 (V_DS, V_SB)**에서 LUT 역산한 값이다(as-built `block_columns.update`: `_vgs_of_coordinate(lut, m, kind, L, vds, vsb, ln_idu)`). 층 0 국소 문제는 '후보의 θ와 (VDS, VSB)'(DEC-71 (4)(c-1))를 쓰고, 출발 단계는 출발 곡선 동작점 `start.point`를 쓴다. 봉인 R9는 커널 DC 해의 동작점을 쓴다. 그래서 같은 정의를 **다른 정밀도의 동작점 입력**으로 계산한다 -- graph 규칙 3('정의가 다를 때만 새 필드, 다른 축을 문서에 적음')의 대상이고, 지금 문언은 그 축을 'θ'로 잘못 적었다.
3. **P0 위험.** 동작점 추정이 실제보다 V_DS_op를 크게 잡으면 V_GS를 작게 잡아 I_cell(끝)을 과소 추정한다 → 하한이 세진다 → R4 정의역 자르기(gm/ID 상한 = gm_req/I_min)가 실현 가능한 영역을 잘라낸다. 크기: 같은 셀의 CLM 전류 변화가 nmcnr M302에서 정지 17.5 µA 대 20-80 중 14.9~27.3 µA(1.56배), ngcc M12에서 VDS 1.49 → 1.8 V로 148 → 261 µA(1.76배, 이번 n1 실측)다. 동작점 오차가 수십 %의 하한 오차가 될 수 있다(**미실측**: 층 0 추정 동작점 대 봉인 동작점의 실제 차이).
4. **봉인 뒤 다시 계산하면 둘째 생산자.** 층 0 최대-최소 반복은 x마다 커널 평가를 부른다(as-built layer0_center.py §3 '같은 x의 같은 평가'). 그 평가 뒤에 블록 안에서 같은 동작점으로 함수를 다시 부르면 DE-1 R9 필드와 같은 값의 둘째 생산자다. O-155 m-2('봉인 스냅샷에서는 READS')가 막지만, '층 0 블록'이 커널 전 국소 문제인지 커널 뒤 반복인지 문언이 가르지 않는다.

### 7.2 끝 시각 민감도(`t2_endtime.jsonl`)
같은 파형을 t_end = t_step + k·(t80 − t_step)에서 잘랐다.
- k = 0.8: 80 % 수준을 지난 모든 방향(ngcc 18·nmcnr 14)이 FAIL(80 % 수준 전에 끝남) -- 끝 시각이 짧으면 좋은 점도 정의 불능(거짓 FAIL).
- k = 1.0~3.0: 대부분 통과. nmcnr l0_allx0.5 상승은 k = 1.0 FAIL, 1.2 통과(레일로 가는 중).
- k = 5: nmcnr r5v2m_M202x0.5 하강이 통과 → FAIL로 뒤집힘(울림, 넘침 16 %).
- 판독: (나)는 끝 시각 한 점에 기대므로 판정이 끝 시각에 따라 바뀐다. 계획은 끝 시각을 'OP-10 design이 정의 근거와 함께, 새 상수 금지'로 미뤘지만 정의 근거가 제시되지 않았다 → ⚠ 원칙 경고: P1 상수 발명 금지 -- 끝 시각 규칙이 없으면 하네스 관례(6·|Δ|/SR_추정, 정착 안 되면 ×4)가 사실상 상수가 된다 -- 근거 `_scratch_srfb/scripts/orc.py` `measure`.
- 표본 한계: 이 표본에는 SR spec을 통과하는 점이 0이다(nmcnr 0.05~0.34 대 0.36, ngcc 0.17~0.57 대 6.3). 통과하는 점에서의 거짓 FAIL은 직접 재지 못했다(**미확인**).

### 7.4 판정

## 10. M3 -- 커널이 종속 W4를 목표 전압으로 받음(특히 볼 것 5)

### 10.1 as-built 확인
- W4 노드 writer 식: `block_columns.update`·`writer_grad`(sizing/block_columns.py 440~548행) -- V = lo + y·(hi − lo), lo·hi = 이웃 노드 값(순서 항 `order_terms`)과 입력 포화 창 덮어쓰기(`override`)로 DC 순환 블록 안에서 매번 다시 계산, 빈 창이면 `SealViolationError(empty_window)`. Newton 야코비안 행은 lo·hi를 정한 이웃 노드에 1 − y, y.
- 목표 전압으로 바꾸면: writer 식 = V*(상수), 야코비안 행 = 빈 사전(이웃 의존 없음 -- 더 단순), 엄격 검증 바퀴에서 lo ≤ V* ≤ hi 확인 → 밖이면 chain_violation(O-155 M-3), y = (V* − lo)/(hi − lo)는 수렴 뒤 보고 양. Gauss-Seidel 비엄격 바퀴의 '빈 창이면 현재 값 유지' 갈래는 그대로 쓸 수 있다.
- 막히는 곳(결함 아님, **재작성 범위** -- O-153): θ 스키마의 `THETA_Y` 종류·`theta_check`(0 ≤ y ≤ 1)·`eval_key`(θ 지문)·`kernel_run._COLUMN_KINDS`, 그리고 커널 입력에 R6 출력 필드 참조를 더하는 자리. 모두 블록 경계 안 변경이다.
- headroom-chain X-1·N3.1-7은 v0.7.9.1에서 'y 정의·창 계산 그대로, y는 커널 (a) 안에서 정해짐'으로 이미 정리됐다(충돌 없음).

### 10.2 남는 위험
R6가 고른 V*는 그 스냅샷의 창 추정 위에서 max-min으로 고른 점이다. 커널의 정확한 창이 추정 창과 다르면 V*가 창 밖으로 나가 chain_violation(clamp 금지)이 된다 -- 실현 가능한 y가 있었던 점을 버리는 경우(P0 손해). 시제품은 W4 전위를 y로 바꾸는 창 되읽기를 썼고(r5r6_prototype.md 45행 'proto set_y와 같은 창 되읽기') 검증자는 '창 다시 읽기 4회'를 적었다 -- 창이 움직인다는 뜻이다. max-min 점은 창 가운데 쪽이라 작은 이동에는 남지만, 창 밖으로 나간 빈도는 기록이 없다(**미확인**).
