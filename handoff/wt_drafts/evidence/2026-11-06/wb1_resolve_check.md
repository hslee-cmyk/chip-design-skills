- **A (빠진 선행): LI-1의 VGS 보존(`slice_density` gm/ID → VGS 순방향 조회)을 먼저 또는 함께.** 안 2만 넣으면 OTA는 VGS 52 mV·전류 5.7 % 옮겨진 점으로 수렴하고, CG는 −70 %로 걷고, folded는 22/22 비수렴이다. VGS 보존을 넣으면 OTA·CG·folded가 모두 1~3회에 수렴한다(최대 ΔVGS 4.8 mV OTA, 8.3 mV folded). card 순서 문제다(LI-1 미병합).
- **B: 레이아웃 보존량 입력 = 사이징 점(출발 점 또는 W_request를 반영한 θ 점) 스냅샷.** 재풀이 스냅샷을 레이아웃 입력으로 쓰지 않는다. 실측: 같은 결과에 재평가 수가 1~2회로 줄고 표류가 없다. W_request가 있으면 'θ + W_request' 사이징 평가 스냅샷이 따로 필요하다(그 점의 DC 풀이를 한 번 더 함 -- P:305 대안 (나)와 같은 비용 문제). **못 잼**: W_request가 실제로 난 경우(folded에서 거부 2회만 봄).
- **C: 봉인 3에서 전압 구동 입력 넷의 외부 원 전류.** 입력 포트가 채널 전류를 받는 회로(CG `vin`)에서는 servo도 입력 고정도 그 넷 KCL 행에서 진다. 물리적으로 입력 전압원이 차 전류를 댄다. 행을 빼거나 원 전류를 기록 칸으로 두면 통과한다(probe). 봉인 정의 변경이라 사용자 결정 대상이다(원칙 19). tol 완화가 아니다.
- **D: as_is는 입력 고정 KCL 재풀이(안 5의 None 갈래와 같은 처리), servo로 보내지 않음.** 근거: IT-2c as_is = '회로 그대로', pushpull 선언 `input_dc`(U-25)와 oracle 입력 DC 칸(oracle P8 DV-15)이 입력을 정한다. 실측 차이: pushpull 0.02 mV 이하, CG(VGS 보존) 입력 고정 ΔV_out +193.6 mV 대 servo ΔV_in 0.3 mV. 둘 다 봉인 통과(C 적용 시). 고이득 단일 입력에서 servo 쪽 근거(DEC-23 V_id* 단일 입력 = 입력 포트 이동량)는 측정 정의로는 있지만, 동작점을 입력 이동으로 정하는 근거로 쓸 결정은 없다 → **조건부, 사용자 결정 대상**.
- 전력 축 정본(원칙 7 칸 (ii))은 어느 안을 고르든 고쳐야 한다.

## 못 잰 것

- ngcc_3stage_ff·pushpull 레이아웃 루프(c ≥ 0인 손 출발 점 없음). pushpull은 실현 평가 단계만 쟀다.
- folded gm/ID 보존 + 재풀이 비수렴의 원인(물리·수치).
- W_request가 실제로 처리되는 경로(대안 B의 θ + W_request 스냅샷).
- OTA 점은 i = 12, j = 5 하나만 쟀다(n/N = 회로 3/5에서 루프, 1/5에서 실현 단계만).
- 안 1만 넣은 OTA 대조는 출발이 실현 평가 뒤인 판(RS = 1)으로 다시 돌리지 않았다. 앞 조사 `q1_placed.txt`(RS = 0, infeasible 21회·키 제외 19)와 folded `l_fc_placed.txt`(infeasible 22회·19)로 갈음했다.
