## 2. Major

### MJ-1 대칭 짝이 KVL 짝 정의에서 떨어져 다멤버 칸 출발 불능 문장과 충돌 (결정 왜곡·계획 내부 모순)

- 사실(plan 308행, 개정 뒤):
  - IDu_p 정의는 '그 멤버의 **KVL 짝**의 … (KVL 짝 = 그 멤버와 gate·source·bulk·kind·L이 **모두 같은** 쓰기 소자 …)'이고, 바로 뒤에 '차동쌍·가지 대칭은 대칭으로 같은 밀도'가 온다.
  - 새 문장은 '다멤버 칸에 **KVL 짝 없는 비쓰기 멤버가 있거나**, 칸 크기와 무관하게 I_i가 없으면 그 칸 출발 불능'이다. 옛 문장은 'KVL 짝 쓰기 멤버가 없거나'였다. 옛 정의는 'VGS·VSB를 공유하는 … 미러 = 같은 gate·같은 source'처럼 예시 꼴이었고, 대칭으로 같은 VGS를 갖는 경우를 막지 않았다.
- 결과: 차동쌍·가지 대칭 반쪽은 gate가 다르므로 새 정의로는 KVL 짝이 없다. 그 칸은 다멤버라 새 문장대로면 출발 불능이다.
- 측정(FS-1 판정의 `partner.jsonl` -- 같은 gate·source·bulk·kind 쓰기 소자가 없는 비쓰기 MOS, 판정자 재독): current_reuse M1b·M4b, folded_cascode M1, nmcnr M102, sf_pushpull M2, two_stage M1. 모두 diff_pair·branch_symmetric 다멤버 칸의 반쪽이다(`m_s1.jsonl` matching_groups). 그런데도 실측 다멤버 None 0/32가 나온 것은 엔진이 `kvl_partner(...) or _symmetric_partner(...)`(`start_intervals.py:271`)로 대칭 짝을 짝으로 주기 때문이다. interface §3.3 괄호도 '대칭 짝은 출발 블록이 … 직접 짝으로 준다'고 적는다.
- 판단:
  - 물리적으로 대칭 짝의 밀도는 맞다. 균형 출발점에서 같은 VGS·VSB이고, 정합 묶음이라 L도 같다(LY2).
  - 문제는 계획 문언이다. 문언이 대칭 짝을 KVL 짝으로 세지 않은 채 'KVL 짝 없는 비쓰기 멤버'를 출발 불능으로 정하면 둘 중 하나가 일어난다. (a) 문언대로 구현해 6/7 회로(2회로 연기 대상 folded_cascode 포함)가 출발 불능이 되거나, (b) 코드가 다시 계획과 다르게 동작하게 된다(M-2와 같은 무표지 편차 꼴).
  - A-196·판정 §2.4의 의도는 '칸 무관 + L 같음'뿐이었고 대칭 짝 제거는 의도에 없었다. 따라서 결정 왜곡이다.
- 고칠 방향(계획 문언, code 변경 없음):
  1. DEC-108 (3)에 **짝** = KVL 짝 ∪ **대칭 짝**을 정의한다. 대칭 짝 = 그 멤버가 든 `graph.matching_groups` diff_pair·branch_symmetric 묶음(칸을 만드는 status)의 다른 쓰기 멤버이고, 둘 이상이면 이름 무관 정준 순서로 고른다. 물리 결정자도 적는다: 균형 출발점의 같은 VGS·VSB와 정합 L 공유(LY2).
  2. '짝 없는 단일 멤버 칸'의 'KVL 짝이 없어 W_i를 낼 수 없으면'과 다멤버 문장의 'KVL 짝 없는 비쓰기 멤버가 있거나'를 '**짝(KVL 짝·대칭 짝)이 없어 W_i를 낼 수 없는** 비쓰기 멤버'로 바꾼다.
  3. N6.43 완료 (2)에 toy (e)를 더한다: 차동쌍의 비쓰기 반쪽 → 대칭 짝 밀도로 W_i가 나오고 칸 출발이 정의됨. (b)의 '짝 없는'도 같은 정의로 읽히게 맞춘다.
  4. 같은 커밋에서 history 'v6.39.5'의 '원래 취지와 다름' (2) 문구('같은 칸' 철회 → 칸 무관 + L 같음, 대칭 짝 유지)를 정정한다.
