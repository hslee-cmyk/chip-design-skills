## 0. 결론

**'KCL이 맞다'가 유지된다. 근거는 v1보다 훨씬 강해졌다.**

1. **동작점이 맞는다.** 기하를 바로잡자 SPICE 봉인점(구성 B, x0)이 엔진과 맞았다.
   - 노드: 세 회로 모두 0.3 mV 안이다.
   - 소자 여유: 엔진 slack과 1.05 mV 안이다.
   - 그래서 v1의 '모형 여유 차'(최대 94 mV)는 결함의 산물이었다. 이제 0이다.
   - folded_cascode도 SPICE 창이 생겨 창 끝을 비교했다.
2. **감도(구성 B, x0)**: KCL은 SPICE `.dc` 접선과 사실상 같다. θ 고정은 θ 가정이 걸린 자리에서 틀린다.

   | 회로 | KCL 최대 오차 (V/V) | θ 고정 최대 오차 (V/V) |
   |---|---|---|
   | two_stage_ota | 0.0010 | 0.061 |
   | ngcc_3stage_ff | 0.0013 | 0.186 |
   | folded_cascode | 0.0010~0.0013 | 0.061 |

   θ가 틀리는 자리는 바이어스 gate 이동과 종속 소자 gds 무시다.
3. **창 끝에서 틀이 정하는 몫(구성 B)**

   | 틀 | two_stage 아래 / 위 | ngcc 위 | folded 아래 / 위 |
   |---|---|---|---|
   | KCL | +0.3 / +0.3 mV | −0.9 mV | +0.1 / −0.7 mV |
   | θ 고정 | +31.4 / +10.2 mV | **−70.3** mV | +1.6 / −6.8 mV |

   θ의 틀 몫은 최대 70 mV로 tol_VDsat(1.9~20 mV)를 넘는다. 그래서 'θ 고정으로 충분'은 기각한다.
4. **남는 창 끝 오차는 틀과 무관하다.** 남는 것은 곡률(선형 외삽 대 대신호)과 VDsat 이동이고, 두 틀에 같다.
   - 곡률: +26.7 / −10.4(two_stage), −36.3(ngcc 위), +18.6 / +1.6 mV(folded)
   - VDsat 이동: folded 아래 −10.3 mV
5. **창 끝 전체 오차(구성 B, 레일로 자름)**: KCL은 다섯 끝 가운데 네 곳에서 SPICE에 더 가깝다.

   | 회로·끝 | KCL | θ 고정 |

   | ngcc 위 | −37.1 mV | −106.5 mV |
   | folded 아래 / 위 | +8.5 / +0.4 mV | +10.1 / −5.8 mV |

## 1. 방법 (v1과 다른 점만)

1. **슬라이스 폭은 엔진 정본 필드에서 읽었다.** `scripts/slice_wm.py`가 엔진 LUT를 읽고, 소자마다 `LUT.slice_map[(kind, w_key)].w_m`을 `slice_wm.json`에 썼다. 세 회로 모든 소자에서 nmos·pmos `w_key` 1000이고, `w_m` = 4.9999999999999996e-06 m다. 숫자를 곱해 만든 폭은 없다.
2. **기하**: finger 폭 = w_m, m = W / w_m(실수 배수, 진단 전용)이다.
   - 오라클 경로(`legacy_adapter.convert` → `validate_input` → `write_netlists` free)는 v1과 같다. 오라클 스키마의 `n_fingers`가 정수라서 instance 행에는 finger_w = w_m, n = max(1, round(W/w_m))를 넘겼다.
   - 쓴 넷리스트에서 MOS 행의 `m=`만 실수 W/w_m으로 바꿨다(`*.free.mreal.cir`, 패치 수 = MOS 수 7 / 16 / 13 검사).
   - 확산 기하(ad/as/pd/ps)는 오라클 출력 그대로다: finger 폭 규칙 ad = 2.5 pm², pd = 7 µm. LUT 생성기 DUT 줄과 같다.
   - 예: two_stage `XM3 … w=5e-06 m=0.175994053706`.
3. 나머지는 v1과 같다.
   - 오라클 경로 조정: ngcc `sizing_roles` null 사본, 수동소자 값을 엔진 값으로.
   - C15 `verified`, 스키마 위반 0, 막힘 0, bulk 일치.
   - 구성 A(순수 follower, Vofs = 0)와 B(봉인점 유지 follower).
   - `.dc` 0.5 mV 간격으로 x0에서 양쪽 레일까지. ngspice 오류 0, 모든 훑기가 끝까지 돌았다.
   - tol: 엔진 `tol_vdsat_table`. `tol_seal`이 본 판정이고 `tol_pt`가 참고다.
   - 레일로 자름. A의 KCL 둘째 우변 식은 이 분석이 세운 것이다(design에 없음).

## 4. 판정과 계획 함의

**판정: 'KCL이 맞다'.**
- KCL 감도는 SPICE `.dc` 접선과 0.0013 V/V 안에서 같다.
- 끝에서 틀이 정하는 몫은 KCL ≤ 0.9 mV, θ 고정 최대 70 mV다.
- 두 틀이 함께 SPICE와 다른 몫(곡률, VDsat 이동)은 선형 끝 자체의 한계다. 어느 틀을 고르든 같다.

계획 함의(v1 4절을 고친 것):

1. **계획 N3.8의 HZ follower 정의를 'θ 고정 손계산'에서 KCL(`graph.ss_nodal` + follower Schur 1칸, KVL 고정·단일 입력과 같은 계)로 바꾼다. 원래 취지와 다르다(사용자 결정 필요).**
   - 상위 취지(O-50·O-53 '오라클 `.dc`와 같은 구성 하나', 물리 우선)에는 KCL이 정확히 맞는다. 오라클 가정(W·바이어스 고정)의 DC 접선 그 자체이기 때문이다.
2. **다듬은 창 -- v1 서술을 고친다.**
   - 선형 끝의 곡률 오차는 tol보다 크다. 구성 B에서 최대 36 mV, 구성 A에서 KCL 끝 오차 최대 50 mV다. 그래서 'HZ는 선형 감도 끝만, 정확값은 오라클' 길을 고르면 HZ 창 정밀도가 tol 수준이 아니라 수십 mV의 '추정'이 된다.
   - 지금의 θ 고정 다듬은 창(대신호 끝 풀이)은 곡률은 풀지만 θ 가정을 대신호로 지닌다. 그래서 KCL 출발 창과 고정 변수가 달라진다(N6.6 범위 1 '같은 측정 구성·같은 기준' 위반). θ 다듬은 창의 SPICE 대비 오차는 **미확인**이다.
   - tol 정밀도가 필요하면 다듬은 창을 W·바이어스 고정 대신호 끝 풀이로 바꾸는 길이 있다. 이것은 새 풀이기 문제(손계산 속도 원칙과의 균형)를 낳으므로 별도 계획 결정이다.
   - 이 분석은 어느 쪽이 맞는지 정하지 않는다. 곡률 크기(≤ 36 / 50 mV)만 근거로 내놓는다.
3. **접근 경로 (가′)**: 그대로다. `region_rows`, `saturation_window`(`slope=` 갈래), `node.dc_v` READS가 필요하다. 감도 생산자만 θ 연립(`writer_grad`)에서 `graph.ss_nodal` + Schur로 바뀐다.
4. **원칙 점검**

   | 원칙 | 점검 결과 |
   |---|---|
   | 물리 우선 | KCL은 SPICE 접선과 정확히 같다. 위반 없음. |
   | DC/AC 분리 | KCL은 ω→0 DC 야코비안이고 `.dc` 접선과 0.001 V/V로 일치한다. 위반 없음. |
   | graph 단일 정본 | HZ 감도 생산자가 `graph.ss_nodal` 하나로 모인다. θ 연립이라는 둘째 생산자가 없어진다. 새 cache·사본 없음. 이번 수정에서도 슬라이스 폭은 정본 필드 `slice_map[...].w_m`에서 읽었다. |
   | 상수 발명 | 0건. |
   | 회로 이름 | 엔진·권고에 0건. |

## 5. 권고 (하나)

**HZ follower 측정 구성 감도를 KCL로 정의하도록 계획 N3.8을 개정한다(원래 취지와 다름, 사용자 결정).**

- KCL = `graph.ss_nodal` + follower Schur 1칸, (3)·(5)와 같은 계다.
- 함께 정해야 할 종속 결정이 있다: HZ 다듬은 창의 정의다. 고를 수 있는 것은 θ 고정 끝 풀이 유지(출발 창과 정의 불일치), 선형 끝만('추정', 곡률 ≤ 36/50 mV), W 고정 대신호 끝 풀이(새 풀이기)다.
- v1 권고는 '선형 끝만'에 무게를 실었다. 그러나 v2 수치로는 곡률이 tol보다 크므로 그 무게를 거둔다. 대신 이 수치를 근거로 사용자 결정에 올린다.

## 6. 미확인

1. θ 고정 다듬은 창(대신호 끝 풀이)의 SPICE 대비 오차. 실행하지 않았다.
2. 실현 가능한 finger(≥ 5 µm, 정수 m) 기하에서의 창 끝. B74 기준으로 노드 최대 40.5 mV가 남는데, 이것은 DEC-89 몫이다. 이번 비교는 엔진 모형을 그대로 옮긴 진단 기하(실수 m)다.
3. 봉인점은 회로당 layer0 시작점 하나다(비현실 폭 포함). 탐색 해·heldout 회로·two_stage_ota_sf는 재지 않았다.
4. 구성 A의 KCL 둘째 우변 식은 이 분석이 세운 것이다.
5. 오라클 경로: 새 엔진용 출구가 없어 `legacy_adapter.convert`에 엔진 값 dump를 넣었다. 실수 m은 오라클 스키마 밖이라 넷리스트 쓴 뒤 `m=`만 고쳤다. 이것을 '기존 경로'로 인정할지는 오케스트레이터 판단이다.
