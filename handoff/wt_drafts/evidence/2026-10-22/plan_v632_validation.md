## 3. 실현 가능성

- **seal 실패 자리**: `seal.py:63`·`:71`의 `calls`에 커널 단계와 이미 성공한 봉인 항목이 누적된다. 실패한 블록은 `:71` 전이라 빠진다. `base`는 필수다(`:49`). 지금 있는 지역 변수만으로 된다.
- **커널 실패 자리**: `_call_block(ctx, block, snapshot, extras)`(`kernel_run.py:56`)는 지금 앞 블록을 받지 않는다. 인자를 하나 더하면 된다. 루프 `:88-89`(steps)와 `:100-101`(later)에서 앞선 블록 목록을 지역 변수로 만들 수 있다. 가능하다.
- **재연 예외(S3 replay)**: `compute_block.py:150-156`은 `from_record`로 **새** 예외 객체를 만든다(`partial` None). 그 예외는 가장 안쪽 try(`_call_block` 또는 `seal.py:68`)에서 줄인 스냅샷을 붙인다. 첫 부착 유지(`failure_partial.py:19`)와 충돌하지 않는다. `seal_dc`는 `_call_block`을 거치지 않아(`kernel_run.py:104`) 두 번 붙는 일도 없다.
- **함수 하나·입력 형태**: 세 자리의 입력이 다르다. keep은 블록 객체(steps는 (block, extras), later·`SEAL_ITEM_BLOCKS`는 블록)이고, coverage와 seal 부착은 (block, extras)다. 함수가 `(base, 블록 이름들)` 또는 `(base, 블록들)`을 받으면 세 자리 모두 `b for b, _ in calls` 꼴로 부를 수 있다. 가능하다. 단 coverage의 서로소 단언(`seal_versions.py:34`)은 합집합이 아니라 base 집합과 호출 이름을 따로 써야 한다(S-1).
- import 방향: `kernel_run → seal → seal_versions`라 순환이 없다.

## 4. 완료 조건 (11)(e)

**등식 성립 여부**: 성립한다. 판단 근거는 다음과 같다.
- 스냅샷 fp는 내용 지문이다. 레코드 fp는 필드를 이름순으로 정렬한 `(field, value_fp)`이다(`graph_record.py:39-47`). 스냅샷 fp는 kind·key 정렬이다(`graph_snapshot.py:40-41`, `:68-73`). writer·입력 버전·쓰기 횟수·`block_versions`는 들어가지 않는다. 그래서 삽입 순서나 `write_count` 차이(parent 경로는 기존 FieldValue를 유지하고 parent 없는 경로는 count 1)로는 어긋나지 않는다.
- k 앞 블록은 parent 경로에서 reuse·graft·compute 중 무엇이 되든 입력 버전이 같다. 블록은 투영만 받는 순수 함수다. 그래서 값이 같다(입력 버전에 투영 fp가 들어가 귀납이 성립한다).
- base writer 필드는 parent 일치 검사(`kernel_run.py:73-74`)와 writer 권한표 때문에 `ctx.base`와 같다.
- reuse된 앞 블록의 parent FieldValue는 `input_version`도 같다.

**반례 후보**: 내용 지문 쪽 반례는 찾지 못했다. 다만 판정 절차에 결함이 있다(G-1). 필드 writer 등식에도 위험이 있다(N-5).

**oracle 독립성**: parent 없는 평가에서는 줄이기가 no-op이다. 그래서 기대값이 피검 축소 code 없이 만들어진다. 같은 엔진을 쓰는 변성(metamorphic) 관계이고, 축소 로직에 대해서는 독립적이다(N-6).

- 위치: `plan.md:1523` (11)(e) "그 fp가 같은 θ를 parent 없이 평가해 … fp와 같고"
- 근거:
  - 평가 키 `eval_key(context_fp, schema_fp, pairs, cells, geometry)`(`search/kernel.py:100`)에 parent가 없다.

  - 또 parent 경로에서 블록 k가 실패하려면 k의 입력 버전이 parent와 달라야 한다. 같으면 reuse돼 실패가 나지 않는다(`compute_block.py:143`). 이 조건도 문언에 없다.

  - "주입한 θ는 parent θ와 달라 블록 k의 입력 버전이 parent와 다르다(reuse면 무효)."
