## 1. DV-10 -- 확정 ICMR 끝이 오라클 슬루 실행에 닿는 경로

### 1.1 원문 확인
- **O-51**(user_decisions 671행): "슬루 계단 끝의 ICMR 창 = (나) 오라클이 잰 창 … 근거: 오라클은 정의의 정확값을 엔진과 독립으로 재야 하고, 엔진 추정 창을 넣으면 엔진 ICMR 추정 오차가 슬루 모델 오차에서 가려짐; 대가 = 2단계 왕복 하나 더".
- **N3.9 슬루 행**(계획 431행): "그 'ICMR 창' = 오라클이 잰 ICMR 창(SPICE 실제 허용 입력 범위 끝, **2단계 전도 판정까지 확정된 값**) … 엔진 창을 오라클에 넣으면 … 가려지므로 넣지 않는다".
- **G-19**(계획 582행): "계단 끝 = 오라클이 잰 ICMR 창 끝(… 같은 입력의 OP-5 ICMR 측정을 2단계까지 확정한 뒤 그 끝을 쓴다; **계단 끝 입력 칸은 두지 않고 엔진 창을 받지 않음**; 순서 = ICMR 측정 → 슬루 계단, 2단계 왕복 하나 더 …)".
- **OP-10 행**(계획 490행): "같은 입력에서 먼저 OP-5 ICMR 측정(1단계 오라클 훑기 → 2단계 전도 판정 → 끝 확정)을 하고, 그 확정 창 끝을 방향별 계단 끝으로 슬루 `.tran`을 돌린다". **누가 슬루 요청을 내는지, 확정 끝이 어떤 형식으로 넘어가는지는 없다** -- design의 지적이 맞다.
- **두 단계**(계획 413-417행, O-55 U2): 2단계 = 엔진 쪽 공용 전도 판정 함수(LUT로 I_off·tol_V); 오라클은 엔진 import 안 함(NFR-P3); 오라클 안 LUT 사본 기각(O-50 G5). 끝 괄호 재요청은 2단계가 오라클 결과의 `rounds_left`를 **그대로 돌려주는** 입력 칸(G-18 '훑기 구간 입력 칸', design `/sweep_rezoom`)으로 한다 -- 즉 **'2단계가 오라클 결과에서 읽은 것을 오라클 입력 칸으로 되돌린다'는 경로는 이미 계획이 승인한 선례**다.

### 1.2 질문에 대한 답: 계단 끝이 양쪽이 이미 가진 데이터의 순수 함수인가?
아니다. 확정 끝 = '1단계 끝과 2단계 첫 전도 쪽 이탈 끝 가운데 공칭에 가까운 쪽'이고, 2단계 판정 I_off ≤ ε·ID에는 LUT 양(I_off·tol_V)이 든다. 오라클은 LUT 보간 규칙을 갖지 않는다(G5, 사본 기각). 따라서 오라클이 '같은 엔진 공용 함수'를 스스로 부르는 안은 import 금지(NFR-P3) 위반이고, 그 함수를 다시 쓰는 안은 사본(단일 정본 위반)이다. 둘 다 불가.

단, 확정 끝의 **전압 값 자체는 언제나 오라클이 이미 잰 점 하나**다(창 끝 = 마지막 통과 점 = 오라클 `conduction.points[]`의 한 점, rezoom 결과 포함). 2단계가 더하는 정보는 '어느 점이 끝인가'라는 **선택**뿐이다. 이것이 아래 권고의 근거다.

## 2. DV-11 -- 단일 입력 회로의 불일치 σ 입력 환산(`.tf` A)

### 2.1 원문 확인
- **계획 N3.9 `offset_in_sigma_mv` 행(433행)**: "V_os,k = (V_out,k − V_out,0)/A − (V_id,k − V_id,0), **A = DC 소신호 차동 이득(`.tf`)** | MC `.op` + `.tf`(servo를 연 개루프 벤치)". 단일 입력 언급 없음.
- **O-43 D1 (d)**(663행): ".tf로 DC 이득 직접 측정으로 바꿔 출처 없는 상수 1e-3 제거" -- A의 출처만 정함, 범위는 정하지 않음.
- **O-50 G1**(670행): "계통 offset … 단일 입력 회로 = 여기 방향 일반형(출력을 기준으로 되돌리는 여기 방향 입력 이동량, O-33 (7))" -- 계통 offset만.
- **정의 정본 gain-budget DEC-23(223행)**: σ = "… 분산을 **차동 이득으로** 입력 환산한 값"; 같은 DEC의 계통 offset = "같은 DC 방정식의 **여기 방향 DC 극한 전달 A_dc**(여기 방향 단위 입력 → 출력)로 V_id* = −ΔV_out / A_dc". **한 DEC 안에 입력 환산 전달이 두 이름으로 있다**(σ = '차동 이득', 계통 = 여기 방향 A_dc).
- **계획 407행 정의 일반형**: 스윙·ICMR·슬루는 여기 방향 일반형, "이름·포트 개수로 추측하지 않음". offset 계열은 이 문장에 없고 G1이 계통 offset만 넓혔다.
- design §21.5 1단계는 이미 `.tf` 구동을 `e = dc_sweep.excite` 방향으로 걸어(일반형) 차동 (½, −½)에서 옛 값과 비트 동일이다. 단일 입력에서 막는 것은 옛 코드의 V_id 정의(`O/oracle_offset_mc.py:117-119` '차동 쌍 없으면 unavailable')뿐이다.

### 2.2 물리(P-1): 일반형이 G1과 같은 물리에서 나오는가
그렇다. 두 양 모두 '출력 편차를 여기 방향 입력 좌표로 옮긴 값'이고 옮기는 계수는 같은 봉인점 DC 방정식의 여기 방향 DC 극한 전달(1차 감도) 하나다. 계통 offset은 큰 쪽 정확값(출력 고정 `.dc`), σ는 작은 불일치의 1차 환산(`.op` MC + `.tf`)이라 계산 방식만 다르고(O-43 D1 (a) '1차' 표기) 전달량의 정의는 같다. 차동 입력 쌍은 여기 방향 = (½, −½)인 특수형이다. 단일 입력 회로(follower, common gate)도 소자 불일치로 출력이 움직이고 그 입력 환산이 물리적으로 정의된다(전달 A가 정의되는 한). **단일 입력을 막을 물리 근거는 찾지 못했다** -- 제한은 옛 코드의 구현 한계다.

## 3. B-45 -- ICMR 구성 벤치에서 공칭 점 차 거부를 '기록만'으로

### 3.1 원문 확인
- 공칭 점 차 거부(`sweep_end_unresolved`, `why = nominal_shift`)는 **계획에 없다**(oracle·gain-budget 계획 `nominal_shift`·'공칭 점 차' grep 0건). design v0.3.0 검증 지적 6이 만든 design 층 규칙이다. 따라서 B-45는 계획 게이트를 약화하는 것이 아니다.
- 그 규칙의 전제(design §21.2): "개루프 벤치가 servo 해와 같은 동작점에 있다고 볼 수 없으면 거부" -- 입력을 servo 해 인쇄 값으로 구동하는 **개루프** 벤치가 같은 동작점을 재현하는지 보는 검사다.
- ICMR 정의(gain-budget 564행): "차동 입력 0(또는 동작점 차)으로 두고 입력 공통모드를 DC로 훑을 때 **출력은 회로가 정하는 대로** 따르는 상태"; G4(O-50): 구성 = 선언 되먹임, 없으면 단위 이득 follower; 엔진도 같은 구성(564행 "follower 행 V_out = x를 더한 선형 감도 끝"). 즉 **ICMR의 공칭 점은 정의상 그 되먹임 구성의 y = 0 해**이고 servo 해와 다른 회로다(예: 출력 DC 0.9 V로 설계된 OTA의 follower 출력은 입력 CM 근처로 감).

### 3.2 판정
- 그 거부를 ICMR에 적용하면 거의 모든 정상 회로가 거부된다(전제가 성립하지 않는 비교). 빼는 것은 **약화가 아니라 범주 정정**이다.
- 되먹임 구성 공칭 점에 **필요한** fail-closed 검사는 이미 있다(design §21.2): 수렴 실패, 공칭 점 선언 소자 불일치 → `intended_region_mismatch`(판정 불능), 선언 없는 소자 공칭 꺼짐 → 정의 불능, 반전 포트 판정 불능 → `inverting_port_undetermined`, 차동 출력 미선언 → `feedback_config_undeclared`.
- 누락 후보 검사 '공칭 y = 0에서 여기 방향 입력 차가 동작점 차와 r 이내'는 **기각**: 유한 루프 이득에서 V_id는 ΔV_out/A만큼 정당하게 움직여 r(해 정확도)을 넘을 수 있다 -- r을 그 문턱으로 쓰는 것은 근거 없는 새 규칙이다.
- 그러나 **'기록만'도 맞지 않다**: ICMR에서 `nominal_output_shift_V`는 서로 다른 두 회로의 출력 차라 정의된 뜻이 없고 소비자도 없다(만들면 배선·출력 전용 선언 원칙 위반, 검증자 오독 위험). 공칭 점 op 값은 이미 `conduction.points[]`(sweep, y = 0)에 있다.

### 3.3 권고
- B-45의 '거부는 swing에만'은 유지(모든 원칙과 일치).
- ICMR에서는 `nominal_output_shift_V`를 **만들지 않는다**(기록만 → 칸 없음). design §21.2 '공칭 점 차 확인' 문장을 "ICMR 구성 벤치(O-50 G4)에는 이 확인과 `nominal_output_shift_V`가 없다 -- 그 y = 0 해가 정의상 ICMR 공칭 점이고, 공칭 점 검사는 위 수렴·`intended_region_mismatch`·공칭 꺼짐 정의 불능이 맡는다"로 바꾼다.
- 계획 변경 없음(design 층 규칙). **원래 취지와 다름 아님**: 작성자가 표시한 '원래 취지와 다를 수 있음'은 계획 취지가 아니라 v0.3.0 design 규칙 기준이고, 계획에는 그 게이트가 없다.
- 확인하지 못한 연관 항목(기록): `icm_margin_v`의 기준 CM(servo 해 입력 CM인지, 되먹임 구성 y = 0 좌표인지)은 gain-budget 정의를 이번에 끝까지 대조하지 못했다. 두 점이 다르므로 design §21.2가 그 기준을 정본 문장에서 인용하는지 다음 검증에서 확인할 것.
