### Ⅳ-6 추가 발견

- **⚠ 경계 사례**: 감사 §3.1 #5의 정정 문언 '대신호 범위 끝·**측정 구성 양**을 정확히 내려는 엔진 순풀이 금지'를 그대로 쓰면 Q-W1 (i)이 걸릴 수 있다. (i)은 실현 점에서 DEC-23 V_id* 측정 구성(servo, 출력 고정·입력 차 미지수)을 비선형으로 푼다(GB 1161). 그 결과가 계통 offset 성분 (3)을 대신하므로, 문언상 '측정 구성 양(계통 offset)을 정확히 내는 순풀이'와 구별되지 않는다. 문언에 '봉인 정의(N3.6·DEC-23 측정 구성) 그대로를 실현 입력 버전(W′)에 적용하는 평가는 허용(새 풀이 정의 아님)'을 명시해야 한다. 그러지 않으면 정정 뒤에도 Q-W1 (i)과 DE-1 완료 1이 다시 충돌한다.
- offset-trim 완료 9도 같은 거짓 red 위험이 있다. 감사 R-17의 대상 목록('DE-1 완료 1·offset-trim 완료 9')과 같다.

### Ⅴ-6 추가 판정 -- (c) e_m 가드

1. **새 집계 규칙인가: 아니오.** e_m은 (회로, metric)마다 선언값 하나를 읽는다(DEC-72 '회로를 묶는 집계 안 만듦', GB 1998·N6.19). 회로 묶음 집계는 없다. 개념은 이미 계획에 있다: U-46(GB 2449) '그만큼 제약을 조여'(닫힘, 뜻 미결), E-2 guard band(GB 1315), DEC-72 소비자 'NFR-5 **여유 바닥**'(GB 271). 그래서 (c)는 새 규칙이 아니라 미결 뜻을 정하는 것이다(감사 B-A17 수정과 일치).
2. **기준 약화인가: DEC-98 쪽은 아니오, NFR-5 쪽은 문언 정합이 필요하다(⚠ 원칙 18 판정 대상).**
   - DEC-98: 엔진 쪽 조건을 c ≥ 0에서 여유 ≥ e_m으로 조인다(강화). (나) 'front 점 모두 oracle 통과'는 그대로 둔다 → 약화 아님.
   - **NFR-5와 같이 쓰면 띠 폭이 0이 된다**: 가드 = 여유 ≥ e_m, NFR-5 = 활성 여유 ≤ max(분해능, e_m) → e_m ≥ 분해능이면 활성 여유는 정확히 e_m 한 점이어야 한다. 격자 분해능으로는 그 점에 놓일 보장이 없다. 그러면 NFR-5가 실제로는 성립하지 않는다. 정합안: NFR-5 상한을 'e_m + 분해능'(가드만큼 띠를 민 꼴)으로 고친다 → NFR-5 과설계 상한이 min(분해능, e_m)만큼 넓어진다 = **NFR-5 기준 변경, 사용자 판정 대상**. 대안: 가드를 'e_m − 분해능'으로 둔다 → E-1 (a) 영역 밖 점이 생긴다(⚠ 원칙 2).
   - 단위: design 41:1441의 `ConstraintRow.c`는 분해능 단위다. 엔진 밖 사실(재작성 범위 확인용 인용): as-built `E/search/ss_constraints.py:62-87`은 c = 여유 / max(resolution, e_m), 활성 = c ≤ 1이다. 그래서 '가드 c ≥ e_m'이라는 표기는 단위가 맞지 않는다. 'c ≥ 1(여유 ≥ max(분해능, e_m))'과 '활성 c ≤ 1'이 한 점에서 만나는 것이 위 띠 폭 0과 같은 현상이다. 계획 문언은 '여유(원 단위) ≥ e_m'으로 적고, design이 c 정규화를 다시 정해야 한다.
   - 경계 등호: E-1 (a)는 \|s\| **>** e_m이다. 가드를 '≥ e_m'으로 두면 s = e_m인 점은 (b) 영역(oracle 판정)으로 남는다. 가드를 '> e_m'으로 하거나 E-1 (a)를 ≥로 맞춰야 한다.
3. **`model_error` 정의·writer(계획 문언 기준)**: 정의 = 7a SPICE 대조에서 (회로, metric)별 `abs(모델 − SPICE)`. 저장 = spec `sizing_spec.json` `derived.model_error_<metric>`(값·단위·`verified_by` oracle 기록 id). 참조 = `value_from_model_error`만(GB 271·2594). 값 생산자 = card ME-1 판정 기록(검증자), spec으로 옮기는 데이터 커밋 = 오케스트레이터(GB 2017~ N6.19, PW-1b 꼴). 엔진 안 graph 필드 = S0 `graph/kernel: model_error`(design 40:426·458, writer = S0 블록, 값 출처 spec). 무효 조건 = `metric_code_hash`·`adapter_fp`·`descriptor_fp` 변경. 값은 점이 바뀌어도 재사용한다(N6.19 재사용 범위).
4. **ME-1 card 상태**: 계획 card 절만 있다(GB N6.19 2017~, N6.1 행 GB 1230). spec card는 없다(`docs/02-design/specs/`에 ME-1 card 0. `20261021-it2-common.md:224`는 '덮지 않는 범위'로 이름만). 선행 = OP-3·OP-5·OP-11·EO-1·PW-1a·VB-1 + metric 코드를 바꾸는 DE-1·NL-1·UB-1·IT-2 → **미착수, 착수 불가 상태**. 그래서 (c)의 효과(과설계량)는 측정할 수 없다. ME-1 전에는 모든 가드 대상 제약이 보류 → A' (나) 판정은 ME-1 뒤에 다시 실행해야 한다(ME-1의 측정점 = DEC-98 시작점·front 점이라 순서는 '가드 없이 실행 → ME-1 → 가드 실행 → oracle (나)'. 순환은 아니다 -- N6.19 재사용 규칙).
5. **⚠ SB-1 (4) 'R10 행 여유 > e_m일 때만 결함'은 e_m의 대상 metric이 정의돼 있지 않다**: R10은 블록 전류 하한(Σ I_cell(R9) − min I_load ≥ C_lower·SR, '판정 아님', GB 264·269)이다. 비교하는 oracle 양은 슬루 `.tran`인데, 슬루는 엔진 모델 오차 대상이 아니다(GB N6.19 'OP-10(슬루)은 O-122로 대상 아님', VB-1 'model_error_ref 없음' GB 2011). R9 방향 전류는 'oracle `.dc`가 잰다'(GB 264)고 돼 있지만 ME-1 대상 목록에 없다. 그대로 두면 SB-1 (4)는 영구 보류가 된다. 수정안 후보: (i) ME-1 대상에 R9 방향 전류(oracle `.dc`)를 넣는다 -- 다만 R10의 가정 오차(창·C_lower·포락)는 전류 e_m으로 덮이지 않는다 (ii) R10 가정 오차를 따로 정의한다. **불확실 -- 권고 전에 물리 결정자 실측이 필요하다**.
6. 9회로 front 활성 제약 여유 분포 대 분해능: **측정 필요**(지시대로 재지 않음).

**(나) 평가 분리의 graph 규칙 정합**

- 규칙 1(같은 입력 → 필드 하나): θ 전용 값(크기·봉인·metric·목적)은 θ마다 한 번 계산하고 한 자리에 둔다 → 정합. 변형별 판정 행은 입력(변형 제약 집합)이 다르므로 다른 입력 → 다른 값이고, 둘째 생산자가 아니다.
- 규칙 2(재사용 두 길): 판정 행은 `graph/metrics: constraint_rows` 블록의 graph 필드로 두고, 재사용은 S3 graft (블록, 분할, 입력 버전 = 변형 제약 집합 지문 포함)로 한다 → 정합. **조건**: 판정 행을 `EvalResult` 값 칸(as-built `rows`)에 두면 '결과 객체 값 칸' 금지에 걸린다. (나)는 design 40:471의 이월(제약 행 → graph 필드)과 같이 가야 한다.
- 규칙 3·4: 같은 정의의 metric 값은 하나다. 변형 단계는 그 값을 참조로 읽는다 → 정합.
- **조건 (요청 합집합)**: 계획 문언 '계획 안 모든 변형의 metric 요청 합집합'을 metric 블록 입력에 넣으면, 실행 중 변형 추가(OS-L, N3.12·XS-16)가 합집합을 바꿀 때 입력 버전이 바뀐다. 그러면 이미 평가한 θ도 다시 계산된다. OS-L 추가 변형은 '같은 topology + 문턱만'(계획 386)이라 요청 집합이 같으므로 지금 범위에서는 성립한다. 다만 design은 둘 중 하나를 적어야 한다: (i) '추가 변형이 새 metric 요청을 가져오면 fail-closed', 또는 (ii) metric 블록을 요청별 분할로 graft해 합집합 자체를 두지 않는 꼴. (ii)는 요청이 없는 θ에서 남의 metric을 계산하지 않아 원칙 1에도 낫다.

**(다)의 같은 θ 재계산 수 추정(코드 읽기, 재작성 범위 파악용)**

- 엔진 밖 사실: as-built `E/search/kernel.py:94-172` `evaluate`. 키 = `eval_key(context_fp, schema_fp, θ, cells, w_fixed_fp)`(`E/search/eval_key.py`). (다)는 여기에 `constraint_set_fp`를 더한다(design §10.3).
- 같은 θ를 문턱 값이 다른 변형 v(θ)개가 밟을 때, (다)의 추가 커널 평가 수는 R = Σ_θ (v(θ) − 1)이다. 상한은 Σ_v E_total,v − (서로 다른 θ 수)이고, 변형별 예산은 XS-12에서 온다. compare 국면 1은 V = 2(matching + trim 국면 1)라서 R ≤ min(E_total) 수준이다. OS-L은 V = 1 + 반복 수(상한 offset-trim D-19)이고, 계획 347 '같은 θ를 다시 밟을 가능성이 크다'에 따라 R ≈ (반복 수) × (반복당 재방문 θ 수)까지 갈 수 있다.
- 추가 평가 1회마다 다시 도는 것(as-built 재작성 범위 목록):
  - 블록 graft 적중(계획 177): 크기·봉인(`size_and_seal`), 요청이 같은 metric 블록
  - **변형과 무관한데 다시 계산되는 비블록 계산**: `cone_rows`, `seal_status`, `objective_values`, 봉인 제약 행 `constraint_rows(snapshot, lut, w_min, grid)`, `ls_constraint_rows`, 봉인 아닌 점의 `passive_values`·`metrics_dc`(kernel.py:107·132·147~157)
  - 결과 객체 사본: θ 전용 값(스냅샷 참조·objectives·봉인 행)을 담은 `EvalResult`가 변형 수만큼 생긴다
  - 변형별로 달라야 맞는 것: `_spec_rows`·`ss_constraint_rows`(판정 행)뿐이다
- 그래서 (다)는 규칙 1(θ 전용 값의 반복 계산)과 규칙 2·4(EvalResult 값 사본)를 어기면서 키만 달라 G-10 `recompute_same_key`(kernel.py:113)에 잡히지 않는다. 감사 R-44 '형식 우회' 판정을 코드 읽기로 확인했다.
- G-10 계측으로 실제 R을 잴 수 있다: 같은 (context_fp, schema_fp, cells, θ) 다른 `constraint_set_fp` 쌍의 수(XS-13 S3 줄 변형 칸). **측정 필요**(엔진 실행은 하지 않음).

### Ⅵ 권고 판정

**유지(조건 2개 추가)**: (나)로 다시 묻는 권고를 유지한다. 조건: (1) 판정 행을 graph 필드 `constraint_rows`로 옮기고 `EvalResult` 판정 칸은 같은 변경에서 지운다(design 40:471 이월과 묶음) (2) 요청 합집합 대신 요청별 분할 graft를 쓰거나, 추가 변형이 새 요청을 가져오면 fail-closed. offset-strategy design 875의 graph 점검 칸 '준수'를 '위반'으로 고친다.
