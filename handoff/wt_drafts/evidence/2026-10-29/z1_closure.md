- 닫기 갱신식은 세 가지를 쟀다.
  - zero = Z1 문언 그대로(Δ ← Δ − s°)
  - mid = 목표를 띠 가운데로(Δ ← Δ − (s° − 분해능/2))
  - secant = 같은 점의 oracle 기록 두 개로 할선 갱신
- 분해능은 metric의 상대 1 %와 0.5 % 두 값을 썼다. **실험 매개변수이고 엔진 분해능이 아니다.**

## 1. 닫기 반복 수 (oracle 실행 수 = 첫 검증 1회 포함)

손계산 오차 d = (손계산 − oracle)/oracle는 동작점에 따라 크게 바뀐다. 원천은 LUT에 정전용량이 없어서 생기는 기생 C 자기부하다(손계산 꼴 근사 (ii)).

> **[정정 2026-10-29, §9]** 'LUT에 정전용량이 없다'는 틀렸다. 이 toy가 쓴 W = 1 µm DC 슬라이스(`sky130_fd_pr__*_dc.npz`)에는 C 열이 없다. 그러나 LUT v2 r2(`lut_data/sky130_lut_v2/sky130_nfet_pfet_lut_v2_r2.npz`, W_ref 5 µm)에는 CGG·CGD·CGS·CGB·CDD·CSS 열이 있다. 그래서 §1~§3의 오차 1~42 %는 'C 열을 쓰지 않은 손계산 꼴'의 오차이지, LUT의 한계가 아니다. C 열을 쓴 재측정은 §9에 있다.

| 케이스(분해능 1 %) | 첫 풀이 oracle 여유 | 수렴 인자 κ = d′/m′(곡선 실측) | zero | mid | secant |
|---|---|---|---|---|---|
| GBW, CL 1 pF, gm/ID 10·14·20 | −2.6·−1.3·−4.8 % | 0.02~0.30 | 5·4·6 | 2·2·2 | 2·2·2 |
| GBW, CL 100 fF, 10·14·20 | −14.8·−14.3·−25.6 % | (중간) | 12·>12·>12 | 5·5·9 | 3·3·4 |
| GBW, CL 30 fF, 10·14·20 | −28.2·−28.2·−42.1 % | 0.55~0.96(g10), 0.85~1.0(g20) | >12 ×3 | 10·10·>12 | 4·4·5 |
| A0, L 0.15·0.5·1 µm | +0.44·+0.97·+1.24 % | \|κ\| ≤ 0.22, 부호 바뀜 | 1·1·2 | 1·1·2 | 1·1·2 |

분해능 0.5 %에서도 secant는 2~6회 안에 닫혔다. 전체 집계(36 케이스 × 갱신식 3): secant 24/24, mid 22/24, zero 14/24.

- **진동은 없었다.** A0에서 κ의 부호가 바뀌었지만 \|κ\|가 작았다. GBW는 κ > 0이라 실패 쪽에서 한쪽 방향으로 다가간다.
- **발산은 있었다.** spec이 oracle 자기부하 점근선(gm/ID 20, CL 30 fF에서 약 970 MHz) 위이면 도달할 수 없다. 이때 secant는 I를 18.8 µA에서 4.36 A까지 키웠고, s°는 −2.35 %로 점근했다. mid는 12회 동안 계속 −23 %대였다. 손계산은 이 spec을 도달 가능하다고 본다.
- Z1 문언의 갱신식(zero)은 1차 수렴이고 수렴 속도는 κ가 정한다. 실패 쪽에서 0으로 점근하므로 [0, 분해능] 안에 잘 들어가지 않는다. κ가 0.05일 때도 4~6회가 걸렸다.

## 2. 비용

- **oracle `.op` + `.ac` 1회**: 0.20 s(중앙값), p95 0.24 s, 381회 실측. 대부분 프로세스 기동 비용이다. 손계산 재풀이는 ms 수준이다.
- **실행당 추가 시간 추정**: N_front × (k − 1) × t_oracle.
  - front 점 수: 계획에 고정값이 없다. 상한 = gain bin × 면적 bin(GB 651), 시간 예산 = 300 s × front 점 수 상한(U-47, GB 2450).
  - 예: N_front = 10, k − 1 = 1~5(secant), t = 0.2~1 s이면 회로당 2~50 s다. 점당 300 s 예산의 1~17 %다. **library 회로 t_oracle은 재지 않았다(추정).**
- **MC metric(σ_in)**: 표본 하나 = 파라미터 바꾸기 + reset 재구성 + `.op`.
  - toy 실측: 1표본 0.27 s, 50표본 3.6 s, 200표본 17.2 s. 표본당 약 0.085 s다. 재구성 없이 `.op`만 돌리면 200표본에 0.31 s다.
  - MC를 한 번 더 돌리는 비용: N = 200, toy 기준 약 17 s. 점당 추가 반복 1~4회면 17~68 s다(추정).
  - 소자 수가 늘면 재구성 비용도 같이 는다.
  - 닫기 분해능은 MC 표준오차보다 작아질 수 없다(T-39의 분해능 정의와 같은 한계). **σ_in 닫기의 반복 수는 재지 않았다(추정).**

e_m은 DEC-72 꼴로 정했다. (회로 = 같은 CL, front 점 = gm/ID 10·14·20의 첫 풀이 점)마다 \|손계산 − oracle\| 최대값이다. 가드 = 손계산 목표 spec + e_m.

- **가드 불합격 5/9(GBW)**
  - 원인: 가드를 걸면 점이 움직인다. 그러면 d도 커진다(κ > 0). 측정점에서 잰 최대값이 옮겨 간 점을 덮지 못한다. 표본 밖 외삽의 실례다(`em_reanalysis.md` §1.3).

  - A0는 손계산이 비관적이다(oracle이 더 높다). 그런데도 abs 가드는 같은 쪽으로 여유를 더 준다.
- Z1은 12/12점을 닫았다. oracle 여유는 0.02~0.97 %, 추가 oracle 실행은 점당 0~4회다.

## 4. Δ의 graph 자리

| 확인 | 결과(경로) |
|---|---|
| GB 계획 'T-30' grep | 0건. 'Δ_T'는 LR6 1건뿐이다(GB 718 '그 루프가 조인 문턱 항목 `offset_in_max_v` − Δ_T를 읽는다 -- 문턱 사본 없음') |
| T-30 Δ_T 정본 | `wt/plan-v6385/docs/01-plan/features/offset-trim.plan.md`(N3.8.3·N3.8.7·NFR-T3·NFR-T8) |

offset-trim 계획이 정한 Δ_T의 성질:
- Δ_T는 **metric별** 측정 기록이다(값·단위·출처 지문).
- 정의: oracle(범위 최악) − oracle(T_j). 엔진 값은 들어가지 않는다.
- 갱신: 반복마다 **교체**한다(누적하지 않음, O-6).
- writer: 엔진 밖 구동기 하나다. 다음 **변형**(실행 계획 안, D-24 안 B)의 제약 입력 하나로 들어간다.
- 문턱 합성은 제약 행 한 곳에서만 한다. 엔진은 oracle 파일을 읽지 않는다(X-23).
- 구동기는 이전 front 점을 시작점으로 주지 않는다(N3.8.7, U-89).

Z1 Δ와 맞춰 본 결과:
1. **S-3·U-89 경계는 정합한다.** Z1 갱신에 쓰는 s°는 oracle 값 − spec이다. 엔진 계산 결과가 아니다. Δ는 실행 입력이다. 실행 사이 cache가 아니다.
2. **자리 통일은 안 된다(실측).** Δ_T 자리는 metric마다 실행 변형 하나다. Z1 Δ는 **(점, metric)마다** 있어야 한다.
   - `shared_delta.jsonl`: 가장 어려운 점(g20)을 닫은 Δ를 같은 회로의 다른 front 점에 같이 줬다.
   - 결과: 다른 점의 oracle 여유가 +2.4·+3.8 %(CL 1 pF), +21 %(100 fF), +42 %(30 fF)가 됐다.
   - 전류 과설계는 +2~3 %, +28~29 %, **+95~96 %**였다.
   - metric별 Δ 하나는 e_m 가드와 같은 결함(점마다 다른 오차를 값 하나로 덮음)을 되살린다.
3. **정의도 다르다.** Δ_T는 oracle − oracle이고 교체한다. Z1 Δ는 누적하거나(Δ − s°), 엔진 값이 든 d(x_k)로 교체한다. 그래서 같은 필드로 둘 수 없다(graph 규칙 3: 축이 다름 = 모형 오차 대 온도).
   - 두 루프가 함께 돌 때 문턱 = spec − Δ_T + Δ_Z1이 된다. 합성 순서와 자리는 계획에 없다.
4. **'그 점의 최적화를 다시 푼다'와 N3.8.7이 충돌한다.** N3.8.7은 '이전 반복 front 점을 시작점으로 주지 않음'이다.
   - 점별 재풀이를 실행 사이에 하면 충돌한다.
   - 한 실행 계획 안에서 하면 충돌하지 않는다(S3 graft 범위). 다만 그 안에서 엔진이 oracle 결과를 받는 경로가 없다(X-23).
   - 점별 Δ의 정본 자리 후보: Q-W1 실현 평가(front 점마다 재풀이, GB 1161)의 입력, 또는 점 id가 붙은 변형. 둘 다 계획에 없다 → **graph 규칙 6: 멈추고 계획부터 고친다.** `em_reanalysis.md` Q2의 'T-30 Δ_T 자리 통일' 권고는 실측상 성립하지 않는다.

## 5. 추가 발견

- **Z1 멈춤 규칙 결함 두 가지**(실측). Z1 문언은 'Δ 변화 ≤ 분해능 또는 같은 Δ 재방문이면 정지'다.
  - (가) 잘못 멈춘다. zero 갱신에서 s° = −0.12 %(CL 1 pF g10, 2회째)이면 Δ 변화 0.12 % ≤ 분해능이라 '비수렴'으로 정지한다. 실제로는 한두 걸음이면 닫힌다.
  - (나) 멈추지 못한다. 도달 불가 spec에서는 Δ가 계속 크게 바뀌므로 규칙이 걸리지 않는다. I가 4.36 A까지 갔다.
  - 수정 후보(새 상수 없음): 목표 = 분해능/2, 갱신 = 같은 점 oracle 기록 두 개로 secant. 정지 = (i) s° < 0인데 \|s°_k − s°_{k−1}\| ≤ 분해능(oracle 진전 없음 → '도달 불가', front에서 뺌) (ii) 갱신 점의 E-0 실현 가능 위반 (iii) 사용자 선언 반복 상한(T-30 꼴, 기본값 없음).
- **닫기는 정의 결함도 흡수한다.** 처음 짠 toy 손계산은 출력 DC를 VDD − VSG3로 뒀다. oracle 측정 구성(servo)에서는 출력 DC가 VCM이다.
  - 이 정의 차이로 A0 오차가 −7 %였다. 고친 뒤에는 −0.3 %였다.
  - 닫기는 이런 차이도 Δ로 조용히 메운다. 그래서 정의 동일성 관문을 닫기 앞에 반드시 둬야 한다(Z1 조건 (3)을 σ_in만이 아니라 모든 대응 행으로 넓힘).
  - \|Δ\|가 클 때 E-2·정의 감사로 넘기는 장치가 필요하다. Z1의 E-2 착수 조건(비수렴·순위 변화)은 이것을 잡지 못한다.
- **활성 제약끼리 맞물린다.** GBW 닫기로 I가 커지면 PM이 떨어졌다(CL 30 fF g20: 55° → 51°).
  - 닫기는 활성 제약 전체를 함께 다뤄야 한다(벡터 닫기). **재지 않았다.**

## 6. 판정

**Z1 = 조건부(방향은 맞다. §2 문언 그대로는 틀린 부분이 있다).**

맞는 근거:
- 손계산 오차는 같은 회로 안에서도 동작점에 따라 1~42 % 바뀐다.
- e_m 가드는 9점 중 5점을 oracle에서 떨어뜨렸다. 합격한 점은 분해능의 2~3배를 과설계했다.
- Z1 닫기(secant)는 모든 도달 가능 점을 1~6회 oracle 안에 [0, 분해능]으로 닫았다.
- 비용은 점당 oracle 0~5회 추가다(toy 0.2 s/회). 300 s/점 예산 안이다.

조건(같은 변경에 넣을 것):
1. 갱신식을 목표 분해능/2 + secant로 바꾼다. 문언의 Δ ← Δ − s°는 κ가 0.5를 넘으면 12회 안에 닫히지 않았다.
2. 멈춤 규칙을 oracle 진전 기준으로 바꾸고, E-0 실현 가능 검사와 사용자 선언 상한을 둔다(§5).
3. **Δ를 (점, metric)별로 두고, 정본 자리는 계획을 개정해 새로 정한다.** T-30 Δ_T 자리 통일안(Q2)은 기각한다(§4 실측). 자리가 정해지기 전에는 만들지 않는다(graph 규칙 6).
4. 모든 대응 행에 정의 동일성 관문을 닫기보다 먼저 둔다. 큰 \|Δ\|는 E-2·정의 감사로 넘긴다.
5. 남은 측정: 활성 제약 여러 개를 함께 닫기, library 회로의 t_oracle, σ_in(MC) 닫기 반복 수.

- 결과 파일: `multi.jsonl`, `miller_pm_curve.jsonl`, `stall_rule_check.jsonl`(모두 케이스마다 append)
- ⚠ `multi.jsonl` 안 `_c2` 기록은 무효다. Edit가 실패해서 수정 전 코드로 돈 기록이다. 지우지 않고 사후 대조에서 뺐다.
- Δ는 (점, metric)마다 둔 상대 문턱 이동이다. 목표는 분해능/2, 분해능은 1 %다(실험 매개변수).
- 닫기 방식 셋:
  - (a) metric마다 독립 secant를 같은 걸음에 함께 갱신한다.
  - (b) Δ 벡터를 Broyden으로 갱신한다. J₀ = I다. '손계산 metric = 목표'라는 정의에서 나오는 값이고 추가 실행이 없다.
  - (c) 한 번에 하나씩 순차로 갱신한다(secant).
- 멈춤 규칙(새 상수 없음):
  - 모두 [0, 분해능] 안 → 닫힘
  - 손계산 풀이 불가 → e0
  - 진전 없음: '옮긴' 실패 metric 모두 |Δs°| ≤ 분해능 → stall
  - 반복 상한 15 → 실험 매개변수

### 8.1 다제약 닫기 결과 (oracle 실행 수)

  - 부호가 계속 뒤바뀌는 진동은 없었다.
  - (a)는 B에서 한 번 넘어간 뒤(GBW −0.5 → +3.9 %) 위쪽에서 띠로 들어왔다.
  - (b)는 한 번 넘어간 뒤(+1.6/−0.3 %) 4회에 닫혔다.

    - 닫힌 이력에서 거짓 정지 6건. 모두 mid(1차 갱신)였다.

  - R4(진전 ≤ 분해능 이면서 Δ 이동 > 분해능)는 이 자료에서 R1과 똑같이 걸렸다.

### 8.3 판정

**Z1 + 조건은 다제약에서도 조건부로 성립한다.** 조건 두 개를 더한다.

1. 다제약 갱신은 (a) metric별 독립 secant 동시 갱신을 기본안으로 한다.
   - toy A 12/12, B(도달 경우) 1/1 닫힘, 거짓 정지 0이었다.
   - (b) Broyden은 B에서 실행 수가 더 적었다(4 대 6). 대신 거짓 stall이 1건 있었다. 대안으로 둔다.
   - (c) 순차는 맞물림 때문에 기각한다.
   - 실측 범위는 toy 2종, 다제약 9점뿐이다. library 회로는 측정이 필요하다.
2. 멈춤 규칙의 진전 판정 대상은 '직전 걸음에서 옮긴 실패 metric'으로 한다. R2는 기각한다.

**큰 |Δ|를 E-2로 넘기는 기준은 새 상수 없이 정의할 수 있다.** 'Δ가 분해능의 몇 배' 같은 배수는 필요 없다.

- (i) **손계산 꼴 천장 e0**: 닫기 목표를 손계산 꼴이 표현하지 못해 풀이가 실패한 경우다.
  - 예: PM 목표 ≥ 90°, 자기부하 점근선 위의 손계산 목표.
  - oracle 곡선에서 도달할 수 있는지 확인되지 않았으면 '도달 불가'가 아니라 E-2로 넘긴다(B CL 200 fF 실례).
- (ii) **닫기 비용 > 목적 축 bin**: 닫힌 점과 첫 풀이 점의 목적값(전력·면적) 차가 그 축의 bin(DEC-80·b_P, 기존 선언)을 넘는 경우다.
  - 이것은 O-173 E-2 'guard band 비용 > 분해능'에서 guard band를 닫기 Δ로 바꾼 꼴이다.
  - 실측: 기본 꼴은 +1.7~+118 %, 정밀화 뒤는 0~+17 %였다. bin 값은 선언에 달려 있다.
- (iii) **stall·상한 도달**: oracle이 둔감하거나 반복 상한에 닿은 경우다. 도달 불가와 손계산 꼴 결함을 가르는 E-2 진단 대상이다.
- (iv) **정의 감사는 기준이 아니라 관문이다.** 닫기보다 먼저 둔다(§5).
- E-2 완료 조건은 전·후 실측으로 잰다. 재는 양은 첫 풀이 여유, 닫힌 |Δ|, 닫기 실행 수, 닫기 비용이다. §8.2 표가 그 실례다.

**원래 취지와 다름**:
- 멈춤 규칙 문언에 '옮긴 metric' 한정을 더했다.
- E-2 착수 조건을 바꿨다. 손계산 꼴 천장 e0과 닫기 비용 > 목적 축 bin을 더했다. Z1 원문은 '비수렴·순위 변화'만 적었다.

  - C 꼴 불합격은 9점 중 1점이고, 그것도 −0.02 %로 경계값이다. 다제약 6점은 0/6, Miller는 1/3(PM −0.14 %)이다.
  - 5/9 불합격은 'C를 넣지 않은 손계산 꼴'(base)의 결과다. r2 형상으로 다시 재도 base에서는 5/9로 재현된다.
  - 그래서 §3의 '가드가 표본 밖 외삽 때문에 깨진다'는 근거는 **손계산 꼴이 거칠 때에만** 강하다. C 꼴에서는 d가 점마다 −2.7 ~ +2.3 %로 작다. 이때 가드의 주된 결함은 불합격이 아니라 과설계다.
- **과설계 결론은 성립한다.** C 꼴에서 가드 합격 점의 여유가 분해능 1 %를 넘은 것은 6/8(5T), 4/6(다제약), 2/2(Miller)다. 여유는 1.3~4.6 %이고 전력은 Z1보다 0.1~17 % 더 든다.
  - 원인: abs 가드는 방향을 보지 않는다. 손계산이 이미 비관적인 점(첫 풀이 oracle 여유가 + 쪽)에도 여유를 더 준다.
  - C 꼴에서 첫 풀이 오차의 부호는 점마다 다르다(−2.7 ~ +2.3 %).
- **Z1 닫기의 비용은 C 꼴에서 더 작아진다.** 5T는 1~2회, 다제약은 1~4회, Miller는 2회다. 닫힌 |Δ|는 3.2 % 이하다.
- **§5·§8 결론 가운데 C 유무와 무관한 것은 그대로다.** Δ는 (점, metric)별이어야 하고 T-30 자리 통일은 안 된다. 멈춤 규칙 수정과 '옮긴 metric' 한정도 그대로다.
  - 다만 shared Δ 과설계 크기(§4, +2~96 %)는 base 꼴에서 잰 값이다. C 꼴에서는 점 사이 d 차이가 작아서 훨씬 줄 것이다. **재지 않았다.**
- **판정 갱신: Z1 = 조건부(유지).** 근거의 무게중심이 바뀌었다.
  - 이전: '가드는 불합격과 외삽 실패'
  - 지금: '가드는 방향을 보지 않는 과설계(분해능의 1.3~4.6배)'이고, 'C 꼴에서도 점별 d의 부호가 섞여 값 하나가 맞지 않는다'.
  - 손계산에 C 열을 쓰는 것은 E-2가 아니라 **기본 손계산 꼴**로 두는 것이 맞다. LUT에 이미 있는 데이터이고, 원칙 1의 물리 정합에 해당한다.
  - E-2 기준 (i) 천장 e0은 C 꼴에서 '첫 풀이 도달 불가'로 바뀌어 나타났다. 기준 (ii)는 §9.1의 ⚠대로 해석에 주의해야 한다.

**원래 취지와 다름**:
- §3·§6의 '가드 5/9 불합격' 근거가 C 꼴에서 약해졌다.
- §8.2의 'C 정밀화 = E-2 실례'는 'C 열 사용 = 기본 꼴'로 바뀐다.
