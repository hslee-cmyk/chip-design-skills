## F. P10 (DV-16) -- 두 분석 비교와 권고

**일치하는 점**

- 정본은 엔진 2단계 판정 기록 하나다. writer는 OP-5 통합 병합 엔진 커밋의 2단계 호출 자리이고, 값은 공용 전도 판정 함수가 반환한 것이다.
- 오라클 쪽에는 값 사본도 재판정도 두지 않는다. `range_final`은 참조만 한다.
- (다)/(B)(값을 오라클에 싣기)와 (라)/(C)(오라클 재판정)는 두 분석 모두 기각한다.

**갈리는 점**

1. 결합 키
   - oracle 쪽 (가): 새 키 없이 지목 `{record_id, point_id}` 자체로 결합한다. 2단계 기록 참조를 더하는 안은 (나)로 기각했다.
   - gb 쪽 (A): 확정 범위 지목이 2단계 판정 기록의 `record_id`도 가리킨다. oracle 쪽이 기각한 (나)와 같은 안이다.
2. gb 쪽에 무엇을 둘지
   - oracle 쪽: gb에 칸 하나와 완료 조건을 둔다.
   - gb 쪽: graph 필드는 두지 않고(N3.3 (b) 출력 기록 부류) 정의 문장 하나만 둔다.
3. `reason` 곁 발견은 oracle 쪽 분석에만 있다.

**검증자 판단**

- oracle (가)의 "지목 = 결합 키"는 **정의 불능 끝에서 끊긴다.** 그 끝의 P는 `{undefined: true, reason}`이어서 `record_id`·`point_id`가 없고, `range_final.source.<end>` = `null`이다(design 1034·1056행). 그 상태에서 `reason`까지 지우면 검증자 변화표가 엔진 기록을 찾을 키가 없다.
- gb (A)는 키를 더해 이 문제를 풀지만, 오라클이 검사할 수 없는 참조를 닫힌 입력 키 집합에 넣게 된다.
- gb 쪽이 근거로 든 "N3.3 (b) 'S3 기록 = 출력 기록(엔진이 실행 사이에 읽지 않음)'"은 v6.22 grep('출력 기록'·'실행 사이에 읽지 않')으로 해당 문언을 찾지 못했다. 그래서 "graph 필드가 아니어도 된다"는 근거가 아직 확인되지 않았다. 확인되지 않으면 규칙 6(정본 자리가 없으면 멈추고 계획부터)에 해당한다.

**권고(분석만, 결정 아님)**

1. 정본 = 엔진 2단계 판정 기록이다(잠정 방향 유지). 끝마다 `{oracle_record_id, metric, end, 결과: point_id | 정의 불능 사유, departed: [{device, declared, actual}]}`를 담는다. 참조 방향은 **엔진 기록 → 오라클 기록**이다.
2. 오라클 입력 `confirmed_range`에서는 정의 불능 끝 P를 `{undefined: true, record_id}`로 바꾼다. `record_id`는 2단계가 판정한 원 범위·재훑기 기록이고, `reason`은 삭제한다. 그러면 모든 P가 `record_id`를 가지므로 G-19 검사 (1)(같은 입력 지문)를 정의 불능 끝에도 그대로 적용할 수 있다. 새 개념 키를 만들지 않고 기존 키만 쓴다. 검증자는 (record_id, metric, end)로 엔진 기록과 결합한다. `range_final.source.<end>`의 정의 불능 꼴도 `null` 대신 `{undefined: true, record_id}`로 맞추면 결합이 대칭이 된다(design 몫).
3. 필요한 gb 계획 문언(gb N6.20 EO-1 범위 (4) '옮긴 판정' 또는 OP-5 통합 병합 엔진 커밋 범위)
   - 필드: "2단계 판정 기록 = 엔진 결과 JSON 점 레코드의 범위 판정 부분(gb 1894행 범위 (2)의 판정 기록), 끝마다 위 1의 꼴. 이탈 소자 어휘 = N3.8 '소자 조건'(선언 없음 = 포화 / triode / off; 실제 = 포화·triode·꺼짐·전도)."
   - writer 하나: "writer = 2단계 호출 자리 하나. `departed`·사유는 공용 전도 판정 함수의 소자별 반환(소자, 선언 영역, 실제 판정)에서만 온다. 다른 자리(오라클 `range_final`, 검증자, 보고)는 읽기만."
   - graph 위치: graph 필드인지 출력 기록인지 **N3.3에 명시한다.** 출력 기록이라면 N3.3이 허용하는 graph 밖 출력 기록의 문언을 찾아 인용하고, 없으면 N3.3에 추가하는 계획 개정이 먼저다(규칙 6).
   - 완료 조건: (i) toy 회로 셋으로 정의 문장에서 기대값을 쓴 test. triode 선언 소자가 꺼지는 끝, off 선언 소자가 전도하는 끝, 정의 불능 끝(사유)을 하나씩 두고 `departed`·사유가 정확히 일치해야 한다. (ii) 소비자 ≥ 1 = 검증자 원인 변화표의 2단계 끝 원인 칸, 또는 graph-consumption 출력 전용 선언. (iii) `confirmed_range`·`range_final`에 `departed`/`reason` 값 칸이 grep 0건.
4. oracle 계획 쪽 문언(N3.9 '범위 판정' 끝 또는 G-18 '결과 칸')
   - "2단계 끝 이탈 소자 정보와 정의 불능 사유는 엔진 2단계 판정 기록(정의 = gain-budget)에만 있다. 확정 범위 지목의 모든 끝은 `record_id`를 가진다. 오라클 기록에는 두지 않는다."
   - design에서는 §11.6 P 꼴 변경과 `reason` 삭제를 처리하고, §11.7 `end_cause`에 2단계 갈래를 둘지 정한다.

## 결론

**조건부 승인 가능.** 차단 사항은 없고, must-fix 2건(경미한 문서 정리)만 반영하면 된다. P7·P8·X-R1·X-R2는 O-61 범위 그대로 반영되었고, graph 단일 정본 위반은 없다. P10은 결정하지 않는다는 O-61대로 열려 있다. 다만 다음 계획 개정 때 두 분석의 결합 키 차이와 N3.3 근거 확인을 반드시 먼저 풀어야 한다.
