## C. oracle V_id* 갈래를 design에 맡긴 것(434 '무엇으로 판정…은 design 몫', DR-20) -- PARTIAL, must-fix

**물리 확인**

- 정의(DEC-23)상 V_id*는 '출력을 기준에 고정하고 입력 이동량을 미지수로 푼 DC 해'다. 동작점 근처 1차식은 A_dc·V_id* + ΔV_out = 0이다.
  - A_dc = 0이면 ΔV_out ≠ 0일 때 해가 없고, ΔV_out = 0이면 해가 무수히 많다.
  - 0 < |A_dc| ≤ 판정 분해능이면 해는 있다. 하지만 출력 쪽 허용치 δV_out(SPICE에서는 수렴 허용치)가 δV_id ≈ δV_out/|A_dc|로 커진다. 그래서 해는 판정 분해능 안에서 정해지지 않는다.
  - 결론: 출력 고정 풀이의 해는 정해지지 않는다. DEC-23의 '수치적으로 정해지지 않은 값' 근거는 oracle `.dc` 풀이에도 그대로 맞다.
- oracle design §21.4 절차(servo 목표를 출력 기준으로 둔 `Op` 한 점, 수렴 실패 → `sim_convergence_failed`)는 이 상황을 알아채지 못한다. |A|가 작으면 결과는 둘 중 하나다.
  - (가) 수렴에 실패한다. 이때 사유가 '수렴 실패'로 기록되어 갈래 사유와 섞인다.
  - (나) 대신호 비선형으로 먼 입력 점에 수렴해 그럴듯한 숫자를 낸다. 거짓 값이다.
  - 따라서 oracle은 `.dc` 풀이 결과만 보고 갈래를 판정할 수 없다. 다른 측정량 A가 필요하다.

**계획에 맡긴 몫과 design에 맡긴 몫의 경계**

- '무엇으로 판정하는가(어떤 A, 어떤 분해능)'는 정의에 속한다. 엔진은 DEC-23에서 'A_dc를 내는 자리 하나 + N3.8 판정 분해능'으로 정했다. oracle이 다른 기준(예: 수렴 실패)을 고르면 같은 회로에서 엔진은 '정의 불능', oracle은 '값'이나 '수렴 실패'가 된다. 정의가 갈라진다.
- 이것은 oracle 계획 434가 스스로 적은 'DEC-23 그대로 인용' 원칙에도 어긋난다.
- design에 맡겨도 되는 것은 사유 이름, 기록 위치, 손 회로 test뿐이다.

**권고 계획 문안**(oracle N3.9 `offset_sys_mv` 행, 434의 'design 몫' 문장을 대체; 새 상수·새 저장 없음)

> A_dc 정의 불능 판정은 같은 설계점·같은 여기 방향 e의 **`.tf` 개루프 전달 A 한 측정**(아래 `offset_in_sigma_mv` 행의 A와 같은 측정 -- 한 번 재고 두 행이 읽는다, 둘째 측정 없음)으로 한다. 기준은 \|A\| ≤ 판정 분해능이다(정의 자리 = gain-budget N3.8 하나, 오라클 쪽 입력 = 시뮬레이터가 선언한 수렴 허용치 -- ICMR 행 '반전 입력 포트 식별'과 같은 규칙). 갈래가 발동하면 `.dc` 출력 고정 풀이의 해(수렴했더라도)를 값으로 내지 않고 정의 불능·사유를 기록한다. `.tf` 실패와 `.dc` 수렴 실패는 갈래 사유와 따로 기록한다(σ 행과 같은 원칙). 오라클은 ΔW를 모르므로(판정 W 설계점의 정확값만 잰다) DEC-23의 'ΔW = 0 → 0'은 엔진 1차 계산 규칙이고 오라클 판정 조건이 아니다 -- ΔW = 0이고 갈래가 발동한 점에서 엔진 0(통과)과 오라클 정의 불능의 대조는 [분류 자리: N4-2 '정의를 바꾼 칸'의 원인 기록 또는 DEC-72 모델 오차 대상 아님]으로 적는다. 사유 이름·기록 칸·손 회로 test만 design(DR-20)이 정한다.

- 대괄호 안의 '대조 분류'는 계획에 없는 새 판단이다. 오케스트레이터 기본안으로 정하거나 사용자에게 올린다. 이 검증자는 정하지 않는다.
- gb 쪽 대응: DEC-23의 'ΔW = 0 → 0' 문장에 '엔진 1차 계산(ΔV_out이 정확히 0)의 규칙이고 oracle `.dc` 정확값은 같은 갈래를 자기 `.tf` A로 판정한다(oracle N3.9 인용)' 한 구절을 넣는다. 그러면 정의 자리가 DEC-23 하나로 닫힌다.
- graph 점검: 권고안은 oracle 안에서 A를 한 번 재고 두 행이 읽게 한다(규칙 1). 반대로 V_id* 벤치에 A 측정을 따로 더하면 oracle 안에 둘째 생산자가 생긴다. DR-20의 '(σ 행 `.tf` A와의 관계 포함)'을 design 선택지로 열어 두면 그 위험이 남는다.

## E. ΔW = 0 → 0 순서 -- PASS(해석 보고 권고)

- 문서 안 정합:
  - 223에 '갈래는 ΔW ≠ 0인 V_id*와 σ에만 발동'이 있다.
  - '계산' 문장은 'ΔW = 0이면 0(통과), ΔW ≠ 0이고 A_dc 갈래면 정의 불능'이다.
  - 1577·1591도 같은 순서다. 네 자리가 같다.
- 물리:
  - ΔW = 0이면 엔진은 ΔV_out을 계산하지 않고 정확히 0으로 둔다. A_dc ≠ 0인 한 V_id* = 0은 1차식의 유일한 해다. 분모가 오차를 키운다는 갈래의 근거가 적용되지 않으므로 순서는 타당하다.
  - A_dc = 0이고 ΔW = 0이면 해는 정해지지 않는다(무수히 많음). 이때 '0(통과)'은 선택이다.
- σ: ΔW와 무관하므로 갈래는 언제나 적용된다. 정합한다. 같은 회로에서 σ는 정의 불능이 되어 커널 판정은 fail-closed이고, V_id*만 0(통과)이 된다. 둘이 모순되지는 않는다.
