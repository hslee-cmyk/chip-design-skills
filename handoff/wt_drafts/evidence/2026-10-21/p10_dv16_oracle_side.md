# P10 (oracle design v0.3.3 DV-16) -- 2단계 끝 이탈 소자 정보의 자리: oracle 쪽 분석 (읽기 전용, 결정 아님)

작성 2026-10-21, oracle-portability 계획 v0.6.12 작성자(`wt/oracle-v0612`, base master `512b3c48`). 사용자 결정 O-61 P10 = "계획 개정 때 분석해 따로 올림(잠정: 엔진 2단계 판정 기록, range_final은 참조)". 이 문서는 계획에 결정을 넣지 않는다(계획 v0.6.12 N7.4c OQ-9).

## 1. 질문

design v0.3.3(`design/oracle-eo1` `fd2848f1`) §19.2 DV-16(1582행): 엔진 쪽 2단계가 정한 끝(전도 쪽 이탈: 선언 없음·triode 소자가 꺼짐, off 선언 소자가 전도)의 **이탈 소자 정보**(어느 소자가 어느 선언 영역에서 벗어났는지)를 어디에 싣는가. 1단계 끝은 오라클 끝 기록 `departed: [{device, declared, actual}]`(design §11.7, 1056행)에 있지만, 2단계 판정은 오라클 기록에 없고 `confirmed_range` 지목(1034행)은 `{record_id, point_id}`만 담는다. 소비자 = 검증자 원인 변화표의 2단계 끝 원인 칸(계획 G-18 O-54 '검증자 원인 변화표가 읽음').

## 3. 선택지

| 안 | 내용 | graph 규칙 점검 | 판정 |
|---|---|---|---|
| (가) | 이탈 소자 정보 = **엔진 2단계 판정 기록의 칸**(writer = 2단계 호출 자리 하나, OP-5 통합 병합 엔진 커밋). 그 기록은 끝마다 자기가 낸 지목(`record_id` + `point_id`)과 이탈 소자 `[{device, declared, actual}]`를 함께 싣는다. `range_final`은 이미 같은 지목(`source`)을 참조하므로 **새 oracle 칸 없음** -- 검증자 원인 변화표는 `range_final.source` 지목 ↔ 엔진 기록의 지목으로 둘을 잇는다(참조 키 = 지목 자체) | 규칙 1 writer 하나(2단계 자리) ✓, 규칙 3 같은 정의 한 칸(1단계 `departed`와 축이 다름 -- 판정 단계(1단계 SPICE op만 / 2단계 LUT I_off·tol_V 포함); 칸 정의를 같은 꼴로 두되 writer가 다른 별개 칸) ✓, 규칙 4 참조 전달 ✓, oracle 쪽 새 저장 0 ✓ | **권고** |
| (나) | (가) + `confirmed_range` 끝 P에 엔진 기록 참조(`stage2_record_id` 등)를 더하고 `range_final.source`가 그것을 다시 싣는다 -- 잠정 방향 문언 'range_final은 참조'를 글자 그대로 | 참조 사본이라 값 사본은 아니지만, 오라클이 검사할 수 없는 칸(F7)을 닫힌 입력 키 집합(X-D7)에 더하고 출력에 되싣는다. (가)의 지목 키로 이미 이어지므로 둘째 참조 경로 = 불필요한 중복 | 기각(필요 없음, 기각 근거 = 같은 이음이 (가)에 이미 있음) |
| (다) | `confirmed_range`/`range_final`에 이탈 소자 값을 싣는다 | 엔진 판정 값의 사본(규칙 4 위반), 오라클이 검사 불가(F7) | 기각 |
| (라) | 오라클이 2단계 이탈을 스스로 정한다 | X-34·O-50 G5(오라클은 LUT 양을 계산하지 않음)와 충돌 | 기각 |

'잠정 방향'과의 관계: (가)는 '엔진 2단계 판정 기록'과 '`range_final`은 참조(record_id + point id), 사본 없음'을 모두 만족한다 -- `range_final.source`의 `{record_id, point_id}`가 그 참조 키다. 참조의 방향은 엔진 기록 → 오라클 기록(지목)이고, `range_final`은 같은 지목을 가리켜 둘이 한 키로 이어진다. 원래 취지와 다름 없음.

## 4. 권고 (원칙 점검 포함)

1. **정본 자리** = 엔진 2단계 판정 기록(gain-budget EO-1이 붙이는 엔진 결과 JSON 점 레코드의 범위 판정 부분, F2). writer = 2단계 호출 자리 하나(OP-5 통합 병합 엔진 커밋). **칸 이름·형식은 gain-budget 쪽 정의가 필요하다**(F3 -- 지금 칸이 없음). 그래서 이 결정은 oracle 계획만으로 닫히지 않는다: gain-budget 계획(EO-1 범위 (4) '옮긴 판정' 또는 OP-5 통합 병합 엔진 커밋 범위)에 칸 하나와 완료 조건(이탈 소자 toy, 소비자 = 검증자 원인 변화표 -- graph-consumption '소비자 ≥ 1')을 더하는 개정이 함께 있어야 한다. 정본 자리가 gain-budget 쪽에 아직 없으므로 규칙 6에 따라 **두 계획을 먼저 고친 뒤** design이 형식을 정한다.
2. **oracle 쪽에 필요한 것** = 계획 문장 한 줄뿐: N3.9 '범위 판정' 끝(또는 G-18 '결과 칸')에 "2단계 끝 이탈 소자 정보는 엔진 2단계 판정 기록(정의 = gain-budget)에 있고 오라클 기록에는 두지 않는다; 검증자 원인 변화표는 `range_final.source` 지목으로 그 기록을 찾는다". 오라클 스키마·코드 변경 0, 새 칸 0.
3. **곁 발견(F6, graph 규칙 4 점검 대상)**: `confirmed_range` 정의 불능 끝의 `reason`은 엔진 2단계 사유를 오라클 입력·출력에 그대로 되싣는 **값 사본**이다(판정에 쓰지 않는 출력 전용 칸). (가)를 택하면 그 사유도 엔진 2단계 기록에 이미 있으므로 `reason` 칸은 지울 수 있다(정의 불능 끝 = `{undefined: true}`만). design 개정 대상으로 올림 -- 이 문서는 결정하지 않는다.
4. 검증자(원인 변화표)의 읽기: 엔진 기록과 `range_final`을 지목 키로 잇는 것은 기존 '참조로 전달' 규칙의 적용이라 새 집계 규칙이 아니다.
