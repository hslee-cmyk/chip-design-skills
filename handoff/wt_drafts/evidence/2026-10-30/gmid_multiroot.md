## 1. 정의 (상수 없음)

- 분지: 곡선 gm/ID(VGS)에서 정점 오른쪽 부분이다(LUT VGS 격자 원값, 보간 없음).
- **가려진 점(shadowed)**: VGS 격자점 x에서 max_{x' > x} g(x') ≥ g(x)인 점이다. 이런 x는 같은 gm/ID에 더 큰 VGS 해가 있으므로 '가장 큰 VGS 해' 규칙으로는 도달할 수 없다.
- 진폭: max_x (max_{x'>x} g − g(x)) / g(x).

pfet을 L별로 보면(가려진 점 비율, gm/ID 띠):
- L 0.15 → 20.7 %, g 14.1~18.2
- L 0.18 → 13.2 %, g 14.9~18.1
- L 0.2 → 9.7 %, g 15.2~18.0
- L 0.25~0.7 → 0.9~1.8 %, g 16~18
- L 1 → 0.6 %
- L 1.5~20 → 3.4~6.4 %, g 17.2~17.6

L 0.3 이상에서 띠 위쪽 끝 ~33.5는 정점 바로 옆의 평탄(동률, 진폭 0)이다. 162곡선, 206점이고 실질 다가가 아니다.

- **실질 다가는 pfet 혹 하나다.** 중간 반전, VGS 약 0.6~1.05 V, gm/ID 약 14~18 S/A에 있다. 단채널 L ≤ 0.2에서 진폭이 가장 크고(최대 8 %), VSB가 클수록 비단조 곡선이 늘어난다(VSB 0 → 1.8에서 447 → 758곡선).
- SPICE와도 맞는다. 가려진 동작점에서 LUT gm/ID 대 ngspice @m[gm]/@m[id] 차가 ≤ 1.1 %다. 그러므로 LUT 보간 인공물이 아니고 **sky130 pfet 모델 곡면 자체의 성질**이다. 이 모델이 oracle이므로 엔진이 따라야 할 사실이다.
- **θ 상자와 겹친다.** 계획 303행: S gm/ID 범위 = 그 L bin LUT gm/ID 정의역 ∩ 최소 폭 하한이다. pfet 분지 정의역(약 1~30 S/A)이 띠 14~18을 포함하므로, 최소 폭 하한이 띠 위를 자르지 않는 한 **모든 pfet L bin에서 겹친다**. 최소 폭 하한의 위치는 재지 않았다.

## 3. 원문 설계점 근처 동작점에서 '가장 큰 VGS 해'가 다른 점을 고르는 사례

대상: current_reuse class-AB 반쪽. kv1 oracle 20회 × 8소자 + classab_battery 대표점 M9a = 161 동작점(원문 Fig.7 치수 근처, 앞 §1).

| 소자 | 가려진 / 전체 | 규칙이 고르는 VGS − 실제 VGS |
|---|---|---|
| nfet (M16, M9b, M14a, M14b) | 0 / 80 | -- |
| pfet M15 (L 0.35, VSB 0) | 0 / 20 | -- |
| pfet M9a (L 0.15, VSB ≈ 0.85) | **21 / 21** | +0.10~+0.30 V |
| pfet M11a (L 0.18, VSB 0, 다이오드) | **14 / 20** | +0.1~+0.28 V |
| pfet M11b (L 0.18, VSB ≈ 0.7, 다이오드) | **14 / 20** | +0.09~+0.30 V |
| **합** | **49 / 161** (pfet 49/81) | +0.092~+0.298 V |

- 예 1(rep 원문 근처): M9a 실제 VSG = 0.695 V(g = 15.91)인데, 같은 g의 해가 {0.497, 0.695, 0.891}이다. 규칙은 0.891을 고른다.
- 예 2: M11a 실제 0.701 V인데 해가 {0.525, 0.701, 0.799}다.
- 물리 영향: VSG가 +0.2 V 커지면 같은 고리 합에서 V(N11b)가 0.2 V 줄어든다(classab_battery에서 M12 여유는 0.24 V였다). 같은 gm/ID 값을 θ로 줘도 엔진은 원문 설계점이 아닌 다른 동작점(헤드룸이 없는 쪽)을 만든다.
- 결론: gm/ID를 θ나 역산 키로 쓰는 경로에서는 원문 설계점 근처 pfet 동작점의 **60 %(49/81)에 도달할 수 없다**.

## 4. 판정과 권고 후보

**판정**: '가장 큰 VGS 해' 규칙은 sky130 pfet에서 **틀림**(조건부가 아님)이다.
- 근거 (1): 같은 gm/ID를 만족하는 동작점이 최대 셋이고, 셋 다 물리적으로 정당하다(E-0 전 단계에서 셋 모두 포화 가능).
- 근거 (2): 규칙이 고른 해는 원문 설계점이 아니다(실측 49/81).
- 근거 (3): 큰 VGS가 '강반전'을 뜻한다는 전제가 혹 구간에서는 성립하지 않는다(혹은 중간 반전 안에서 생김).
- nfet은 영향 0이다. 그래서 회로 일반성 측면에서는 pfet을 쓰는 13회로 모두에 걸리는 잠재 결함이다. 실제 발현은 동작점이 혹 띠(g 14~18)에 들어갈 때만이다.

### 5.4 (3) 사용자 spec이 gm/ID를 직접 주는 곳 / (B) 다근 후보의 graph 정본 자리

**사용자 spec이 gm/ID를 직접 주는 곳: 0/13.**
- 13개 sizing_spec의 비주석 키·값에서 gm/ID 값은 0이다.
- 유일한 언급은 current_reuse `offset_in_sigma_mv ≤ 3.3` source 기록의 유도 가정('gm/ID 15·L 0.5')이다. 값은 offset이고 gm/ID가 아니다.
- spec `_comment`도 'gm_id_groups … 이관하지 않는다'로 되어 있다.
- 그러므로 (A)에서 사용자 입력 gm/ID를 ln IDu로 옮겨야 하는 자리는 없다.

**(B) 다근 후보의 graph 정본 자리**
- (A)를 적용하면 θ 경로의 gm/ID 역산이 모두 순방향 조회가 된다. 그래서 '근 선택'이라는 필드 자체가 생기지 않는다. 남는 gm/ID 목표(LR6 하한, 출발 구간 ft·이득 경계)는 hull(해 집합)로 ln IDu 구간을 낸다. 구간이 여럿이면 기존 출발 구간 필드(S0 수준 파생 '출발 구간')의 구간 목록 칸에 넣는다. 이 칸이 이미 구간 여럿을 받는지는 design 41 §6 확인이 필요하다(미측정).
- **새 필드 없이 가능한 조건**: 근을 '근 번호'로 저장하지 않고 **각 근의 ln IDu 값을 후보로**(θ 값 자체로) 둘 때다. 근 번호·분지 표지를 graph 칸으로 두면 새 필드다(⚠ graph 규칙 1·6). 그 경우 멈추고 계획부터 고친다.
- 레이아웃(DEC-89)만은 (ID, gm/ID) 보존을 유지하는 한 다근이 남는다. 근 선택 자리가 없으므로 **정본 자리 없음 → 멈추고 보고 대상**이다(위 5.3 사용자 결정과 묶음).
