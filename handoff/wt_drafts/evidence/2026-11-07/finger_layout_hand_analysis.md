### 3.9 J4 -- AI 직접 레이아웃 + 생성 스크립트·의도 문서 보관 (사용자 방향, 측정용 가정)

사용자 원문: "만약 레이아웃을 실제로 한다면 그건 ai가 직접수행하고 그 레이아웃을 생성하는 스크립트를 보관하고 레이이웃 의도를 문서로 남겨. 다음번 수행에서도 재현 가능하게 하는 쪽이 낫겠지?"
꼴(오케스트레이터 전달): 손가락 결정(기하 묶음·w_s·m·P/N 가로·대칭 짝)은 사이징 루프 안 가벼운 기하(J2)가 graph 필드로 기록. 완전 레이아웃은 AI가 회로마다 직접 수행하고 생성 스크립트 + 의도 문서를 저장소에 보관. 같은 입력이면 같은 레이아웃.

**(1) 입력·출력 계약**

### 4.2 제안 (원칙으로 가장 맞는 안)

**제안 = P1 + J3(필요하면 J2-가벼운 기록), 묶음 키 = (kind, body) 연결 확산 + 정본 정합 묶음 폐포, stage는 묶음 속성으로 기록(분할 축 아님). LA-1에는 넣지 않고 LA-1 뒤 레이아웃 재작성(packer 재작성·AI floorplan Q1~Q9)과 함께.**

근거:
1. **물리 결정자(원칙 1·6·21)**: 사이징 평가에 들어가는 기하는 w_s(bin)뿐이고(§3.1), m은 계획 JC-1 문언대로면 평가 물리에 들어가지 않는다. 그러므로 사이징이 정할 것은 W + 묶음 w_s이고, 정수 m·행·접기·대칭·빈 곳은 레이아웃이 실현 기하로 정해 LY7·O-237로 재평가한다. 사용자 원문 5와 같은 꼴이다.
2. **미러 비 우선(사용자 원문 2)**: 미러 단위 공유 = 같은 w_s다. 묶음을 stage로 나누면 8/13 회로에서 미러가 갈리고, (kind, body)로 두면 13/13에서 한 묶음이다(§2.1). 그래서 묶음의 분할 축은 kind·body(물리 결정자 -- 같은 well·같은 확산, LR8)이고, stage는 분할 축이 아니다. 문헌 손 레이아웃도 stage를 넘어 묶는다(Maloberti p.29·p.36, reference §4 'stage 경계는 stack 배정의 결과일 뿐 입력 전제가 아니다'). **⚠ 원래 취지와 다름**: 사용자 원문 1 '같은 스테이지에 있는 kind가 같은 소자들'. stage는 묶음 필드에 속성으로 남겨, 레이아웃이 방안 A(stage별 배치 → 통합)를 고를 때 쓴다.
3. **Euler(원문 1·8)**: 짝수 손가락이면 연결 성분마다 경로 하나가 늘 있으므로(S1) Euler는 사이징의 제약일 필요가 없다. 묶음 필드에 '성분 수(= 최소 끊김)'와 성분별 홀수 꼭짓점(m = 1 기준)을 정적 사실로 기록하면 손가락 수 결정 근거로 쓸 수 있다(원문 3). 정수 m 홀짝은 레이아웃이 정한다.
4. **대칭·빈 곳(원문 7)**: 둘 다 접는 줄 수와 행 구성에 기대고(S5·S6), 서로·Euler와 충돌한다(§2.2). 사이징이 정하면 레이아웃이 다시 정해야 하므로 판정 축 면적(DEC-79 (b), LY10)과 matching 감사(LY4·LY5·LY9)가 있는 레이아웃의 목적으로 둔다. 사이징 쪽에는 '기록'(묶음 필드의 연속 손가락 근사 행 폭·대칭 짝 목록)만 둔다(출력 전용 선언 또는 레이아웃 입력 소비자).
5. **graph 정본(원칙 7)**: (a) 묶음 소속 = S1v 뒤 정적 블록 writer 하나, (b) 묶음 w_s = `dc_solve`. MOD7 행 그룹 유도는 (a)를 READS(둘째 유도 삭제), 다시 구성한 결과는 `ly_rows`(다른 축). 새 cache 0.
6. **속도(원칙 1, O-200)**: P1은 탐색 차원·평가 비용 증가가 없다. J1은 §3.4 비용과 불연속 목적 멈춤 규칙 부재로 맞지 않는다. J2는 후보에서만 레이아웃을 돌리므로 지금 J3(LY7·MOD8)과 같은 자리다 -- 추가할 것은 '평가 안 가벼운 기하' 하나인데, P1이면 그 값(연속 손가락 행 폭)이 기록용이라 J3과 사실상 같다.
6-1. **J4(AI 스크립트)**: 사이징 쪽 결정(P1의 (a)(b))은 J4와 맞물린다 -- 스크립트 입력이 바로 (a)(b)다. J4는 엔진 기본 레이아웃 위에 덧붙는 꼴(writer = 실행기 하나, 스크립트 없음 = 기본 스크립트)일 때만 graph·일반성 규칙과 맞는다(§3.9). DRC·LVS 도구가 없어 기하 규칙 검증이 부분적이므로 LA-1 뒤 AF 질문 묶음과 함께 정한다.
7. **LA-1 시점(O-229 4)**: 이 변경은 DEC-105 (2)·`dc_finger` 소비자·MOD7 입력 재작성을 부른다. LA-1을 막는 결함은 아니다 -- LA-1을 막는 쪽은 진행 중인 QB 질문(정합 묶음 bin 분리)이고, P1의 '미러 묶음 공유 w_s'는 QB의 R3/R4 꼴(정본 matching_groups READS로 고친 것)과 같은 방향이다. 그래서 QB에서 '정합 묶음 같은 w_s'를 고르면 그것이 P1의 첫 조각이고, 묶음 필드·m 연속·MOD7 READS는 LA-1 뒤 레이아웃 재작성에서 한다.

## 7. 남은 불확실

1. 대표점은 two_stage_ota HS 하나. 나머지 5회로 수치는 HS 변환(봉인 확인 안 함) W이고 층 0 θ 전류 비가 퇴화 점의 비라 ngcc·nmcnr 차동쌍 비 오차·대칭 실패는 점 결함이다. 6회로는 구조만.
2. 접기 모형은 손가락을 줄마다 고르게 나누고 분할점마다 끊김 1로 셌다(확산 안전 분할점 존재 가정). 실제 LY9(패턴 함수로 행 수 다시 짓기)·LY11 hub 병합·floorplan packer 결과와 다를 수 있다. 정사각형 목표는 측정용 기준이다.
3. 대칭 판정은 행 단위(엔진 `mirror_symmetric_trail` + 짝 없는 홀수 ≤ 1)이고, 행 사이 배치(축을 두고 행 순서·가운데 맞춤)는 세지 않았다. common-centroid 2행(LY5) 판정은 하지 않았다.
4. P1의 'm 연속이면 사이징 물리에 m 불필요'는 계획 JC-1 문언 기준이다. as-built 접합은 m을 읽는다(R5 §7.1, agent 인용 + `ss_linearize.py:80` 직접 확인). 그 차의 크기(R5 §7.2)는 진행 중 문서라 인용하지 못했다.
5. E-1 오라클 합격이 어느 기하(사이징 / MOD8 수렴)에서 도는지가 front 점 닫기(O-173)와 어떻게 묶이는지 계획 문언을 끝까지 대조하지 않았다 -- P1에서 정수 m이 사이징에서 빠지면 사이징 기하 진단 SPICE의 m 출처가 필요하다.
6. 결정 간 모순 점검(원칙 26 ⑩)은 이 문서 작성자가 채울 수 없다 -- 점검자 배정 필요.
7. J1 비용 추정은 한 회로·한 점의 MOD7 시간 × 기록된 탐색 평가 수이다(§3.4). 큰 회로의 MOD7 시간은 재지 않았다.
