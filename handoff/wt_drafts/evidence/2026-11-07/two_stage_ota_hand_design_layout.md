## 1. 입력 (엔진 밖 사실)

## 2. gm/ID 손계산 설계

### 2.1 설계 선택(근거)
| # | 선택 | 근거 |
|---|---|---|
| S1 | Rz = 1/gm6 | 오른쪽 반평면 영점을 무한대로(책 식 6.69 영역) |
| S2 | VSG6 = VSD4 = VSD3 = VSG3 | KVL(M4 drain = O1 = M6 gate) -- 계통 offset 0. 처음엔 L6 = L3·gm/ID6 = gm/ID3로 맞췄고, L3을 늘린 뒤에는 VSG만 같게 두고 L6 따로(gm/ID6은 그 VSG에서 따라옴) |
| S3 | M5·M7 같은 L | 같은 gate·source → 같은 VGS → 전류 비 = W 비(미러) |
| S4 | VCM = M1·M5 포화 여유가 같은 점 | spec input_dc 미정(SP-2) -- 선택으로 표지 |
| S5 | 출력 DC = VCM | PM 정의 beta = 1 루프(선언 되먹임 없음) |
| S6 | gm/ID3 ≤ gm/ID1 | noise_excess = 1 + gm3/gm1 ≤ 2 의 선행 조건 |

### 2.2 순서(손계산 식, `scripts/design.py`)
1. DC(원칙 3, DC 풀이): M3 다이오드 VSG3 = VSD3를 gm/ID3로 고정점 → D3 = O1 = VDD − VSG3. M5 gm/ID5·M1 gm/ID1(VS = CS, 몸체 효과)로 S4 고정점 → CS, VCM. M6은 VSG3·VSD6 = VDD − VCM, M7은 VGS5·VDS7 = VCM.
2. gm/ID 고정이면 노드 전압은 전류와 무관하고 gm·gds·C·W는 전류에 비례 -- 단위 전류 동작점 하나를 풀고 비례(계산을 한 번만).
3. 소신호(동작점 MNA, 노드 D3·O1·CS·N_cc_rz·OUT): gm·gmb·gds, LUT C 열 CGS·CGD·(CDD−CGD)·(CSS−CGS)(O-179), Rz·Cc·CL. 1 Hz 이득, |A| = 1 주파수, 펼친 위상으로 PM.
4. I1 = 2π·GBW·Cc/(gm/ID1)에서 출발, I6은 PM ≥ 70°인 최소값을 이분, GBW가 목표가 되도록 I1 보정 반복.
5. 스윕(책 Example 6.7과 같은 꼴): 1차 1620점(288점에서 경향 확인 후 멈춤) → 2차 82점. 경향: 작은 Cc, 짧은 L6, 높은 gm/ID1이 전력을 줄인다.

## 3. 손가락·행 결정 (사용자 기준 O-251~O-254, `scripts/fingerplan.py`)

연결로 판정(태그 0): 채널 연결 성분(stage 근사) = {M1..M5}, {M6, M7}. 미러(같은 kind·gate·source) = (M3, M4), (M5, M7). 차동쌍 = (M1, M2).

1. **미러 비 최우선**: M7/M5 손가락 비 = 정수 n, 같은 w_s. PM이 요구하는 I6 이상인 최소 n(= 5). (M5, M7)은 stage가 다르다 -- 방안 A에서도 같은 w_s를 강제했다(사용자 기준 1이 stage 묶음보다 앞).
2. **tail 이 전류를 정한다**: I5 = m5·w_s·IDu5(같은 bias VGS), I1 = I5/2, 나머지 소자 손가락은 그 전류로.
3. **홀짝**(대칭 + Euler 연속, 손 배치에서 유도): 축 위 tail은 짝수(반씩), ABBA 짝은 4의 배수, 끝의 큰 소자는 짝수. 홀수 tail 하나를 가운데 두면 CS–gnd 방향 때문에 끊김 2가 생겼다.
4. **행 안 w_s 하나**(LR8), 행 길이 = Σ m(L + overhead) + 양 끝 더미·확산 끝.
5. 순서(사전식): Euler 끊김 → 대칭 → 전력 → 빈 면적 → box.

| 방안 | 후보 | 최상위 | box | 빈 면적 | 대칭 | 끊김 | 전력 |
|---|---|---|---|---|---|---|---|
| A stage 블록(S1 \| S2) | 2592 | S1 w_s 0.42/0.42, S2 0.42/0.42~0.64 | 224~277 µm² | 7.8~8.6 % | 행마다 성립, 전체 불성립(블록이 한쪽) | 0 | 59.1 µW |
| **B kind 전체 행** | 216 | N 0.58, P 1.26 µm | **112.1 µm²** | **3.0 %** | **성립** | 0 | 76.9 µW(최종 점) |

방안 A가 처음 돌렸을 때(미러 w_s를 stage별로 따로 둠) M7/M5 비가 정수 손가락 비가 아니게 되어 I6이 PM 필요량보다 작게 나왔다(16.7 µA < 26.7 µA). 미러 비 우선이 stage 묶음과 충돌하는 실례다.

**되먹임(J2 꼴, `scripts/loop.py`)**: 손가락 규칙이 I1을 1.09 → 3.31 µA로 바꿨다 → GBW = 7 MHz가 되게 Cc를 다시 풀고(0.45 → 1.38 pF) → PM에 필요한 I6을 다시 풀고 → 미러 n을 다시 정했다. n이 바뀌지 않아 1회에 멈췄다.

**E-1 닫기(원칙 2)**: 같은 기하에서 첫 SPICE GBW 6.850 MHz(−2.1 %) → Cc를 secant로 옮기며 4회 → 6.99999 MHz. 마지막 두 걸음의 진전(10~40 Hz)이 SPICE `meas`(decade당 100점 보간) 분해능 수준이라 멈췄다(멈춤 규칙: 옮긴 metric의 oracle 진전 ≤ 분해능). 엄밀히는 7 MHz보다 10 Hz(1.4 ppm) 작다 -- 통과로 셀지는 판정자 몫으로 남긴다. 중간에 넷리스트가 Cc를 6자리로 써서 걸음이 막힌 도구 결함을 찾아 10자리로 고쳤다.

**큰 차이와 원인**
1. 시험대 (b)의 GBW −3.2 %: 기준 다이오드의 VDS(= VGS 0.77 V)와 M5의 VDS(0.43 V)가 달라 미러 전류가 4 % 작다. bias 생성은 topology 밖(`bias_inputs`)이라 손계산은 이 오차를 모른다 -- spec에 bias 생성 구성이 없다는 사실이 판정을 바꾼다(§6 사용자 결정).
2. 손계산 GBW +2.1 %: 같은 기하·전류에서도 남는 차이. 원인 분해는 하지 않았다(후보: 기준 폭 표 용량을 W 비례로 읽은 근사, 공유 확산 접합 용량이 LUT 생성 기하(ad = W·0.5 µm)와 다름).
3. offset 가드: 처음 손 점(M3/M4 L 0.35 µm)은 SPICE gm으로 계산한 offset_excess 2.11로 위반이었다. 짧은 L(< 0.5 µm) pmos bin은 vth0_slope1(7.356 mV·µm)을 쓰고, 경계 L = 0.5 µm는 아래 bin(같은 slope1)이었다 -- L 0.7 µm(slope 5.856)로 옮겨 1.38.

DRC·LVS: magic·klayout·netgen 실행 파일 없음(`C:/pdk/open_pdks_sky130_magic` tech 파일만 있음). 기하는 PDK 역할 양으로만 맞췄고, 규칙 검사는 하지 않았다.

## 7. 제안

1. **사이징이 정하는 것 = W + 행(기하 묶음)별 w_s + 정수 손가락 수의 '제약'(미러 정수 비·홀짝·최소 1~2 손가락)**. 이번 회로에서 13회로 분석의 P1(정수 m은 레이아웃이)과 갈리는 점: 작은 소자(tail·부하)에서는 정수화가 전류를 3배까지 바꿔 GBW·PM·전력이 움직였다. 그래서 정수 m 자체는 레이아웃이 확정하더라도, **사이징 평가가 정수화 제약을 안 채 전류를 정해야** 한다(C6·C7·C10). 큰 소자(M6)는 정수화 영향이 작아(±1 손가락 = 5 %) P1과 같게 둬도 된다 -- 갈림 기준은 '손가락 수가 작은 소자'인데, 그 문턱을 상수로 두지 않으려면 정수화를 늘 넣는 쪽이 단순하다(가벼운 계산, 216 후보).
2. **기하 묶음 = kind(·body) 전체 행이 기본, stage는 속성**(13회로 분석 제안과 같은 결론을 이 회로가 실측으로 확인 -- box 112 대 224~277 µm², 미러 정수 비 유지). ⚠ O-251 원문 1과 다름 -- 사용자 결정(U3).
3. **J2 결합**: 사이징 루프 안에 C6~C10(가벼운 기하·손가락 제약), 후보에만 레이아웃 생성(C8)과 SPICE(C12·C13). 이번 손 실행이 그 꼴 그대로였다(되먹임 1회, 닫기 4회).
4. **AI 레이아웃(J4)**: A1~A4를 AI가 회로마다 정하고 `gen_layout.py` 꼴의 생성 스크립트(입력 = 손가락 결정 필드 + PDK 역할 양, 숫자 없음, 결정적) + 의도 문서로 보관. 엔진은 그 스크립트의 출력(실현 기하)만 READS(LY7 재평가). 스크립트가 없으면 C8의 기본 패턴(이번 rows_B를 일반화한 축 대칭 패턴)으로 돈다.
5. **먼저 고칠 것(재작성 범위 후보, 계획 문언 기준)**: DEC-105 (2) '손가락 선택 = 소자 하나의 순수 함수' → 행 단위 w_s + 정수 제약; offset 가드의 bin slope 선택이 (L, w_s) 경계 규약(아래 bin)을 따르는지 확인; oracle 넷리스트 수 정밀도(이번 6자리 결함과 같은 꼴이 엔진 쪽에 있는지 확인).

## 8. 앞선 분석과의 대조
- `finger_layout_hand_analysis.md`(13회로, 같은 날) 제안 P1 + J3/J2, 묶음 키 (kind, body), stage는 속성: **이 손 실행과 맞음**(방안 B 우세, 미러가 stage를 넘음). **다른 점**: P1은 정수 m을 레이아웃 몫으로 두지만, 이 회로에서는 작은 소자의 정수화가 전류·Cc·전력을 바꿔 사이징 쪽에 정수 제약이 필요했다(§7-1).
