# 사용자 결정 질문 -- V3 뮤테이션 대상 범위 (B26-1 착수 조건)

## 함께 드리는 승인 요청(강화 -- 거부 집합이 넓어짐)

V3 면제 기록이 승인한 코드에 묶이지 않는 **결함**을 고칩니다(`draft_v3_exempt_binding.spec.md`). 판정 기준 소유가 사용자라 강화여도 **승인이 필요합니다**(승인 기록 `20260930-v3-exempt-binding`).
* 지금은 한 card에서 승인한 변이 id 면제가 뒤 card의 같은 경로 변이를 조용히 면제합니다. 실측: B26-1용 면제 목록이 B34(넓은 범위) 변이 1,402개 중 619개를 미리 면제, 옛 C8 면제 14개 중
  `save_instance_json` 4개는 def가 바뀐 뒤에도 적용 중 -- **DF-36 판정(`148bd6d`)의 V3 PASS(죽음 22·면제 4·생존 0)가 실제로 이 4개에 기댔습니다**(auditor가 같은 문장임을 손으로 확인했으나 C8 승인
  범위 밖). 그 판정은 자동으로 뒤집히지 않고, 4개를 지금 실제로 돌려 보는 일을 백로그에 둡니다.
* 고침: 면제 원소를 `변이 id@묶기 해시`(docstring까지 포함한 def AST의 해시 -- docstring 한 줄로 경로가 밀리는 것도 막음)로 묶고, 해시가 없거나 다르면 적용하지 않고 출력에 싣습니다.
* 잃는 것: 기존 C8 면제 14개는 더는 적용되지 않습니다. **앞으로의 card 기준으로는 잃는 것이 없습니다**(그 def를 다시 바꾸는 순간 어차피 해시가 달라짐 -- 실측). 이미 내려진 DF-36 판정은 위와 같습니다.
* 운영 비용: 면제를 승인한 def를 재시도에서 고치면(docstring만 고쳐도) 면제가 풀려 **시도마다 다시 승인**하셔야 합니다. Python 판을 올릴 때도 묶인 면제가 풀릴 수 있습니다(fail-closed).

## 질문

V3는 지금 **AST가 바뀐 def의 본문 전체**를 변이합니다. 엔진 def가 커서 몇 줄을 고친 card도 그 def의 기존 문장 전부를 죽여야 병합됩니다. 어떻게 할까요?
(수치는 B26-1 초안 시뮬레이션 head, 직렬 실행. 하한 = 변이 × 5초, 상한 = 전부 생존 가정. **현실 하한** = 하한 + 어떤 test도 실행하지 않는 줄의 변이(반드시 생존 → 인벤토리 전체 약 3.1~3.4분씩).)

| | 선택지 | B26-1 대상 변이 / 시간 | card가 떠안는 것 | 놓치는 결함 | 약화 |
|---|---|---|---|---|---|
| 1 | **지금 규칙 유지**(def 전체) | 2,472 / 3.4 h ~ 129 h, **현실 하한 약 19 h**(3.4 h + 미실행 줄 변이 306 × 인벤토리 ≈ 15.8 h) | 어떤 test도 실행하지 않는 줄의 변이 **306개는 반드시 생존** → 레일과 무관한 기존 코드의 test를 새로 쓰거나 변이 id 면제 승인(묶기 뒤라 재시도마다 재승인). 그 밖에 C8 때 면제한 `load_topology` 기존 공백 10개(B8)도 경로가 밀려 다시 대상 | 추가로 놓치는 것 없음 | 아니오 |
| 2 | **바뀐 문장 + 감싸는 제어문 + 지운 문장 자리 앞뒤 + 바뀐 매개변수를 읽는 문장 + 새 def 전체**(N2, 권고) | 228 / 19분 ~ 12 h, 현실 하한 0.6 h | 이 card가 쓴 코드의 test(미실행 줄 변이 6). 대상 밖 변이는 실행하지 않고 id만 출력 → 백로그 | 바뀐 값이 **다른 블록이나 두 단계 이상**을 거쳐 흘러드는 바뀌지 않은 문장, 매개변수 값이 다른 이름을 거쳐 흐르는 문장, 블록 끝에서 지운 절(`else` 통째 등)의 뒤 영향 | **예**(판정 범위 축소) |
| 2a | 2와 같되 **def 머리(매개변수·기본값·데코레이터)가 바뀌면 본문 전체** | 1,309 / 1.8 h ~ 71 h, 현실 하한 5.8 h | 머리가 바뀐 def(B26-1은 `rails` 추가로 20개)의 기존 본문 전체 → 미실행 줄 변이 74 | 2의 공백 중 '머리가 바뀐 def'의 몫은 없음. 나머지는 2와 같음 | 예(2보다 작음) |
| 3 | **2 + 바뀐 문장과 이름 한 단계로 이어진 기존 문장**(데이터 의존) | 399 / 33분 ~ 21 h, 현실 하한 1.6 h | 2 + 바뀐 값을 쓰거나 대 주는 기존 문장의 test(미실행 줄 변이 20) | 2보다 작음: 두 단계 이상·속성·컨테이너 경유 흐름 | 예(2보다 작음) |

다른 card: P9 실제(병합 `b7765b0`) 28 / 12 / 12 / 11개. B34 좁힌 초안(def 4개)은 55 / 10 / 10 / 14개이고, **그 card가 지금 규칙(1)으로 55개를 모두 죽였습니다**(면제 0) -- 선택과 무관합니다.
어느 선택지든 바뀐 def에 닿는 test가 없으면 FAIL입니다(`early_return`을 항상 대상으로 삼음 -- 개정 전 초안에는 def 머리만 바꾸면 대상 0개로 통과하는 구멍이 있었습니다).

## 권고: 2

* V3의 목적은 "이 변경을 위해 쓴 test가 이 변경의 코드를 판정하는가"(DEC-38)입니다. 바뀌지 않은 문장의 생존은 card의 test가 아니라 기존 test 공백을 잽니다 -- 그중 306개(B26-1)는 어떤 test도 그 줄을
  실행하지 않아 card마다 확정 FAIL입니다. 1은 이 공백 메우기를 엔진 card마다 병합 조건으로 만듭니다(B26-1·B26-2·B35가 같은 큰 def를 다시 바꾸므로 반복).
* 2a는 B26-1처럼 매개변수를 더하는 card에서 def 전체의 53%를 대상으로 삼아, 1의 부담(미실행 74개)을 상당 부분 되살립니다. 2a가 더 덮는 것은 '바뀐 매개변수가 다른 이름을 거쳐 흐르는 문장'입니다.
* 3은 2가 놓치는 '이름 한 단계 흐름'을 덮고 대상이 2의 1.75배입니다. 3이 더하는 171개가 실제로 생존할지는 재지 않았습니다.
* 1의 시간은 약화 없는 가속(줄 커버리지 선택·병렬, 별도 card)으로 줄일 수 있지만, 미실행 줄 변이 306개는 가속으로 없어지지 않습니다.
* 권고하지 않는 중간안: 표본 추출·예산(약화인데 빠지는 변이가 임의), 자동 기준선 차분(결과는 2와 비슷하고 비용은 1 이상).

## 선택하면 일어나는 일

* **2·2a·3**: 게이트 변경 card `20260930-v3-changed-stmt-scope`(`draft_v3_scope_policy.spec.md` -- 2a는 T3(a), 3은 T7 추가) + 승인 기록(`target_kind: diff`, 범위 설명에
  **"판정 기준 적용 범위 축소(약화) 승인"** 명시). 순서: 면제 묶기 → 이 card → B26-1. 이 card는 데코레이터 변이가 실제로 적용되지 않던 도구 결함도 함께 고칩니다.
  Phase 3 이동 card G1도 같은 도구의 대상 선택을 바꾸므로, 나중에 병합하는 쪽이 상대 card에 맞춰 계약 문장 한 줄을 고칩니다.
* **1**: 범위 card는 쓰지 않습니다. 데코레이터 변이 결함 수정만 별도 게이트 card로 냅니다. B26-1은 V3 전수로 가고, 미실행 줄 변이 306개와 추가 생존은 test 보강 또는 card별 면제 승인
  (해시에 묶인, 재시도마다 재승인)으로 처리합니다.
