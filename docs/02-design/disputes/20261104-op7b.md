## 문제의 test

1. `test_result_contract.py::test_t3_8d_compare_json_new_fields_and_deleted_u6` (83행): `assert fp["capability_record_id"] is None and fp["compat_sha256"] is None`.
   spec card C-6("`fingerprints.compat_sha256` = 선언 글 sha ... `compat_sha256 = null`인 oracle_run 결과는 없다")와 '재작성 범위/소비자' 표
   ("`compat_sha256 is None` 단언 | `O/tests/test_result_contract.py:83` | 기대값 전환")이 이 단언을 바꾸라고 하는데, test 커밋 32362b67은
   이 파일을 건드리지 않았다. 구현은 C-6대로 `compat_sha256 = 선언 글 sha`를 내므로(실측 `e632b709...` = 이 World 선언 모드 `m`의 글 sha) 이 단언이 red다.
   spec 잠금 test `test_bin_rule.py::test_lock_oracle_run_compat_sha_not_none_literal`도 같은 요구를 한다. 두 test가 서로 모순이다.
2. `test_bin_rule_run.py::test_t7_10e_model_bundle_mismatch_comes_before_undeclared` (120행): 기대 `rec["code"] == "model_bundle_mismatch"`.
   입력(`make_lut_toy(w.lut, model_sha={"m.lib": "f"*64})`)은 8단계의 앞 검사인 '기록 뿌리 교차'(§7.2 8단계 순서: 빈 표 -> 기록 뿌리 교차 -> 역할 -> 규칙)에서
   `lut_record_root_mismatch`(stage "8")로 먼저 거부된다. `m.lib`는 엔진 선언 `sources`에 있는 파일이라 기록 sha가 틀리면 그 검사가 먼저 걸린다.
   `model_bundle_mismatch`는 그 검사를 통과한 입력에서만 나온다. 구현 쪽 8단계는 이 card에서 바뀌지 않았다(`check_bundles`는 기록 모으기만 함수로 뺌).

## 근거(oracle 또는 사용자 원문)
