## 문제의 test

`tests/op23_support.py::World.run`(208행)을 쓰는 모든 test(위 넷은 대표, 진입점 `oracle_run.main` 을 stub 로 도는 test 전부, 약 70개)가 오라클 코드에 닿기 전에 다음으로 죽는다.

```
ip = conftest.write_json(self.tmp / "inputs" / f"{out.name}.input.json", inp)     # op23_support.py:208
tests/conftest.py:280  path.write_text(json.dumps(obj, indent=1), encoding="utf-8")
FileNotFoundError: ... test_xxx0/inputs/out.input.json
```

`World.run` 은 `out` 폴더만 `mkdir(parents=True, exist_ok=True)` 하고(207행 앞), 입력을 쓸 `<tmp>/inputs` 폴더는 만들지 않는다. `conftest.write_json` 도 부모 폴더를 만들지 않는다(옛 `run_oracle` 은 이미 있는 `out` 안에 썼다). pytest 의 `tmp_path` 는 새 폴더이므로 `<tmp>/inputs` 는 어떤 test 에서도 먼저 생기지 않는다(`git grep '"inputs"'` 는 이 줄과 `test_result_contract.py:86` 읽기뿐).

## 근거(oracle 또는 사용자 원문)

코드와 무관한 test 지원 파일의 결함이다. 계약 문서(interface §6 '입력 계약', design §11.7)는 입력 파일 위치를 정하지 않고, 주석(`# 입력은 출력 폴더 밖(산출물만 센다)`)이 뜻을 밝힌다: 입력은 출력 폴더 밖에 쓰되 그 폴더는 test 가 만든다는 전제다. 이 줄이 실행되지 않은 채 red 로만 확인되었다(base 에 오라클 새 구조가 없어 import 단계에서 이미 실패하므로 이 줄까지 닿지 않음).

확인: 코드 쪽 구현을 끝낸 뒤, **test 파일을 건드리지 않고** 로컬 pytest 플러그인(저장소 밖 `C:/Users/HSLEE/AppData/Local/Temp/la1s_op23_code/plug/mkdirfix.py`, `pytest_collection_modifyitems` 에서 `conftest.write_json` 이 부모 폴더를 만들게 감쌈)만 얹어 돌리면 아래가 전부 통과한다(코드 작성자의 자체 실행이라 판정 증거는 아님).

`pytest -p mkdirfix tests/core tests/test_input_contract.py tests/test_result_contract.py tests/adapters/ngspice/test_dialect.py tests/adapters/ngspice/test_errors.py` -> 166 passed.

## 요청

`op23_support.py::World.run` 에서 입력을 쓰기 전에 `(self.tmp / "inputs").mkdir(parents=True, exist_ok=True)` 를 하거나 `conftest.write_json` 이 `path.parent.mkdir(parents=True, exist_ok=True)` 를 하게 고친다(test 작성자 몫, 기대값·판정 약화 아님). 오라클 코드를 이 test 에 맞춰 입력 폴더를 만들게 하는 쪽은 택하지 않는다: 입력은 오라클의 출력이 아니라 호출자의 것이고, 거부 test 는 출력 폴더에 거부 기록 하나만 있음을 단언하므로 오라클이 출력 폴더 밖에 폴더를 만들 이유가 없다.
