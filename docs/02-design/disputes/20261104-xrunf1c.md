## 문제의 test

위 세 test(card C 이전부터 있던 test)는 손으로 만든 가짜 `sctx`(`SCTX`, `SCTX_RT`: `types.SimpleNamespace(domain=..., dc=...)`)로 `run_sensitivity_gate` 를 부른다.
이 가짜 `sctx` 에는 `eval_budget`·`eval_budget_source` 칸이 없다. test 작성자는 `fake` 의 시그니처에 `**kw`(ceiling 통과)만 더했고 가짜 `sctx` 는 고치지 않았다.
새 계약(interface C7·C3)은 게이트 묶음 `ceiling` = `e_total(sctx)` 이고 `e_total` 은 `sctx.eval_budget`(없으면 None)·`eval_budget_source` 를 읽는다.
그래서 이 세 test 는 `AttributeError: 'types.SimpleNamespace' object has no attribute 'eval_budget'` 로 실패한다(구현이 계약대로 `sctx.eval_budget` 을 읽기 때문).
같은 파일의 새 test(`SCTX_C`)는 `eval_budget=E_B_GATE, eval_budget_source="declared", eval_times=[]` 를 갖고 통과한다.

## 근거(oracle 또는 사용자 원문)

interface card 3.1 C-T10: "가짜 `sctx` 는 이 문서의 칸만 쓴다" -- 이 문서(C3)는 `e_total` 이 `sctx.eval_budget` 을 읽는다고 정한다. 칸이 없는 가짜 `sctx` 는 이 계약의 입력이 아니다.
`getattr` 기본값으로 읽으면 fail-open(칸 없음 = 예산 없음)이 되어 원칙 10(fail-closed)과 spec card '정본 칸 읽기'에 어긋난다. 그래서 구현에서 흡수하지 않았다.

## 요청

세 test 의 `SCTX`·`SCTX_RT` 에 `eval_budget=None, eval_budget_source=None`(또는 `SCTX_C` 와 같은 칸)을 더한다(test 주체 몫: `e_total` = None 이면 `ceiling=None`, 동작 변화 없음).
구현은 바꾸지 않는다.
