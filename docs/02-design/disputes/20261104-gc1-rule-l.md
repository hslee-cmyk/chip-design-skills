## 요청

1. 판정자가 현재 master(또는 병합 base)에서 독립 스크립트로 기준선을 다시 재고, `BASELINE`·`DEBT`를 갱신한다(test 역할). 새 L-4 4키는 card id가 정해질 때까지 부채로 넣지 않는다.
2. `test_rule_l_baseline_has_fg13_eight_sites`는 `BASELINE` 상수만 보므로 통과한다. 다만 현재 엔진에서 F-G13 8자리 중 `dc_writer_plan`은 `_edges`로 이동했다. test 3의 기대 키를 새 키로 바꿀지 판정이 필요하다.
3. **op_copy 해석**(card가 애매하게 둔 자리): 거부 픽스처 L5b-1·L5b-2는 '칸 값을 꺼내 반환한 함수(`_row`, `_current`)와 그 값을 영속 자리에 담은 함수(`place`, `lay`)' 둘을 위반으로 적는다. 이 규칙을 엔진에 그대로 적용하면 기준선 4개(추출 자리)에 더해 영속 자리(`layout/run.py::run_layout`, `metrics/metrics_aux.py::metrics_aux`, `core/failure_partial.py::attach_partial`)와 그 운반 경로(`convergence/*`, `search/eps_sweep.py`, `search/layer0_center.py`, `search/slsqp_outer.py`, `metrics/ss_evaluate.py` 등) 20개가 더 잡힌다. 이 20개는 손 분류(N3.1-5 '이 정의로 분류한 다른 자리')가 없는 자리이고, 일부는 `ops`·`snapshot`을 인자로 운반하는 함수라 과잉 탐지일 수 있다(컨테이너 대 칸 값 구분은 AST만으로 불가). 판정자가 20개를 N3.1-5 분류(사본/계산 입력/출력 함수 면제)로 손 분류하거나, 규칙을 '칸 추출 자리 + 영속 자리' 대신 '칸 추출 자리만'으로 줄일지 결정해야 한다(후자는 픽스처 L5b-1·L5b-2 기대 수정이 필요하다).
4. op_copy writer 파일: `PARAMS`는 `sizing/s2_values.py`(`DeviceOp` 클래스가 있는 파일)로 적었고, 실제 `device.dc_op` 쓰기 블록은 `sizing/block_widths.py::dc_widths`다. 구현은 PARAMS의 파일만 면제한다. 쓰기 블록 파일로 면제를 바꾸려면 PARAMS를 바꾸고 지문이 바뀐다.
