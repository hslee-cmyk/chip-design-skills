## 1. 위치 선언 (`gmid_engine.lut.resolve_lut_location`)

설정 `files.verify_midpoints`(선택) = JSON **배열**, 원소 = `{"path": <root 기준 상대 경로>, "sha256": <파일 바이트 그대로의 sha256 hex>}`(원소의 다른 키는 읽지 않는다). 하위 폴더 허용(`verify_midpoints_w/<이름>.npz`).

`LutLocation`: 칸 `midpoints_paths` = 절대 경로 tuple(`path` 문자열 오름차순), 항목이 없으면 `()`. **옛 칸 `midpoints_path`는 없다**(`hasattr(loc, "midpoints_path")` 거짓). 칸 순서: `config_path, root, manifest_path, cap_npz_path, midpoints_paths, pdk_root, sources, noise_path, mismatch_path, bin_rule_path`.

| 입력 | 결과(`SchemaRejectedError` detail `reason`, `item`) |
|---|---|
| 배열, 원소 2개, 파일·sha 맞음 | 통과, `midpoints_paths` 길이 2, 정렬 |
| 같은 두 원소를 역순으로 적은 설정 | 위와 같은 `midpoints_paths` |
| 항목 없음 | 통과, `midpoints_paths == ()` |
| **옛 꼴**: 단일 객체 `{"path", "sha256"}` | `lut_location_config_invalid`, item `verify_midpoints` |
| 빈 배열 `[]` | `lut_location_config_invalid`, item `verify_midpoints` |
| 원소가 객체 아님·`path` 없음·`sha256` 없음·절대 경로·`..` 포함 | `lut_location_config_invalid`, item `verify_midpoints` |
| 같은 `path` 둘 | `lut_location_config_invalid`, item `verify_midpoints` |
| 파일 없음 | `lut_location_file_missing`, item `verify_midpoints` |
| 바이트 sha256 ≠ 기록(raw 비교, LF 환산 없음) | `lut_location_sha256_mismatch`, item `verify_midpoints` |

결과는 `load_lut_set(loc.manifest_path, loc.cap_npz_path, spec, bin_rule=loc.bin_rule_path, pdk_root=loc.pdk_root, verify_midpoints=loc.midpoints_paths, noise_npz=loc.noise_path, mismatch_npz=loc.mismatch_path)`로 넘긴다.

**저장소 선언**(`A/lut_v2_location.json`, 코드 커밋 안): `files.verify_midpoints` = 출처 기록 `A/lut_v2_midpoints_w.provenance.json` `files[]` 30행의 (`path_rel_root`, `sha256`) 그대로(30원소). 옛 단일 객체 항목은 없다. 나머지 키 불변. R-1이 이 대응을 단언한다(출처 기록을 JSON으로 읽어 비교).

## 2. 중점 파일 형식과 적재 관문 (`lut_provenance`, `load_lut_set`)

**파일 형식 = DC 슬라이스 npz와 같은 꼴**(LM-1d 데이터): `W`(스칼라, m), `L`(중점 L 점, m, 1개 이상), `VGS`·`VDS`·`VS`, `ID`·`GM`(필수), `VDSAT`(선택), 그 밖 열은 읽지 않음, `corner`·`temp_c`, `meta_json`(JSON: `device`, `generator_sha256`, `model_files_sha256`, `ngspice`). 배열 모양 `[len(L), len(VGS), len(VDS), len(VS)]`, 절댓값. **열 접미사·`w_ref_m`·meta `L_source`는 쓰지 않는다**(옛 형식).

서명: `lut_provenance(manifest_path, cap_npz_path, spec, *, bin_rule, pdk_root=None, verify_midpoints=None, noise_npz=None, mismatch_npz=None)`, `load_lut_set(...)` 같은 키워드. `verify_midpoints` = 경로 sequence(list·tuple) 또는 None. None과 빈 sequence = 중점 없음. 문자열 하나 → `TypeError`.

**짝 슬라이스**: 중점 파일 meta `device` = manifest 슬라이스 **파일의** meta `device`(같은 문자열)이고, `W`의 폭 키(`round(W / manufacturing_grid_m)`, 슬라이스와 같은 격자 규칙) = 그 슬라이스 폭 키인 슬라이스 하나. kind = 그 슬라이스 kind. (합성 toy는 슬라이스 meta와 중점 meta 둘 다에 `device`를 넣는다.)

관문(파일마다, 위에서 아래로 첫 맞는 행; 거부 = `SchemaRejectedError`, detail에 `path`). **사유는 기존 이름을 쓰고, 새 이름은 `lut_midpoints_slice_unmatched` 하나**(spec '원래 취지와 다름' 2):

## 4. 지문·자료 id·중점 검증
