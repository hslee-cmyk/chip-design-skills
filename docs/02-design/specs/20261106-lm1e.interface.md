## 1. 위치 선언 (`gmid_engine.lut.resolve_lut_location`)

설정 `files.verify_midpoints`(선택) = JSON **배열**, 원소 = `{"path": <root 기준 상대 경로>, "sha256": <파일 바이트 그대로의 sha256 hex>}`. 다른 키는 무시하지 않고 거부하지 않는다(원소에 `path`·`sha256`만 읽는다). 하위 폴더 허용(`verify_midpoints_w/<이름>.npz`).

`LutLocation`: 칸 `midpoints_paths` = 절대 경로 tuple(배열 순서를 `path` 문자열 오름차순으로 정렬한 순서), 항목이 없으면 `()`. **옛 칸 `midpoints_path`는 없다**(`hasattr(loc, "midpoints_path")` 거짓). 나머지 칸·순서는 그대로(`config_path, root, manifest_path, cap_npz_path, midpoints_paths, pdk_root, sources, noise_path, mismatch_path, bin_rule_path`).

## 2. 중점 파일 형식과 적재 관문 (`lut_provenance`, `load_lut_set`)

**파일 형식 = DC 슬라이스 npz와 같은 꼴**(LM-1d 데이터): `W`(스칼라, m), `L`(중점 L 점, m, 1개 이상), `VGS`·`VDS`·`VS`(축), `ID`·`GM`(필수), `VDSAT`(선택), 그 밖 열(`GDS`·`VTH`·`GMBS`)은 읽지 않음, `corner`·`temp_c`, `meta_json`(JSON 문자열: `device`, `generator_sha256`, `model_files_sha256`, `ngspice` 필수 -- 아래 관문). 배열 모양 `[len(L), len(VGS), len(VDS), len(VS)]`, 값은 절댓값(슬라이스와 같은 규약). **열 접미사(`_n`·`_p`)·`w_ref_m`·meta `L_source`는 쓰지 않는다**(옛 형식).

서명: `lut_provenance(manifest_path, cap_npz_path, spec, *, bin_rule, pdk_root=None, verify_midpoints=None, noise_npz=None, mismatch_npz=None)`, `load_lut_set(...)` 같은 키워드. `verify_midpoints` = 경로 sequence(list·tuple) 또는 None. None과 빈 sequence = 중점 없음. 문자열 하나를 주면 `TypeError`(옛 단일 경로 호출 거부 -- 문자열을 글자 sequence로 읽지 않는다).

**짝 슬라이스**: 중점 파일의 meta `device` = manifest 슬라이스 파일 meta `device`(같은 문자열)이고 `W`의 폭 키(`round(W / manufacturing_grid_m)`, 슬라이스와 같은 격자 규칙) = 그 슬라이스 폭 키인 슬라이스 하나. kind = 그 슬라이스 kind. (manifest 줄의 `device`는 `nfet_01v8` 꼴이고 파일 meta `device`는 `sky130_fd_pr__nfet_01v8` 꼴일 수 있다 -- 대조는 **파일 meta끼리**.)

## 3. 지문·U-87 자료 id (`lut_fingerprint`, `TableCache`)

- `lut.fp`: 중점이 있으면 지문 항목에 `("midpoints_sha256", <위 property 값 tuple>)`가 든다. 중점이 없으면 그 항목이 없다(중점 없는 LUT 지문은 이 card 전과 같다).
- `TableCache.data_id(provenance)` = `core.fp_of((manifest_sha256, cap_sha256, provenance.midpoints_sha256))`.
- 설정에서 같은 값: 보존 집합 계산이 설정 파일 `files`에서 자료 id를 만든다 -- 배열 꼴 → `tuple(sorted(원소 sha256))`, 항목 없음 → None. **옛 단일 객체 꼴**(다른 worktree 설정) → 그 `sha256` 문자열(옛 자료 id 그대로 -- 그 worktree의 칸을 지우지 않게). 이 경로는 데이터 적재가 아니다(적재는 §1에서 거부).

| id | 입력 | 기대 |
|---|---|---|
| F-1 | 중점 파일 둘인 LUT, 하나의 바이트만 바꾼(값 하나 바꿔 다시 저장) LUT | `fp` 다름, `data_id` 다름 |
| F-2 | 같은 두 파일, sequence 순서만 다름 | `fp` 같음, `data_id` 같음 |
| F-3 | 같은 내용 파일을 다른 폴더에 둠 | `fp` 같음 |
| F-4 | 중점 없는 LUT | 지문 항목에 `midpoints_sha256` 없음(이 card 전 지문 정의와 같은 값 -- 독립 구현: `core.fp_of`로 항목 tuple을 직접 만든다) |
| F-5 | 배열 꼴 설정 파일(§1)과 그 설정으로 적재한 LUT | 설정 쪽 자료 id(보존 집합 계산이 쓰는 함수 -- 관찰 지점 §9) = `TableCache.data_id(lut.provenance)` |

## 4. 중점 검증 (`midpoint_l_bin_checks(memo, kind, w_key) -> MidpointChecks`)

## 5. tol 표 정의 불능 (`tol_v_table`, `tol_vdsat_table`)

규칙(두 표 공통, 규칙 자리 하나 -- 소스 grep으로 단언하지 않는다): 슬라이스 L bin 지도에서 앵커 2개 bin의 상태는 그 bin에 외부 값(중점 rows의 그 bin 행)이 있으면 `external`, 없으면 `missing_external`(그대로). **`missing_external` bin에 속한 앵커 행 i의 모든 VDS 셀 값 칸 = None**: `TolVCell.id_equivalent_v`, `TolVdsatCell.vdsat_v`. 진단 칸(`id_equivalent_loo_v`, `vdsat_loo_v`)은 그대로(그 셀의 VGS·VDS·VS 축 LOO 값). 그 밖 행(앵커 3개 이상 bin의 행, 앵커 1개 bin 행, `external` bin 행)은 지금 정의 그대로(`external` 행 = max(셀 LOO, 그 VDS 원소 외부 값), 외부 원소 None이면 셀 LOO 값). `l_loo` 표지(`bin_missing_external` 등)·`l_loo_bins`는 그대로.

`at(L, vds, ...)`: 지금과 같은 셀 고르기(L이 앵커면 그 행, 같은 bin 보간이면 양옆 두 행; VDS 칸 [k, k+1]) 뒤 정의된 값의 max, 없으면 None. 따라서 `missing_external` bin 안 조회는 **L이 앵커와 정확히 같아도** None(m9 조건부 표지 -- Q-T0).

`l_bin_checks` 인자(test 주입 자리)는 그대로: `None` = 중점 표 값, `()` = 외부 값 없음 → 앵커 2개 bin 전부 `missing_external` → 그 행 None.
