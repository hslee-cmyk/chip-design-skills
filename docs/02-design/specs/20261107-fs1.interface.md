## 1. `realize_fingers(w_theta, w_f_m, ratios) -> RealizedCell` (`gmid_engine.sizing` 공개, 자리 `E/sizing/realize_fingers.py`)

**서명·타입**
- `w_theta: tuple[float, ...]` = 칸 멤버의 θ W(탐색 스냅샷 `DeviceOp.W`), 멤버 순서 = 칸 키 순서(정준 위치 순). 길이 ≥ 1.
- `w_f_m: float` = 칸 손가락 폭.
- `ratios: tuple[DeclaredRatio, ...]` = 칸 안 선언 미러 비. `DeclaredRatio(reference: int, outputs_with_k: tuple[tuple[int, float], ...])`(frozen) -- 정수는 `w_theta` 안 위치. 한 멤버는 묶음 하나에만 든다.
- 반환 `RealizedCell(m: tuple[int, ...], ratio_err: float, member_err: float)`(frozen) -- `m` = 멤버 순서 정수 손가락 수, `ratio_err` = 고른 벡터의 E1, `member_err` = 고른 벡터의 E2.
- 순수 함수(graph 읽기 0, 저장 0, 같은 입력 = 비트 같은 출력).

**계약 위반(ValueError -- 호출자 결함)**: `ratios`의 위치가 범위 밖, 한 멤버가 두 묶음에 듦, 묶음의 reference가 자기 output. **분류된 실패**: `w_theta`에 `not (w > 0)`(0·음수·NaN) 또는 비유한 값, 또는 `w_f_m`이 `not (w_f_m > 0)`·비유한 → `SealViolationError(devices=(), detail={"reason": "realize_tie_unresolved", "w_theta": w_theta, "w_f_m": w_f_m})`(호출자 DC 블록이 `devices` = 칸 멤버로 다시 올린다 -- §4).

**정의(이 꼴 그대로 -- 기대값도 같은 부동소수 꼴로 계산해 `==` 비교, 허용오차 상수 0)**:
1. `x_i = w_theta[i] / w_f_m`.
2. **단위**: 묶음마다, 그 묶음의 모든 k가 양의 정수(`float(k) == int(k) and k >= 1`)면 그 묶음 = 단위 하나: 선택 = m_d, 후보 = {⌊x_d⌋, ⌈x_d⌉} ∪ ⋃_j {⌊x_oj / k_j⌋, ⌈x_oj / k_j⌉}에서 1 미만은 1로 올린 집합(`max(1, math.floor(·))`, `max(1, math.ceil(·))`), m_oj = int(k_j)·m_d. k 가운데 하나라도 정수가 아니면 그 묶음 멤버는 모두 독립 단위다. 묶음 밖 멤버 = 독립 단위: 후보 {max(1, ⌊x_i⌋), max(1, ⌈x_i⌉)}.
3. 벡터 m(단위 선택의 곱집합 원소)마다 `r_i = m_i / x_i`, `e_i = abs(m_i - x_i) / x_i`(**|r − 1| 대신 이 꼴** -- 반정수 동률을 정확 산술과 맞춤, spec '원래 취지와 다름' 4).
4. 키 K = (E1, E2, E3, E4, E5): `E1 = max(r) / min(r) - 1`(max·min 먼저, 나눗셈 뒤 뺄셈), `E2 = max(e)`, `E3 = math.fsum(e)`, `E4 = sum(m)`(정수), `E5 = tuple(m)`(사전식). 답 = 곱집합에서 K 사전식 최소(파이썬 tuple 비교와 같은 순서).
5. **계산 꼴**(D40 6 단위 창 -- 구현이 곱집합을 펼치지 않아도 답은 4와 같아야 한다). 창 비교 `hi / v - 1 <= E1*`와 `E1(v) == E1*`는 E1*를 낸 식과 **같은 꼴 `hi / v - 1`**로 한다(`v * (1 + E1*)`와 `hi` 비교 금지 -- D40 v1.16.29 r-m2).

test 쪽 손 oracle = 위 1~4를 그대로 쓴 곱집합 전수 함수(test 파일 안에 둠 -- 피검 함수 아님).

- `groups` = ((role, members, status), ...)(`graph.matching_groups`의 `kind`·`members`·`status`), `mos` = MOS 이름 tuple, `position` = {이름: 정준 위치 int}, `kinds` = {이름: kind}, `start_w` = {이름: float(멤버 출발 W) 또는 why 문자열(`"reference_slice_undefined"` / `"no_member_density"` / `"no_partner"`(v6.39.5 -- 비쓰기 멤버가 I_i는 있고 짝이 없음, §3.3))}, `candidates` = {kind: 오름차순 키 tuple}, `defined(name, key) -> bool`(그 멤버의 출발점 조회가 그 슬라이스에서 정의되는가 -- VGS·VDS·VSB를 쓰는 판정), `reference` = {kind: 그 kind LUT 선언 기준 폭 슬라이스 키 int}(v6.39.5), `l_defined(name, key) -> bool`(v6.39.5 -- 그 멤버의 출발 L 값이 그 슬라이스의 L 축·bin 안인가: L 위치 판정만, 전압 인자 없음), `grid` = 아래 W_c 비교용 격자는 인자 `candidates`의 키 × `grid_m`(키워드 `grid_m: float`, 필수).

- **kind 섞임**: 한 칸에 kind가 둘 이상이면 `StructureUnresolvedError`(core) detail `{reason: "wf_cell_kind_mixed", members}`.
- **선택**(칸마다, 이 순서):
  1. **짝 없는 단일 멤버 칸**(v6.39.5): 칸 멤버가 하나(X)이고 `start_w[X] == "no_partner"`이면 r = `reference[kinds[X]]`; `r in candidates[kinds[X]]`이고 `l_defined(X, r)`이면 그 칸 키 = r(아래 2의 W 기준 선택을 거치지 않음, `defined`를 부르지 않음), 아니면 None, why `"reference_start_undefined"`.

  3. 아니면 W_c = 멤버 출발 W 최솟값; 후보 키 오름차순에서 (i) `key * grid_m <= W_c`이고 모든 멤버 `defined(name, key)`인 가장 큰 키 (ii) 없으면 모든 멤버 정의인 가장 작은 키 (iii) 없으면 None, why `"no_defined_candidate"`.
- **기록**(칸 순서, 한 칸에 하나): None 칸마다 `("wf_start_undefined", {"members": members, "why": why})`, 선택 1로 키가 정해진 칸마다 `("wf_start_reference", {"members": members, "w_key": r})`(출력 전용 -- 소비자 = 계획 M-FS1·N6.43 완료 (8) (b)). margin 없음. why 집합 = {`reference_slice_undefined`, `no_member_density`, `no_member_partner`, `no_defined_candidate`, `reference_start_undefined`}.

### 3.3 종속 멤버 출발 W와 짝 `start_partner` (`gmid_engine.search` 공개, 자리 `E/search/wf_partner.py`)

**v6.39.5(D40 §3.7-B 3 '짝')**: 옛 `kvl_partner(name, cell, …)`(칸 안 한정, L 비교 없음)와 출발 블록의 사적 대칭 짝 정의는 지운다(공개 이름 `kvl_partner` 없음 -- §7 G-8). 짝 = KVL 짝 ∪ 대칭 짝, 둘 다 있으면 KVL 짝.

`start_partner(name, mos, position, gate, source, bulk, kind, length, writers, groups) -> str | None`
- `mos` = 회로 MOS 이름 tuple(전부 -- 칸으로 거르지 않음), `position` = {이름: 정준 위치 int}(`device.dc_colour`), `gate`·`source`·`bulk`·`kind` = {이름: 넷/kind}(bulk = DEC-61 kind별 기본이 적용된 실효 bulk 넷), `length` = {이름: 출발 L 값(5의 L)}, `writers` = 출발 단계가 ln IDu 좌표를 두는 쓰기 소자 집합, `groups` = §3.2와 같은 ((role, members, status), ...).
- **KVL 후보** = `mos`에서 `name`이 아니고 `writers`에 들고 gate·source·bulk·kind가 `name`과 모두 같고 `length[o] == length[name]`(값 그대로, 허용오차 0)인 o. 있으면 그 가운데 `position` 최소를 답한다(대칭 짝은 보지 않음).
- **대칭 후보**(KVL 후보 없을 때만) = role ∈ {`diff_pair`, `branch_symmetric`}이고 status ∈ {`derived`, `ratified`}이며 `name`이 든 묶음들의 다른 멤버 가운데 `writers`에 드는 o(L·넷 비교 없음; role `mirror` 묶음은 대칭 짝을 주지 않음). 있으면 `position` 최소.
- 둘 다 없으면 None. 순수 함수, 저장 0. 출발 블록이 비쓰기 MOS마다 한 번 부른다.

### 4.2 탐색 평가 (`realized = None`, `layout = None`)
- 소자 m의 슬라이스 키 = m이 든 칸의 `wf.keys` 값; `DeviceOp.w_key` = 그 키. 쓰기·종속 소자 모두 선택 없음.

D-6 spy가 기록한 `ratios` 인자 = 모두 `()`.

## 5. front 이웃 시험 `polish_cells(sctx, solved, origin) -> (tuple[SolveResult], str)` (`gmid_engine.search` 공개, `polish_l_cells` 대체)

- 한 바퀴 순서: L 칸(기존 `sctx.domain.l_cells` 순서, MOS마다 −1, +1) → w_f 칸(칸 순서, 칸마다 그 kind `widths` 목록에서 지금 키의 바로 아래, 바로 위; 목록 끝이면 그쪽 건너뜀). 시험 평가 = 탐색 평가 1회(`evaluate(sctx, θ, cells, wf′, parent=base, origin=tag)` -- w_f 이동은 θ·L 칸 그대로, `wf′` = keys 한 원소만 바꿈).
- 수락·정지 = 기존 L-b와 같은 하나: 받아들일 상태이고 (목적 감소 또는 위반 합 감소)인 후보만 `solve_eps`(그 칸 벡터·그 `wf′`로 시작한 `StartPoint`) 재시작, 그 축 분해능 한 칸 이상 개선이면 수락하고 다음 바퀴; 한 바퀴 수락 없음 = 끝; 예산·벽시계 = 기존 `search_stop`. 정지 사유 문자열 = 기존 셋(`converged`·`eval_budget`·`wall_budget`).
- origin 태그: L 이동 = 기존 (`("stage", STAGE_L_SEARCH)`, `("device", mos)`, `("move", ±1)`), w_f 이동 = (`("stage", STAGE_L_SEARCH)`, `("wf_cell", 칸 index)`, `("move", ±1)`).
- `perf` 출력 전용 칸(find_front runs 줄): `wf_neighbor_evals`(w_f 이동 시험 평가 수), `wf_neighbor_wall_s`(그 평가 벽시계 합).
- 분지(W-c): `sweep_front`는 (L 칸 벡터, `wf.keys`)가 다른 시작점을 다른 분지로 다룬다.
