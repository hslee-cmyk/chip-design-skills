## 의도

TS6(계획 N3.11), design `20-dead-code-dup` v1.2 §5.1의 셋째 줄: `probe_physical_consistency`를 승격한다. 이 probe는 절이 셋이고
성격이 다르다(원문 확인 2026-09-23) -- **B7-(i)**(노드전압 전파를 순회 순서를 바꿔 두 번 돌려 결과가 같은지), **B8**(노드별 KCL 잔차),
**B9**(`vs` 필드 일관성). 앞의 둘은 판정할 수 있는 성질이라 승격하고, **B9는 옮기지 않는다** -- 읽는 필드가 `vs`에서 `vsb`로 바뀌어 지금은
전 소자가 0으로 읽히고(무동작), 원문도 "`vs`의 정의와 의도는 회로 해석이라 사용자 확인 필요"라고 적는다. A = `skills/analog-gmid-design/assets`.
code 커밋이 없다(test-only).

## 관찰 가능한 계약

1. `A/tests/unit/test_probe_physical_consistency.py`가 생기고 `A/tests/probe_physical_consistency.py`가 없어진다. 이름은 P3a 승격 규칙
   `unit/test_<probe 파일 이름>`을 따른다 -- P1·P3a 계약 test가 이 규칙으로 승격본을 센다(2026-09-29 착수 전 개정, P3b 1차 시도 실패와 같은 결함).
2. **B7-(i) 승격**: 노드전압 전파가 **순회 순서에 의존하지 않는다**를 판정한다. 원본처럼 순서를 바꿔 두 번 돌리고 결과 노드전압이 같아야 한다. 다중 도달 불일치가 있으면 그 목록이 판정에 나온다(조용히 넘어가지 않는다).
3. **B8 승격**: 노드별 KCL 잔차가 **선언된 허용 범위 안**이어야 한다. 임계값을 새로 지어내지 않는다 -- 엔진이 이미 쓰는 판정(`_metric_kcl_residual`의 기준)이나 spec 선언에서 읽고, 읽을 곳이 없으면 그 사실을 보고하고 멈춘다(WP-03 숫자 금지).
4. **B9는 옮기지 않는다**. 판정 기록과 test 파일 docstring에 사유를 적는다(읽는 필드가 바뀌어 무동작, 정의는 회로 해석 대상).
5. **하드코딩 제거**: 원본이 레일 집합(`{"vdd","VDD"}`·`{"gnd","GND","vss","VSS"}`)과 `VDD = 1.8`을 상수로 다시 선언한다. 승격본은 이것을 **선언에서 읽는다**(topology의 `supply_nets`, spec의 공급 전압). 읽을 수 없으면 그 회로는 판정 대상에서 빼고 사유를 남긴다. 이것은 복제 제거가 아니라 회로 종속 리터럴 제거이고, 미래 topology에서 레일 이름이 다를 수 있기 때문이다(design §6.4 G-3 (b)와 같은 취지).
6. 원본이 읽던 `instance.json` 절대 경로는 파일 위치 기준 상대 경로로 바꾼다.
7. 승격한 test는 기본 순서와 `--shuffle-seed` 1~5에서 통과한다. 실패하면 test를 약화하지 말고 멈추고 보고한다(엔진 결함 가능성).
8. 엔진 소스와 다른 test는 바뀌지 않는다. 수집 집합은 base에서 사라진 id 0.

## oracle 종류와 출처

(b)·(d): B7-(i)의 기대는 "같은 입력에 순회 순서만 바꾸면 결과가 같아야 한다"는 결정성 성질이고, B8의 임계값은 엔진·spec 선언에서 읽는다(계약 3). 엔진 출력을 기대값으로 박지 않는다.

## 거부해야 할 입력

순회 순서에 따라 값이 갈리는 합성 넷리스트(B7-(i) 판정이 거부해야 한다), 잔차가 허용 범위를 넘는 합성 사이징(B8 판정이 거부해야 한다), 레일 이름이 선언과 다른 합성 topology(계약 5의 '선언에서 읽기'가 실제로 발동하는지).

## library 회로 적용 여부

원본은 파일럿 하나를 읽는다. 승격본은 **사이징 산출물이 있는 회로 전부**로 넓힌다(읽을 산출물이 없으면 그 회로는 빼고 사유를 남긴다). 레일 이름이 회로마다 다르므로 계약 5가 여기서 실제로 검증된다.
