## 관찰(사실 표지, 판정 기준 아님)

- **o2 물리 사실**(LM-1d 판정 관찰 o2, A-137): nmos 여러 슬라이스에서 같은 모델 bin 안 중점 L의 \|ID\|가 두 앵커 \|ID\|보다 크다(같은 bin 안 L 비단조 -- 예: 7 µm L 0.165 µm 1094/23520점, 앵커 범위 밖 최대 상대 38%; pmos 0점). 그 셀의 L 보간 오차(외부 값)가 커지고 tol_V가 커지는 것은 **정의대로**다(물리 사실이고 생성기·데이터 결함 아님). 이 card는 그 값을 줄이거나 자르지 않는다. 판정자는 완료 조건 3·8에서 tol_V가 큰 슬라이스를 이 관찰과 맞춰 기록한다.
- **`edge_costs` bin 전부 None**: 그 bin 값 = inf(as-built `per_l` min, `headroom_bound` 폭 −inf → 그 bin 닫힘). LM-1d 뒤 발동 0. 꼴 재검토는 LA-1 재점검 입력(`wt/_drafts/la1_auto_decisions.md`).

## 원래 취지와 다름

1. **옛 중점 적재의 `L_source` 대조 삭제**: 옛 reader는 중점 meta `L_source` sha256 = 기준 LUT `L_source` sha256(승인 L 파일 같은 판)을 대조했다. LM-1d 데이터는 슬라이스 생성기 산출이라 meta에 `L_source`가 없고(stub sha만), 재생성은 O-242 '1회' 밖이다(A-134). 대신 **생성기 sha256 = manifest 값**(N3.6 '그 슬라이스 앵커와 같은 생성기'를 직접 대조), 모델 파일·시뮬레이터 판·조건 = 짝 슬라이스, 위치 선언 raw sha256(LM-1d가 승인 L 목록과 제조 격자를 관문 (b)로 확인하고 출처 기록에 남긴 파일 그 자체)으로 받는다. 승인 L 목록과의 직접 대조는 엔진에서 빠진다 -- 판정자 확인 항목.
2. **새 적재 거부 사유 셋**(`lut_midpoints_slice_unmatched`, `lut_midpoints_duplicate`, `lut_midpoints_source_mismatch`): 계획 LM-1e 3 '새 사유 이름 0'은 **판정 갈래** 범위로 읽었다(적재 스키마 거부는 판정 사유가 아님). 사유를 기존 이름으로 합치면 짝 없음·중복·출처 어긋남이 한 사유로 섞여 fail-closed 원인을 가르지 못한다.
3. **계획 문언 '봉인 3·4의 노드 셀 집계'**: N3.6 표에서 봉인 4 = 버전 일치(tol 안 씀)이고 노드 셀 max 집계는 봉인 1(노드 충돌)·3(KCL)이다. 이 card는 **봉인 1·3**으로 읽고 toy를 쓴다(봉인 8 `kvl_branch`는 하나라도 None이면 undefined라 바로 (a)). 계획 문언 정정은 오케스트레이터 몫(계획 정정 대기 -- 재점검 입력).
4. **U-87 보존 집합의 옛 꼴 읽기**: 위치 선언 reader는 옛 단일 객체 꼴을 거부하지만, 디스크 캐시 정리의 보존 집합 계산(`_config_data_id`)은 다른 worktree(master 등)의 옛 꼴 설정을 그 꼴의 옛 자료 id로 계속 읽는다 -- 안 그러면 WB-1 + LM-1e 병합 전까지 다른 worktree의 살아 있는 표 칸이 지워지거나 정리가 failsafe로 꺼진다. 데이터 적재 경로가 아니라 파일 이름 id 계산이다.
5. **기준 폭 중점 값 교체**: 기준 폭 슬라이스의 앵커 2개 bin 행이 옛 기준 생성기 중점에서 DC 슬라이스 생성기 중점으로 바뀐다(LM-1d 대조 784셀 차/문턱 최대 4e-5 -- A-137). 기준 폭 셀 값이 상대 1e-5 수준으로 바뀐다(완료 조건 4).
6. **toy 기대 변화**: 중점 없는 앵커 2개 bin을 가진 합성 LUT test의 그 앵커 행 기대가 값 → None(정의대로, 기준 약화 아님 -- P N6.40 LM-1e 2). 목록 = interface §8.
7. 계획 문언의 card +1(O-242 승인), 위임 A-63 Q-DC3 (나) 철회 -- 계획 N6.40 근거 그대로.
