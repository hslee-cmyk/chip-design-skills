- **o2 물리 사실**(A-137): nmos 여러 슬라이스에서 같은 모델 bin 안 중점 L의 \|ID\|가 두 앵커보다 크다(같은 bin L 비단조 -- 예: 7 µm L 0.165 µm 1094/23520점, 최대 상대 38%; pmos 0점). 그 셀의 L 방향 값이 커지고 tol_V가 커지는 것은 **정의대로**다(SPICE 모델 사실, 생성기·데이터 결함 아님). 이 card는 줄이거나 자르지 않는다.

## 원래 취지와 다름

1. **옛 중점 적재의 `L_source` 대조 삭제**: 옛 reader는 중점 meta `L_source` sha256 = 기준 LUT `L_source` sha256을 대조했다. LM-1d 데이터는 슬라이스 생성기 산출이라 meta에 `L_source`가 없고, 재생성은 O-242 '1회' 밖이다(A-134). 대신 생성기 sha256 = manifest 값(N3.6 '그 슬라이스 앵커와 같은 생성기'를 직접 대조), 모델 파일·시뮬레이터 판·조건 = 짝 슬라이스, 위치 선언 raw sha256(LM-1d가 승인 L 목록·제조 격자를 관문 (b)로 확인한 파일 그 자체)으로 받는다. 승인 L 목록과의 직접 대조는 엔진에서 빠진다 -- 판정자 확인.
2. **새 적재 거부 사유 하나**(`lut_midpoints_slice_unmatched` -- 중점 파일의 (meta `device`, 폭 키) 짝 슬라이스 없음): 계획 v6.38.25 '새 사유·기록 이름 0'·오케스트레이터 지시 '기존 이름 우선'에 따라 나머지는 기존 이름으로 합쳤다 -- 같은 (kind, w_key) 둘 = `lut_slice_duplicate`(detail `set: "midpoints"`), 생성기·모델 파일·시뮬레이터 판·corner·temp_c 어긋남 = `lut_conditions_mismatch`(detail `key` = 어긋난 항목 -- 지금 이 사유가 쓰는 꼴), 결측 = `bin_missing_external`. 짝 없음은 기존 이름에 같은 정의가 없다(`lut_device_undeclared` = 선언 밖 장치, `lut_slice_missing` = manifest 파일 없음 -- 다른 정의). ⚠ 이름 하나 추가 -- 판정 대상(대안: `lut_device_undeclared`로 합치면 '선언 밖 장치'와 '짝 슬라이스 없음'이 한 사유로 섞인다).
3. **계획 문언 '봉인 3·4' → '봉인 1·3'**: 계획 v6.38.25가 고쳤다(옛 초안 지적 반영) -- 이 card는 v6.38.25 문언 그대로.
4. **U-87 보존 집합의 옛 꼴 읽기**: 위치 선언 reader는 옛 단일 객체 꼴을 거부하지만, 디스크 캐시 정리의 보존 집합 계산은 다른 worktree(master 등)의 옛 꼴 설정을 그 옛 자료 id로 계속 읽는다 -- 안 그러면 통합 병합 전까지 다른 worktree의 살아 있는 표 칸이 지워지거나 정리가 failsafe로 꺼진다. 적재 경로가 아니라 파일 이름 id 계산이다.
5. **계획 6 (1) 'base = red' 문언과 다름**: 판정 갈래 3의 집계 규칙은 WB-1 `e6bb22bd`(A-139)가 이미 구현해 이 card base에서 green이다. 이 card의 3 toy는 회귀 고정이고 red-green 증거가 아니다(계획 문언 정정 대기 -- 오케스트레이터 몫).
6. **기준 폭 중점 값 교체**: 기준 폭 슬라이스의 앵커 2개 bin 행이 옛 기준 생성기 중점에서 DC 슬라이스 생성기 중점으로 바뀐다(LM-1d 대조 784셀 차/문턱 최대 4e-5 -- A-137).
7. **toy 기대 변화**: D7 영향 7(+조건부 3)은 적재 거부 → 중점 추가·적재 인자 조정(정의대로, 기준 약화 아님 -- P N6.40 LM-1e 2). 단언 대상과 기대값은 바꾸지 않는다.
8. 옛 초안(`781fdd66`)의 런타임 `missing_external` 앵커 행 None 갈래·Q-T0 조건부 표지·그 toy(옛 T-2~T-5, J-a~J-d의 중점 결측 원인)는 O-246 D7로 철회했다.
