## 의도

TS7(계획 N3.11)과 `00-common` CC-3: 계약 test IC1~IC11의 뼈대를 Phase 1에서 선언하고, 담당 Phase 전에는 conftest가 계획서 N4.1 표로
xfail을 만든다. conftest에 `--gmid-phase`·`--gmid-strict`·`--gmid-dod` 옵션과 `gmid_ic` 표식을 둔다. 표식과 계획서의 대조 test를 둔다.
정본 명세는 design `10-test-separation` v1.2 §5.4 'C6에서 만드는 것'·§6.5·§9 C6 행, 의미의 정본은 `00-common` §8.1·§9.3.

## 관찰 가능한 계약

1. `A/tests/conftest.py`: design §5.4 'C6에서 만드는 것' 그대로 -- `pytest_addoption`(`--gmid-phase=`·`--gmid-strict=`·`--gmid-dod`, `=` 한 토큰), `pytest_configure`(표식 `gmid_ic(ic, *, phase, case)` 등록, `--gmid-phase` 없음·계획서 `phase_order` 밖이면 `pytest.UsageError`), `pytest_collection_modifyitems`(`00-common` §9.3의 xfail 조건·reason·엄격 대상·모르는 케이스 키 거부; 빈 `--gmid-strict=`는 키 없음). `read_plan_tables`는 `tools/gates/merge_gate.py`를 import(`<저장소 루트>/tools/gates`를 `sys.path` 끝에).
2. `A/tests/contracts/test_ic1.py`~`test_ic11.py`: design §6.5 선언 목록의 함수 이름·표식 `(phase, case)` 그대로. 본문은 IC3·IC5 포함 전부 `pytest.fail()` 한 줄(인자 없음). 케이스가 둘 이상이면 `pytest.param(..., marks=pytest.mark.gmid_ic(...))`.
3. `A/tests/contracts/test_ic_markers_match_plan.py`: 계획서를 `read_plan_tables`로 읽고 contracts 파일을 AST로 읽어 IC 11개 모두 표식 phase 집합 = 계획서 `ic_parts[IC]`의 phase 집합을 단언하고, 합성 소스(계획서에 없는 Phase를 단 함수, 계획서 Phase에 표식이 없는 함수)에서 판정기가 실제로 거부함을 단언한다.
4. `--gmid-phase=1`로 전체 test를 돌리면 기존 test는 PASS, 뼈대 11개(케이스 포함)는 xfail(비엄격), 대조 test PASS, 수집 오류 0. `--gmid-phase` 없이 돌리면 `UsageError`.
