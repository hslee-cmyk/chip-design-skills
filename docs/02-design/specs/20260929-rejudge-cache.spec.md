## 의도

세션 시작 hook(`hooks/role_session_start.py`)이 2026-09-29 실측으로 348초 걸린다(cProfile: 347초가 `integrity.row3b`, accept-log 86구간
× (게이트 코드 추출 + `merge_gate.py receive` 한 번), Claude Code 명령 hook 기본 제한 600초의 58%). 행 3(나) 구간 재판정이 세션마다
전 구간을 다시 돌기 때문이고, 비용은 병합마다 한 구간씩 늘어 결국 세션 시작이 제한시간에 걸린다.

이 변경은 design 05 §3.3 행 3(나) 개정(2026-09-29)대로 **재판정 통과 캐시**를 둔다: 재판정을 통과한 `(old, new)` 쌍을
`<git-common-dir>/gmid-gate-cache/rejudged`에 적고 다음 세션부터 건너뛴다. 로그 마지막 줄은 캐시와 무관하게 항상 재판정한다.
review31 N-06(캐시 한 줄로 마지막이 아닌 위조 구간 재판정을 건너뛰게 함)은 §13.5 알려진 한계로 재분류했다(사용자 결정 2026-09-29).
행 3(가) 사슬 대조, 행 1·2·4·5·6, 재판정 자체(`receive` 판정)는 바꾸지 않는다.

게이트 변경이라 반영 뒤 §13.4 재설치가 필요하다(사용자: gate에 `tools/gates/gate/*` 복사, `.claude/hooks/role_*` 갱신,
`integrity.py check --scope session`). 재설치 직후 첫 세션은 캐시가 비어 전 구간을 한 번 재판정한다(지금과 같은 시간).
반영 push와 재설치 사이의 fail-closed는 정상이다.

## 관찰 가능한 계약

`C` = `<git-common-dir>/gmid-gate-cache/rejudged`(`role_paths.CACHE_DIRNAME` 아래, 이름 `rejudged`). 줄 형식 `<old 40자리> <new 40자리>`.
"재판정" = 그 구간에 대해 old 판 게이트 코드의 `merge_gate.py receive`를 실행하는 것(지금 `integrity.row3b`의 동작).

1. `integrity.check("session", …)`에서 재판정이 통과한 구간 `(old, new)`는 대조가 끝난 뒤 `C`에 한 줄로 있다.
2. `C`에 있는 구간은, 그 구간이 accept-log의 **마지막 줄이 아니면** 재판정하지 않고 통과로 본다.
3. accept-log 마지막 줄의 구간은 `C`에 있어도 재판정한다. 재판정이 실패하면 행 3b는 `ok: false`다(지금과 같음).
4. 재판정이 실패한 구간은 `C`에 적지 않는다. `C`에 적힌 구간이더라도 마지막 줄이라 재판정해 실패하면 `C`에서 뺀다.
5. `C`의 형식이 깨진 줄(필드 수·16진 40자리 위반)과 현재 accept-log에 없는 쌍은 무시하고, `C`를 다시 쓸 때 남기지 않는다
   (`C`의 줄 수 상한 = accept-log의 old != new 줄 수). `C`가 없거나 읽을 수 없으면 전 구간을 재판정한다(지금과 같음).
6. 행 3b의 출력 행: 재판정한 구간은 지금처럼 구간마다 한 행이다. 캐시로 건너뛴 구간이 1개 이상이면 `ok: true`인 요약 행 하나를
   더하고, 그 `actual`에 건너뛴 구간 수가 `캐시 통과 <k>구간` 형태로 나온다. 재판정할 구간이 하나도 없는 경우는 지금과 같다.
7. `C` 쓰기는 임시 이름 + 원자적 이름 바꾸기로 한다(중간에 죽어도 반쯤 쓴 `C`가 남지 않는다). `role_paths.ensure_cache`는 `C`를 지우지
   않는다(지금 지우는 대상은 40자리 16진 디렉터리와 `.tmp-` 접두뿐).
8. `C`는 `--scope session`의 행 3b만 읽고 쓴다(행 3b는 다른 scope에 없다 -- 지금과 같음).

## oracle 종류와 출처

(a) 구성으로 정답이 정해진 합성 입력: 임시 gate 저장소(`run_all.py --mode direct`의 임시 gate와 같은 방식)에 accept-log와 구간을 만들고,

적어 둔, 재판정하면 실패할 위조 구간)으로 관찰한다 -- 피검 코드 출력에서 기대값을 만들지 않는다. test 위치는 `tools/gates/redteam/`
(게이트 변경의 판정 기준 경로, 쓰기 경로표 N3.12.2).

## 거부해야 할 입력

행 3b가 계속 `ok: false`여야 하는 입력(드러나게 하는 동작 유지):
* 마지막 줄이 재판정 실패인 위조 구간(공격 22 c) -- `C`가 비었을 때와 `C`에 그 구간을 적어 둔 때(공격 22 f의 기록된 형태) 모두.
* `C`에 없는, 마지막이 아닌 위조 구간.
* `C`에 형식이 깨진 줄·현재 로그에 없는 쌍만 있고 위조 구간 자체는 없는 경우의 위조 구간.
알려진 한계(§13.5, 기록 케이스 -- 거부 기대 아님): `C`에 적어 둔, 마지막이 아닌 위조 구간은 행 3b가 건너뛴다.
