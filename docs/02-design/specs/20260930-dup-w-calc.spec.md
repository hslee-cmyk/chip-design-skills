## 의도

design `20-dead-code-dup` v1.2 §3 DIFF-DUP·§6.1·§8 P8: 소자 폭 식 **W = L·ID/IDu**(방법론 식 1.18 -- 단위 폭 전류밀도 IDu에서 폭을 얻는 식)가
엔진 곳곳에 인라인으로 흩어져 있다. 정의를 하나로 모아 엔진이 바뀔 때 같이 따라가게 한다(WP-14). 이 식은 회로·넷·소자 이름을 읽지 않는
물리 식이라 topology 무관이다. A = `skills/analog-gmid-design/assets`.

**통합 방향(design §6.1 정정)**: design은 "6곳을 `size_transistor` 호출로"라고 적었지만 (1) 인라인은 실측 18곳이고 (2) 대부분 IDu를 이미
`_sizing_bundle` 배치 조회·`id_density_at_vgs` 등으로 얻은 핫루프 안이라, `size_transistor`(gm·gm/ID를 받아 IDu를 다시 조회)를 부르면 LUT 재조회가
생기고(수정마다 재계산 비효율 점검 원칙) (3) 정해진 VGS의 IDu로 W를 구하는 곳은 `size_transistor`와 다른 질문이다(P4 실측). 그래서 **식 함수를 추출**한다 --
새 함수 `sizing_recipe.width_from_id_density(L, ID, IDu)`가 `L * ID / IDu`를 돌려주고, `size_transistor`와 18곳이 이것을 부른다. 가드(`IDu <= 0` 처리)는
각 호출부에 지금 있는 그대로 둔다(함수는 가드를 더하지 않는다 -- 동작 보존).

대상(2026-09-30 base 실측, `sizing_recipe.py` 줄):
`size_transistor`(101), `find_optimal_sizing`(878), 1579, 2057, 2575, 3456, 3470, 3534, 3557, 3684, 5564, 5758, 6770, 7149, 7346, 8700, 8765, 8841.
대상이 아닌 비슷한 모양: `L * L / idu`(2166, 면적 대용 L²/IDu -- 다른 양), `raw * L / self._w_ref_effective(L)`(568·594, IDu 자체를 만드는 식), docstring·주석.

## 관찰 가능한 계약

1. **새 함수** `width_from_id_density(L: float, ID: float, IDu: float) -> float`(신규 시그니처 표)가 `sizing_recipe`에 있고 `L * ID / IDu`를 돌려준다.
   임의의 유한 float 입력에서 그 결과는 인라인 식 `L * ID / IDu`·`ID * L / IDu`와 **비트 단위로 같다**(IEEE 곱셈은 교환적이다).
2. **W 식 인라인 0**: 엔진 `A/*.py`·`workspaces/run_harness.py`에서 다음 모양의 산술식이 `width_from_id_density` 본문 밖에 0개다 --
   `(a * b) / c`에서 `c`의 이름(변수 이름, 속성 이름, 또는 문자열 첨자 키)이 대소문자 무시 `idu`를 포함하고, `a`·`b` 중 하나가 **L 계열**, 다른 하나가
   **ID 계열**인 것. L 계열 = 앞의 밑줄과 앞의 소문자 `m` 하나를 뗀 이름이 `L`이거나 `L_`로 시작하거나 `L` 뒤에 숫자 또는 `c`만 오는 것
   (예: `L`, `_L`, `mL`, `L_m`, `L_up`, `L2`, `Lc`, 첨자 키 `"L"`). ID 계열 = 이름이 `ID`를 포함하거나 `I`와 같은 것(예: `ID`, `ID_target`, `ID_m`, `ID2`,
   `I`, 첨자 키 `"ID"`). base에서는 18개다.
3. `size_transistor`도 새 함수를 부른다(정본의 정본). 시그니처·가드·반환 불변.
4. **동작 보존**: E-LIB(library 로드 가능 회로 전부)·E-INST(파일럿·`folded_cascode` instance.json)가 base와 같다. 전체 스위트 결과가 base와 같다.
5. **성능**: E-INST 두 회로의 실행 시간을 base와 병합본에서 재서 기록한다(관찰값 -- 임계값을 박지 않는다).
6. **레지스트리 §2 W 계산 행**: 정본 칸을 `width_from_id_density`(식)와 `size_transistor`(gm·gm/ID 입력 경로)로, 중복 칸을 실측(인라인 18곳 통합 완료, 옛 목록
   `feasible_gm_ids`·`search_gm_id_for_role`·`feasible_L_window`는 현 소스와 맞지 않았음)으로 고친다. 정해진 VGS의 W는 같은 식을 쓰는 다른 입력 경로다(P4).
