### N6.30 card CMP-1 -- 엔진 대 AI 손계산+SPICE 비교(평가, 사용자 결정 O-147)

**근거**: 사용자 결정 O-147(2026-10-26 "이 실험을 계획에 넣자.", `_drafts/user_decisions.md` O-147 행) -- 엔진 결과의 의미를 숫자로 확인하는 비교 실험. 원칙으로 정한 기본안(원래 취지와 다름 없음 -- 새 항목).

**성격**: 평가 보고이고 게이트가 아니다. card LA-1 완료 조건에 넣지 않는다(엔진 판정 기준이 비결정적인 AI 기준선 결과에 기대지 않게 -- 작성자≠검증자, 기준 약화 금지). 결과 해석과 엔진 방향 결정은 사용자 몫이다. 이 card는 엔진 graph 필드·cache·사본을 만들지 않는다(엔진 코드 변경 0). C′ 경로 완료 게이트는 이 card가 아니라 card CPG-1(v6.38.2 -- O-164, 기준 = H0r 기준선 기록)이다.

**범위**:

1. **비교 대상**: (A) AI 손계산 출발 → SPICE 수정 반복, (C) 엔진 front → oracle 판정. 같은 library 회로·같은 spec·같은 PDK/LUT·같은 oracle을 쓴다. heldout 회로는 근거로 쓰지 않는다.
2. **공정성**: (A)의 SPICE 예산 = (C)가 그 회로에서 oracle로 판정한 **설계점 수**(단위 = SPICE로 평가한 사이징 후보 점, ngspice 호출·해석 수 아님 -- 상대 예산, 새 상수 없음; v6.38.1 사용자 결정 O-157(2026-10-26, `_drafts/user_decisions.md` O-157 행) S8 -- O-147 보충, 옛 '(A)의 SPICE 실행 예산 = (C)가 그 회로에서 쓴 oracle 실행 수'는 단위가 달라 사실상 무제한). (A)는 점마다 그때까지의 최선(통과 여부·전력·면적)을 기록한다(궤적).
3. **독립성**: (A)는 엔진 출력·코드·`wt/_drafts/evidence`·`wt/_scratch_*` 기록과 원문 논문의 사이징 표·소자 값을 보지 않는 별도 agent가 만든다(회로 연결·spec·PDK/LUT만 -- O-157 S8). 판정은 감사 agent가 같은 oracle로 한다.
4. **항목**: 회로마다 spec 통과 여부, 통과점의 전력·면적(같은 spec 아래), 소요 시간, 재현성(엔진 2회, (A) 독립 세션 2회). 보고에 'library = 엔진 개발 표본(in-sample)' 단서와 비교에 쓴 spec 판(커밋)을 적는다; (C) 비교점 고르는 규칙(비지배 집합 대 집합)은 평가 절차 문서 몫이다(O-157 S8).

**순서**: 선행 = card LA-1 병합. 착수 조건 = 계획 v6.38 승인 → 비교 회로의 선언 spec 항목마다 oracle 판정이 구현됨(SR = OP-10 추종 판정, 정착 = AP-1·oracle `settle_s`; 아니면 그 항목을 판정 불능으로 표기한 부분 비교 -- O-157 S8) → 평가 절차 문서(회로 목록·기록 형식). 결과는 감사 agent 판정 기록으로 남기고 사용자에게 올린다. **시범**(v6.38.1 사용자 결정 O-161(2026-10-27 "권고 가로 해보자", `_drafts/user_decisions.md` O-161 행) -- zip gm/ID harness(AI 의도 YAML + 격자 전수탐색 + ngspice 확인)를 (A) 쪽으로 써서 library 회로 2개에서 엔진(C)과 같은 spec·같은 판정으로 비교하는 CMP-1 시범을 LA-1 전에 실행; **원래 취지와 다름(승인 O-161)**: O-147은 LA-1 병합 뒤): 시범은 정식 CMP-1 card를 대신하지 않는다(정식 CMP-1은 위 순서대로 LA-1 뒤); 결과 = `wt/_drafts/evidence/2026-10-27/cmp1_pilot_judgment.md`(진행 중) -- 평가 보고이고 게이트가 아니며, 독립성(범위 3)·heldout 금지·in-sample 단서는 그대로 적용한다. design v1.15 재개정은 시범 판정 뒤 착수(O-162).
