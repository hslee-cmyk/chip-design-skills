# graph-consumption Planning Document

> **Summary**: graph 필드가 만들어진 그대로 실제로 쓰이게 하고, KVL·KCL 관계를 graph에 한 번만 두어 엔진 계산과 결과 검증이 그 정본을 읽게 한다. 네 갈래다.
> 1. **구조 규칙 L(규칙 L-1~L-5)**: writer 밖 실제 읽기, 출력 전용 선언과 진입점 도달, 블랭킷 READS 금지, 하위 칸 reader, 정본 술어 재계산 거부. 기존 위반은 card id를 붙인 **줄어들기만 하는 목록**(부채 목록)에 둔다.
> 2. **필드별 처리**: 문서·계획이 소비자를 지정한 필드는 그 소비자에 배선하고, 정본 우회 재계산(R1·R2)은 정본 읽기로 바꾸며, 나머지는 출력 전용 선언 또는 삭제(삭제는 사용자 승인)한다.
> 3. **KVL·KCL 관계 단일 정본**: 엔진이 실제로 푸는 관계(쓰기 계획의 종속 사이클, 전류 기저)를 정본으로 두고, 쓰이지 않는 S1 관계 사본(`rel_kvl_branch`·`gvgs_summary`·`rel_kcl_group`·`rel_vds_eq_vgs` 등)을 지운다. 봉인 8은 엔진이 실제로 종속시킨 사이클 전부를 읽는다.
> 4. **결과 검증의 독립성**: 봉인 3이 기저 결선을 S1 `dc_nets`와 대조하고, 공급 전류 합을 판정하며, MNA 풀이 잔차를 기록한다. 출발 전류의 조용한 자리값 대체는 충돌 기록으로 바꾸고 기저를 거친다.
>
> **Project**: chip-design-skills (analog-gmid-design skill) · **Author**: Claude Code
> **Status**: **계획 v0.1 -- 초안**(2026-10-16). 독립 검증과 사용자 승인 전이다. 착수 근거는 사용자 결정 O-10 (2)(`wt/_drafts/user_decisions.md` 628행)이다. 다음 단계는 독립 검증 → 사용자 결정(N10.2) → GC-0(card 0 측정) → GC-D(상위 문서 개정 → design)다.
>
> **이력**: 경위, 재측정 근거, 검증 반영 기록은 [graph-consumption.history.md](graph-consumption.history.md)에 있다.
> **상위 계획**: [gain-budget-gmid-sizing.plan.md](gain-budget-gmid-sizing.plan.md). 상위 원칙(N1.4 NFR, N2 결정, N6.3 병합 전 확인)을 따른다. 관계는 N2 표, 상위 문언과 다른 곳은 N5와 N3.10에 있다.

## N1. 목적·범위·요구

### N1.1 목적

사용자 2026-10-16 원문: "code를 작성할 때 계산식을 작성하여 값을 얻는 대상이 이미 graph에 계산되어 있는지를 확인하고 계산식을 사용하여 작성하게 해. 원래 graph를 완성하여 계산되어 있다면 KVL과 KCL이 항상 성립해야 겠지만, 이 KVL과 KCL에 따라 계산을 수행하는 엔진에서는 이 계산을 수행하여 결과를 내야 하는거지. 이 관계가 엔진에 적용되어 있는지도 확인해."

재측정(history H2)의 결론은 다섯이다.
* 필드 131개 가운데 writer 밖 실제 읽기가 0인 필드가 26개다(test만 읽음 24, 아무도 안 읽음 2). 출력 전용인데 선언이 없거나 출력 함수가 진입점에서 도달하지 않는 필드가 4개다.
* 엔진은 KVL·KCL을 **실제로 풀어** 결과를 낸다. KVL은 노드전압 정식화와 쓰기 계획 신장 숲으로, KCL은 유리수 전류 기저로 푼다(F-G4·F-G5). 그런데 그 관계를 graph S1 관계 필드에서 읽지 않고 커널 쪽에서 따로 다시 만든다. S1 관계 필드(`rel_kcl_group`, `rel_vds_eq_vgs`, `rel_matching_ratio`, `rel_matching_offset`, `gvgs_summary`)는 엔진 소비자가 0이고, `rel_kvl_branch`는 봉인 8만 읽으며 쓰기 계획과 정의가 다르다(F-G6·F-G7).
* 결과 검증 쪽에서는 봉인 8이 S1 사이클 목록만 돌아 엔진이 실제로 종속시킨 사이클과 목록이 다를 수 있다. 사이클이 0개인 회로에서는 행이 0이다(공허 통과). 봉인 3은 결선을 기저 출력에서 그대로 받는다. 공급 전류 합과 MNA 풀이 잔차는 판정되지 않는다(F-G8~F-G11).
* 출발 구간은 θ 전류가 0 이하이거나 정해지지 않은 소자에 소자별 자리값을 둔다. 그 자리값은 KCL 기저를 거치지 않는다(F-G12).
* 정본 술어를 핀에서 다시 계산하는 곳이 있다(diode 판정, (gate, source) 묶음, F-G13).

이 기능의 목표는 다섯이다.
1. 구조 규칙 L로 '만들고 안 쓰는 필드'와 '정본 우회 재계산'을 기계적으로 거부한다. 기존 위반은 부채 목록으로 시작해 줄어들기만 하게 한다.
2. 위반 필드마다 원칙대로 처리한다(배선, 정본 읽기, 출력 전용 선언, 삭제).
3. KVL·KCL 관계를 엔진이 실제로 푸는 형태로 graph에 한 번만 둔다. 계산과 검증은 그 정본을 읽고, 쓰이지 않는 사본은 지운다.
4. 결과가 KVL·KCL을 만족하는지 계산 경로와 독립된 경로로 확인한다.
5. 계산 결과가 바뀌지 않아야 하는 곳에서는 base와 비트 동일함을 보인다.

### N3.1 구조 규칙 L

모든 하위 규칙은 AST만 쓴다(엔진 import·실행 없음). 형식은 기존 규칙 A~K와 같다. 정적으로 풀지 못하면 위반이다(fail-closed).

1. **규칙 L-1 reader 존재**
   * 판정: 권한표(F-G1의 두 표)의 (kind, field)마다, writer 블록 함수 밖 엔진 코드(tests 제외)에 실제 읽기가 1곳 이상 있어야 한다.
   * 필드 인자는 상수 해석으로 푼다. 모듈 수준 tuple을 도는 루프 변수는 그 tuple로 펼친다.
   * 동적 필드 접근은 고정 파일 목록(core 접근자와 봉인 판 검사)에서만 허용한다. 그 밖의 동적 접근은 위반(`field_arg_dynamic`)이다.
   * 읽기로 치지 않는 것: READS 선언, 실행 스냅샷 전체 덤프, 이름이 같은 다른 객체의 속성(예: 선언 객체의 `.value` 속성 -- 재측정에서 1건 확인, H2-1).
2. **규칙 L-2 출력 전용 선언과 도달**
   * 판정: 실제 읽기가 모두 출력 모듈에 있으면 그 필드는 출력 전용 목록에 있어야 한다. 목록 항목은 (필드, 출력 함수, 근거)다.
   * 출력 함수는 엔진 진입점(단계 A·B, 탐색 진입점, 수렴 진입점)에서 호출 그래프로 도달해야 한다. 도달을 풀지 못하면 위반이다.
   * 출력 모듈의 범위는 design이 정한다(GD-1).
3. **규칙 L-3 READS = 실제 읽기**
   * 판정: 블록 READS의 열마다 그 블록 함수(그리고 투영을 넘겨받는 같은 패키지 함수 한 단계) 안에 그 열의 실제 읽기가 있어야 한다.
   * 블랭킷 선언(`S1_READS` 등)은 펼쳐서 같은 검사를 한다. helper를 따라가지 못하면 위반(`reads_unverifiable`)이다.
   * 근거: READS는 블록 입력 판(재계산 키)이다. 안 읽는 열이 READS에 있으면 그 열이 바뀔 때 결과가 같은 블록을 다시 계산하게 된다(상위 NFR-2 위반).
4. **규칙 L-4 하위 칸 reader**
   * 대상: graph 필드 값 형식(각 패키지 값 선언 모듈의 frozen dataclass, design 40 §2.4.10 ② 목록과 같은 출처)의 칸이다.
   * 판정: 칸마다 클래스 본문 밖 엔진 코드에 속성 읽기·상수 `getattr`·레지스트리 문자열 중 하나가 있어야 한다. 없으면 출력 전용 칸 목록이나 지문 전용 칸 목록에 있어야 한다.
   * 한계(알고리즘): 이름 기반이다. 다른 클래스의 같은 이름 칸 읽기도 읽힘으로 세므로, 죽은 칸을 놓칠 수는 있어도 살아 있는 칸을 죽었다고 하지는 않는다.
5. **규칙 L-5 정본 술어 재계산 거부**
   * 등록표: {개념: (정본 필드, writer 파일, 금지 AST 패턴)}. 패턴은 AST 노드 일치로 정의한다(문자열 grep 아님).
   * 초기 개념(기본안): diode 판정(MOS gate 핀 = drain 핀 비교), 같은 VGS 묶음((kind, gate, source) 또는 (gate, source) 핀 tuple을 묶음 키로 쓰기), VGS = 0 누설 전류(VGS 0 조회). 셋째는 R3 공동분석(U-G4) 결과에 따라 등록하거나 뺀다.
   * 판정: writer 파일 밖에서 패턴이 나오면 위반이다. 등록 개념의 writer 파일이 없으면 위반이다.
   * **검증 독립성과의 관계**: 봉인이 결과를 재는 계산(잔차·정합)은 술어 재계산이 아니다. 봉인은 정본 필드를 읽고 다른 경로로 잰다. 그래서 봉인 코드에 면제를 주지 않는다. 봉인이 정본 술어 자체를 다시 만들면 위반이다.
   * 한계(알고리즘): 등록한 개념만 잡는다. 새 개념의 재계산은 리뷰와 gap 분석 몫이다(N6.3 확인에 포함).
6. **부채 목록(줄어들기만 하는 목록)**
   * 형식: 항목마다 (규칙 id, 대상, 처리 종류, card id, 사유)다. 처리 종류는 '배선 대기', '정본 읽기로 교체', '출력 전용 선언 대기', '삭제 승인 대기', '공동분석 대기' 중 하나다.
   * 판정:
     * (a) 현재 위반은 모두 목록에 있어야 한다.
     * (b) 목록 항목은 모두 지금도 위반이어야 한다. 이미 고쳐진 항목이 남아 있으면 실패다(규칙 I `test_rule_i_exemptions_are_used`와 같은 방식).
     * (c) 항목 수 ≤ 기준선 수. 기준선 수는 GC-0 측정값을 GC-1에서 상수로 박는다. 이 값을 올리는 것은 기준 약화(상위 N0.4)이고 `criteria_weakened` 보고와 사용자 승인이 필요하다.
     * (d) card id는 이 계획 또는 상위·관련 계획의 card 표에 있는 id여야 한다. 문서 대조는 검증자가 GC-V와 각 card 판정에서 한다(test가 계획 문서를 파싱하지 않는다).
   * 새 필드·새 블록에는 목록 항목을 줄 수 없다. 새 것은 처음부터 규칙 L을 통과해야 한다(만들면 배선).

### N3.3 KVL 관계 단일 정본

1. **정의 차이**(F-G5·F-G6):

   | 항목 | 쓰기 계획(엔진이 푸는 것) | S1 `s1_gvgs` |
   |---|---|---|
   | 고정 노드 F | 레일 ∪ 노드 목표(W3) ∪ 선언 입력 포트 | 레일만 |
   | 변 | MOS (gate, source), 저항, 미선언 입력 포트 '같은 DC' 변 | MOS (gate, source)만 |
   | 평행 변 | 소자마다 변, `parallel_vgs`로 분류 | 이름순 첫 소자 하나 |
   | 포트 | 미선언 입력은 '같은 DC' 변으로 루프를 닫는다(동일 가정 아래 등식) | 포트 단계별 숲, v1(포트 차)은 제약 없음 |
   | 종속 선택 | DEC-95 (3) 키 Kruskal | 이름순 숲 |
   | 층 | S0(노드 목표·입력 DC 선언은 spec 값) | S1 |
2. **정본(기본안 BD-1)**: KVL 관계의 정본은 **쓰기 계획 블록이 쓰는 S0 graph 필드**다. 기존 `device.dc_coord`·`node.dc_writer`에 더해, 종속 사이클 필드 하나를 같은 writer가 쓴다. 항목마다 (종속 소자, 분류, 사이클 멤버와 부호, 양 끝 고정 노드와 ΔV 출처, 저항 강하 원소)를 담는다.
   * 근거 1(P-1, 가장 일반적인 형태): KVL 사이클에 들어가는 원소는 MOS VGS만이 아니다. 저항 강하·노드 목표·입력 DC가 들어가고, 쓰기 계획은 그것을 모두 담는다. S1 판은 그 부분집합이라 엔진 방정식이 아니다.
   * 근거 2(층 의존성): F에 노드 목표와 입력 DC 선언이 들어가므로 사이클 집합은 spec에 의존한다. 그래서 S1 필드로는 엔진 방정식을 담을 수 없다. graph S1 필드를 쓰기 계획 정의로 일반화하면 그것은 곧 S0 블록이 되고, 종속 선택(DEC-95 (3))까지 하면 쓰기 계획과 같은 일을 한다(사본).
   * 근거 3(DEC-83): 쓰기 계획 출력도 graph 필드다. 정본이 graph 밖으로 나가지 않는다.
   * 다른 안: (나) 관계 블록(숲과 사이클)을 따로 두고 쓰기 계획이 그것을 읽는다. 종속 선택이 숲 선택과 같아서 두 블록 사이에 같은 결정이 걸린다. 모듈 분리가 필요하면 design에서 파일 분할로만 다룬다(GD-2). 사용자 선택은 U-G1이다.
3. **봉인 8**: 종속 사이클 필드를 읽고, `fixed_vgs`·`parallel_vgs`·`cycle_vgs` 모두를 행으로 낸다. 행 수 = 종속 소자 수다. 사이클이 0개인 회로에서 행 0은 '종속 소자 0'과 같은 뜻이 되어 공허 통과가 아니다.
   * 상위 472행이 적듯 봉인 8은 봉인 1·2가 통과하면 자동 성립하는 보조 게이트다. 이 계획은 그 성격을 바꾸지 않는다. 목록만 엔진이 실제로 푼 것으로 바로잡는다.
4. **같은 VGS**: 쓰기 계획의 `parallel_vgs` 판정은 `graph.gs_groups`에서 같은 묶음의 트리 소자를 찾는다. (kind, gate, source) 키를 다시 만들지 않는다(F-G13, 규칙 L-5). 판정 결과는 base와 비트 동일해야 한다(card 0 M-G1c에서 집합 일치를 먼저 잰다).
5. **삭제**(U-G3 승인 뒤): S1 `rel_kvl_branch`, `gvgs_summary`(HC-1이 `vds_saturation`을 지운 뒤 나머지), 그리고 그 둘만 쓰는 `E/graph/gvgs_cycles.py` 모듈 전체. J12-c 측정 기대(상위 DEC-64 끝)는 card 0 M-G1의 대조 기록으로 남긴다.
6. **v1 포트 차 루프**: 미선언 입력 포트끼리 '같은 DC' 변으로 닫힌 사이클은 ΔV 출처를 '같은 DC 가정'으로 기록한다. 이 계획은 동작을 바꾸지 않고 기록만 분명히 한다(X-G2).

### N3.4 KCL 관계 단일 정본

1. **정본**: KCL 관계의 정본은 `graph.dc_current_basis` 하나다. 레일이 아닌 모든 넷의 KCL을 풀었으므로 '직렬 가지 = 같은 전류'(`rel_kcl_group`)는 그 특수형이다(P-1, 가장 일반적인 형태).
2. **`rel_kcl_group`**: 소비자가 0이다. card 0 M-G2에서 묶음마다 멤버 전류가 기저 행에서 같은 선형식인지 잰다. 같으면 삭제 승인 대기(U-G3). 다르면 그 사례를 공동분석으로 올린다.
3. **DEC-17 tail 판정**: 상위 217행은 tail을 `kcl_group`으로 정의한다. 실제 DC 역할 블록이 읽는 정본(가지 등)을 card 0 M-G2b에서 확인하고, 상위 문언을 그 정본 이름으로 맞춘다(N3.10, 사실 정정).
4. **새 전류 사슬 금지**(O-10 (4)): 이 계획은 기저 밖에 전류 관계를 새로 만들지 않는다.

### N3.5 결과 검증의 독립성

1. **봉인 3 결선 대조**(기본안 BD-3):
   * θ 무관 검사다. 기저 `ends`의 원소 집합과 넷 쌍이 S1 `device.dc_nets`(잎 가지치기 원소 제외)와 같은지 실행마다 처음 한 번 확인한다. 다르면 사유 코드로 멈춘다.
   * 위치는 기저 writer 밖의 S0 검사다(작성자 자기 검사가 아니게). 방향 규칙(`_ends`)은 기저 정본 하나를 쓰고 사본을 만들지 않는다.
   * 이렇게 하면 기저 조립의 원소 누락·넷 오류를 봉인 쪽에서 잡는다.
2. **봉인 3의 성격(사실)**: 기본 경로에서 W = ID·L/IDu(DEC-88)이므로 봉인 3의 MOS 항은 ID·(IDu_forward/IDu_coord)다. 따라서 잔차는 봉인 2 불일치를 전류로 환산한 값과 같은 정보다. 이것은 결함이 아니라 DEC-88에서 나오는 성질이다(W가 KCL 전류를 흡수한다). 봉인 3이 독립 잔차를 내는 경로는 W가 ID에서 오지 않는 곳, 즉 W_request(LY3)와 실현 기하 재평가다. card 0 M-G4에서 그 경로에서 봉인 3이 실제로 도는지 확인하고, 안 돌면 해당 card(MOD8 소유)에 배선 대기로 올린다. 문언 차이는 X-G4다.
3. **공급 전류 합 판정**(기본안 BD-4): Σ 레일 전류(F-G10)를 봉인 3 보고의 한 행으로 판정한다. 허용오차는 봉인 3이 MOS 없는 행에 쓰는 부동소수 한계 식(항 수 × 기계 엡실론 × Σ|I|, `E/sizing/seal_kcl.py:58`)을 그대로 쓴다(새 상수 없음). 근거: 기저가 모든 내부 넷의 KCL을 풀면 레일 전류 합은 0이어야 한다(전하 보존). 어긋나면 원소 계수 누락이다.
4. **MNA 풀이 잔차**(GC-4): 소신호 풀이마다 상대 잔차 ‖Ax − b‖ / (‖A‖‖x‖ + ‖b‖)를 기록한다. 이 값의 판정 기준은 선언된 값이 없으므로 정하지 않는다(U-G5). 값이 유한하지 않으면 지금 규칙대로 undefined다.
5. **봉인 8**: N3.3-3.
6. **포화 부등식(G3)**: 사후 판정(봉인 7)만 있는 것은 headroom-chain 범위다. 이 계획은 다루지 않는다.

### N3.6 출발 전류(start_intervals)

1. **충돌 기록**(O-10 (4)): θ 자유 원소 전류나 기저 행으로 정해진 MOS 전류가 0 이하이면, 지금처럼 '정해지지 않음'으로 조용히 바꾸지 않는다. 출발 충돌(`StartConflict`)로 원소 이름과 값을 남긴다. 사다리·θ는 바꾸지 않는다(headroom-chain N3.1-4와 같은 관행).
2. **기저 경유**(기본안 BD-5, X-G8):
   * 자리값은 정해지지 않은 **기저 자유 원소**에만 둔다. 자리값 식은 지금 식(정해진 전류 기하평균과 W_min·IDu/L 중 큰 쪽)을 그대로 쓴다.
   * 나머지 원소 전류는 기저 행으로 계산한다. 그 결과가 0 이하이면 충돌로 기록한다.
   * 근거(P-1, KCL): 지금은 같은 기저 원소를 공유하는 직렬 소자도 서로 다른 자리값을 가질 수 있다. 그러면 면적 추정과 출발 사다리 선택이 KCL을 어긴 전류로 계산된다.
   * 자유 원소가 MOS가 아닐 때(저항·이상원)의 자리값은 design이 기존 식에서 정한다(GD-7). 새 상수는 만들지 않는다.
3. **범위 밖**: 종속 전류 구간 결합 (a)~(c)는 백로그다(O-10 (4)). 이 card는 점 값만 다룬다.
4. **순서**: headroom-chain HC-1이 같은 파일을 고친다. 그래서 GC-5는 HC-1 뒤에 병합한다(N7.2).

## N4. 13회로 적용 판정

판정은 규칙으로 한다. 회로는 library 9 + heldout 4다. 기저 단계에서 멈추는 회로(`StructureUnresolvedError` 등)는 그 사유를 그대로 남기고, 멈추기 전까지의 필드로 판정한다.

1. **무동작(계산 불변 card: GC-2·GC-3·GC-6·GC-7)**: 비교 대상은 DC 필드(노드전압·소자 op·전류), 봉인 판정(통과·거부·margin), front 지문이다. 지운 필드와 새 보고 칸(종속 사이클 행, 결선 대조, 공급 합 행)은 비교에서 빼고 따로 단언한다. 나머지는 base와 비트 동일이어야 한다.
2. **봉인 8 행 변화**: 행 집합이 바뀌는 것은 예상된 변화다(목록 교체). 판정 결과(통과·거부)는 base와 같아야 한다. 같지 않으면 원인(정의 차이 사례)을 card 0 M-G1 표와 대조해 보고한다.
3. **GC-4(MNA 잔차)**: 기록 칸만 더해진다. 판정 기준이 정해지기 전(U-G5)에는 결과가 바뀌지 않는다.
4. **GC-5(출발 전류)**: 자리값을 쓰지 않는 회로는 출발 기록이 비트 동일하다. 쓰는 회로는 바뀐 출발 칸마다 '기저 경유 자리값' 또는 '충돌' 기록이 있어야 한다. 해당 회로 수는 GC-5 착수 때 잰다(LUT가 필요해서 card 0 범위 밖).
5. 제외 목록은 검증자가 소유한다.

* **headroom-chain**:
  * HC-1이 `gvgs_summary.vds_saturation`을 지우고 S0 제약 그래프를 만든다(그 계획 FR-H9·X-6). GC-2는 HC-1 뒤에 병합해 나머지 칸과 모듈을 지운다(기본안 BD-6). 근거: 승인된 계획의 삭제 소유를 존중하고, 같은 파일(`gvgs_cycles.py`, graph test 표)의 겹침을 피한다.
