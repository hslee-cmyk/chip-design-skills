## 이 문서의 성격 (먼저 읽을 것)

* 이 문서의 수치는 전부 **"계획서에 지금 적힌 규칙을 내 코드로 옮겨 `topology.json`에 적용하면 이 값이 나온다"**는
  **기계적 산출**이다. **"이 회로가 실제로 이런 구조다"라는 회로 해석이 아니다.** 해석은 J 공동분석 소관이다.
* 대상 판본: 계획서 HEAD `7474749`("혼재 우선 규칙 일반화와 GB0 적용 범위"). 측정일 2026-09-18.
* 구현: 계획서 원문만 읽고 처음부터 작성했다(N0.4 용어집 '셀'·'소자 역할'·'입력 노드 구동 종류'·'교류접지 집합'·'가지/기둥',
  N3.1, N3.2 규칙 1~9, N3.7, DEC-59·60·63·64·70·71·76·81, N6.2 6a, N7.1, N9.1 행). 저장소 엔진 코드는 import하지 않았고,
  `review*` 자료는 **내 측정을 모두 끝낸 뒤에만** 열었다(부록 A).
* 스크립트(스크래치패드 `fresh3/`): `engine.py`(규칙 1·3·5·6, DC 역할, 구동 종류, 블록), `analysis.py`(규칙 2·4·9, DEC-63, K8,
  DEC-64, DEC-71, DEC-60), `driver.py`(읽기 변형 23종), `dcpart.py`, `sens.py`, `gvgs_sep.py`, `claim_checks.py`, `dec59.py`, `summ.py`.
  산출: `results2_<읽기>.jsonl`(회로별 append), `results3_dc.jsonl`, `results4_loop_sensitivity.jsonl`,
  `results5_gvgs_separate_rails.jsonl`, `results6_claims.jsonl`, `results7_dec59.txt`.
* **뷰**: 9회로 어디에도 `(ac_excite, sense)` metric 선언이 없어 전부 N3.2-2 **기본 전달 뷰**다. 차동 입력 6회로는 기모드 여기
  (두 입력 포트 동시 여기), 단일 입력 2회로(`common_gate_amplifier`, `pushpull_follower_buffer`)는 단일 여기.

  **루프 뷰 자체의 셀·stage 분류는 계산하지 않았다(확인 못 함).** DEC-17(L 동치류)·DEC-61(bulk)·DEC-65(출력 방향)는 **확인 못 함**.

## 0. 요약 (최우선 3건)

1. **이전 검증(review18/19)과 값이 갈렸다 — 헤드라인이 바뀐다.** review19는 "`constraints` 키가 있는 4회로 전부 GB2 L1 무정지"라고
   했지만, 내 측정(주 읽기 P0)은 **2회로**(`two_stage_ota`, `nmcnr_amplifier`)다. 갈린 곳은 두 회로다.
   * **`folded_cascode`**: 계획의 DC 역할 유도 절차로 `M8`은 **신호 소자**(review18의 DC 역할 산출물도 신호 소자)인데, review18 엔진의
     블록 구성은 `M8`에 규칙 5 바이어스 예외를 적용했다(자기 산출과 불일치). 문면대로면 `M8`이 **새 stage를 시작**하고,
     그 결과 9(c)(`M2` 블록 출력 `Vg7` = diode → 임피던스 낮음), `out` 합류 미해소(DEC-81 또는 다입력), 규칙 6 겹침이 연쇄로 나온다.
     반대로 규칙 9(c)의 diode 미러 갈래("블록은 미러 출력 소자 쪽으로 이어진다")를 규칙 5보다 먼저 적용하면 통과한다.
     **두 규칙이 같은 소자에 다른 판정을 내리고 적용 순서가 적혀 있지 않다**(S1, F1).
   * **파일럿**: 비축약 차동 뷰에서 `Voc`가 R1/R2로 신호 넷이 되고 `M37a`(DC 역할 신호 소자)가 stage를 시작한다. 9(c) 미러 갈래대로
     블록을 `Vcmfb`(diode) → `M7` → `Vx`로 이으면 끝 노드 `Vx`가 **임피던스 낮음**(J1로 `Vbias2`가 교류접지가 된 `M58`의 source)이라
     **9(c) `기록만`**이 발동하고, `Vx`/`Vy`는 차동 반쪽 블록 두 개와 CMFB 블록에 동시에 들어 **규칙 6 배타성 `review_needed`**가 난다.
     review18은 블록을 미러 입력 노드에서 멈춰 9(c)=0을 얻었다. **축약 뷰에서는 둘 다 사라진다**(S1, F2·F3).
2. **DEC-64 기대값 "파일럿 v2 4"는 계획 자신의 정의로는 5다.** `{M39, M40}`(vdd→`Voc_des`→gnd 다이오드 직렬)이 레일 병합 G_vgs에서
   기본 사이클을 만들고, 두 소자의 (gate, source)가 달라(`(Voc_des, vdd)` 대 `(gnd, Voc_des)`) v0이 아니라 **v2(레일 경유)**다.
   review18은 병합 뒤 평행 엣지를 v0으로 세어 "4 ✅"를 얻었다(정의와 다른 분류). 레일을 **병합하지 않으면** 4가 나온다 → 문장 "레일을
   병합한 고정 노드"와 기대값이 서로 다른 읽기에 서 있다(S2, F7).
3. **`ngcc_3stage_ff`가 library에 들어온 이유(DEC-81 유일 발동 회로)가 J 항목 없는 한 그룹에 달려 있다.** DC 역할 절차는 `{M8, M14}`
   (gate V1·source gnd 공유, 기준 없음)를 '구조로 못 가름'으로 올리는데 이 그룹은 J12 어디에도 없다. 잠정 신호 소자로 두면 `Vout`
   합류가 ①로 안 풀려 DEC-81 (a)가 발동하고, 바이어스로 두면 2단(`M8`)과 feedforward(`M14`)가 stage에서 사라지고 **DEC-81 발동 0**이다.
   또 용어집의 "못 가르는 그룹 4개는 전부 자기바이어스 사슬"은 이 그룹에 대해 틀린 서술이다(S2, F5).

## 2. 헤드라인 — `sizing_roles.constraints`가 있는 회로의 GB2

`constraints` **키** 보유 4회로(파일럿, `two_stage_ota`, `folded_cascode`, `nmcnr_amplifier`), 그중 **제약이 실재**하는 2회로(파일럿 7건,
`two_stage_ota` 2건. folded·nmcnr은 U-35로 `[]`).

| 기준 | P0(비축약·규칙 5 문면) | P-abs(미러 갈래가 stage 시작 셀 흡수) | P-red+abs(파일럿만 축약 뷰) |
|---|---|---|---|
| 키 기준(4) | **2** — two_stage, nmcnr | **2 + folded 미정의 1**(정지 사유 없음, `Vg9` 구동 종류만 미정) | **3 + folded 미정의 1** |
| 제약 실재 기준(2) | **1** — two_stage | **1** | **2** |
| 검증 발동(L2) 포함 | **0** | **0** | **0** |

* **L2가 0인 이유**: ratified는 J1 하나. 9회로 중 7회로가 `G_vgs v0`(DEC-64 `계산 규칙 있음`)을, 7회로가 CS stage 시작을 발동하는데
  검증 발동 회로가 0이다. 기본 CS stage 시작이 '규칙 분기'인지는 계획이 정하지 않았다(목록 정본은 6a design) — 예시 목록(v0/v1/v2
  포함)만으로 세도 two_stage·nmcnr이 v0을 발동해 0이다.
* 축약 뷰를 전 회로에 쓰면 `two_stage_ota`/`two_stage_ota_sf`는 출력 `OUT`/`vout`이 자기대응 넷(가상접지)이 되어 출력노드를 잃는다
  (J5가 걱정한 상황이 실측됨). 그래서 P-red는 파일럿에만 적용한 혼합 읽기이고, **이런 혼합은 계획에 없다**.

## 6. 결손·모순 목록

### S1 — 6a 착수 전 계획 수정
* **F1. 규칙 5와 규칙 9(c) 미러 갈래가 folded `M8`을 다르게 판정한다.** 규칙 5: "전압 구동 입력을 받는 CS = 새 gain stage 시작(DC 역할 바이어스만 예외)".
  `M8`은 그룹 `(Vg7, Vg10)`에 diode가 없어 신호 소자 → stage 시작. 규칙 9(c): "diode drain 노드(`Vg7`)는 블록 출력노드가 아니다 … 블록은 미러 출력 소자
  (`M8`) 쪽으로 이어진다". 측정: 규칙 5 먼저 → folded GB2 정지(9(c)·합류 미해소·겹침), 9(c) 먼저 → 통과(`Vg9` 미정의만).
  캐스코드 미러처럼 **diode와 출력 소자의 source가 다른 미러**에서 DC 역할 그룹 조건이 성립하지 않아 생긴다. 사이징 대상 회로의 통과/정지가 갈린다.
* **F2. 비축약 차동 뷰의 CMFB 경로가 파일럿을 정지시킨다.** `Voc`(R1/R2) → `M37a` stage 시작 → 미러 연장 → `M7` → `Vx`(낮음) → 9(c).
  계획은 "9(c) 9회로 전부 0"과 "축약 == 비축약"(규칙 8 (ii))을 함께 주장하는데 비축약에서는 둘 다 깨진다. 축약은 '계산 수단'이라 정의 뷰는 비축약이므로
  문면상 파일럿은 정지다. 어느 뷰로 DEC-59를 세는지, 미러 연장 끝이 다른 블록 내부 노드일 때의 출력노드를 정해야 한다.
* **F3. 규칙 6 배타성이 완전차동 비축약 뷰와 fan-out 구조에서 항상 발동한다**(파일럿 8쌍, ngcc 4, sf 18). 예외 규칙이 없다.
