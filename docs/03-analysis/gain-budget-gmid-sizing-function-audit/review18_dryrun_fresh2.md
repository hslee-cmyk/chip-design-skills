**이 문서의 성격 — 반드시 먼저 읽을 것**

이 보고서의 모든 수치는 **"계획서에 지금 적혀 있는 규칙을 그대로 코드로 옮겨 `topology.json`에 적용하면 이 값이
나온다"**는 **기계적 산출**이다. **"이 회로가 실제로 이런 구조다"라는 회로 해석이 아니다.** 회로 해석(J1~J13)은
사용자 공동분석 소관이고, 여기서는 규칙이 무엇을 내놓는지, 어디서 답이 갈리는지만 측정했다.

* 구현: 계획서 원문만 보고 처음부터 작성(N0.4 용어집, N3.2 규칙 1~9, N3.7, N2.1 DEC-17/34/47/59/60/62/63/64/70/71/76/81,
  N6.2, N7.1). 저장소의 엔진 코드와 `review*` 자료는 **측정을 모두 끝낸 뒤에만** 열었다(부록 A).

* 스크립트/산출: `scratchpad/fresh2/{engine,engine2,engine3,engine4,run,run2,run3,run4,run5}.py`,
  `scratchpad/fresh2/out/{results.jsonl,report.txt,report2.txt,report3.txt,report4.txt,report5.txt}` (케이스마다 append).
* 측정일 2026-09-17. 대상 `skills/analog-gmid-design/assets/library/*.topology.json` 9개(`_TEMPLATE` 제외).

## 1. 회로 × 단계 매트릭스

`통과` = 내 구현으로 정지 사유가 나오지 않음 / `정지` = `기록만`·`review_needed` 발동 / `미정의` = 규칙이 답을 정하지 않음 /
`불가` = 그 Phase의 대상(스펙·LUT·탐색)이 아직 없음.

정지를 두 층으로 나눈다. **(L1)** 규칙이 그 회로에서 직접 낸 `기록만`/`review_needed`.
**(L2)** DEC-59 "검증 발동 0 분기 정지" — 현재 `ratified`는 **J1 하나뿐**이므로 J11·J12·J13 대조표가 없는 지금은

"미구현(6a 기록, 6c부터 정지)"이라 6a 동안은 기록만 한다).

## 2. 헤드라인 — `sizing_roles.constraints`가 있는 회로의 GB2

`sizing_roles.constraints` **키**가 있는 회로는 **4개**(= '기존 4개 회로')다. 단 `folded_cascode`·`nmcnr_amplifier`는
`constraints: []`(0건)이라 **제약이 실재하는 회로는 2개**(파일럿 7건, `two_stage_ota` 2건)다. 읽기를 다 적는다.

| 읽기 | 대상 | **GB2를 L1 정지 없이 통과** |
|---|---|---|
| A: `constraints` 키 존재 | 4 (파일럿, two_stage_ota, folded, nmcnr) | **2개** — `two_stage_ota`, `nmcnr_amplifier` |
| B: 제약 ≥ 1건 | 2 (파일럿, two_stage_ota) | **1개** — `two_stage_ota` |
| A + 규칙 9(c)를 "모든 순방향 CS의 drain을 블록 출력노드로 본다"로 읽기(D-09) | 4 | **1개** — `two_stage_ota` |
| A + L2(DEC-59 검증 발동 0)까지 세기 | 4 | **0개** |

**소자 단위 정지 사유(사이징 대상 4회로, 읽기 A)**

| 회로 | 사유 | 소자·넷 |

## 5. 결손·모순 목록

### S1 — 6a 착수 전 계획 수정이 필요

**D-01. 3레일·스펙 미선언 회로의 `supplies_v` 정본이 없어 GB0가 판정 불능**
DEC-60은 "`supplies_v`는 레일 셋 이상이거나 음전위 레일 회로에서는 MG1 전에도 필수 … 없으면 GB0 로드 게이트가
거부한다"라고 적었다. 그런데 실행 `SPECS`에 `pushpull_follower_buffer`·`sf_pushpull_output_opamp` 항목 자체가 없고
(U-25 "실행 `SPECS` 이관은 DEC-60 구현 뒤"), topology의 `_paper_target_spec`은 N3.16·U-25가 "정본이 아니다"라고
못박았다.
→ **측정**: 9회로 중 **5회로**(`pushpull_follower_buffer`, `sf_pushpull_output_opamp`, `two_stage_ota_sf`,
`ngcc_3stage_ff`, `common_gate_amplifier`)가 (i)(ii)의 판정 입력이 없어 **거부도 통과도 규정되지 않는다**.
계획이 "9/9 통과"라 말할 근거는 (iii)뿐이고 (iii)은 통과만 보인다.
→ **필요한 수정**: 스펙 미선언 회로에 GB0 (i)(ii)를 "적용하지 않는다"고 명시하거나, 문서 전용 선언을 6a 한정
정본으로 승격하는 **한 줄**. (S1인 이유: 9회로 전부의 GB0 결과가 이 한 줄로 바뀐다.)

**D-04. DEC-64의 (VDS-1) 분류는 정의된 그래프에서 발동할 수 없다** *(review17 지적, HEAD에서 미해소)*
용어집: "G_vgs = **MOS gate–source 무향 엣지**와 레일을 병합한 고정 노드로 만든 DC 관계 그래프."
DEC-64 분류: "(VDS-1) **drain–source 엣지를 정확히 하나 포함**한 사이클".
→ **측정**: g–s 엣지만으로 만들면 **VDS-1 = 9회로 전부 0**이고 v0/v1/v2 기대값 4건은 전부 재현된다.
d–s 엣지를 넣으면 파일럿 v2가 4에서 크게 늘어 측정 기대값이 깨진다. 두 읽기 모두 6a 완료 조건 하나씩을 깬다.
→ N3.2-8 (vi)이 "VDS-1 계수 제출"을 6a 산출물로 요구하므로 **6a 착수 전에 닫아야 한다.**

**D-05. 끊는 점 후보 규칙이 루프를 실제로 끊지 못하는 후보를 낸다** *(review17 지적, HEAD에서 미해소)*
규칙 2: "끊는 점 = **그 루프가 지나는 CS 셀의 gate**. '루프에만 속한'으로 더 좁히지 않는다."
그런데 CS 셀이 루프를 **`source→drain` 엣지로** 지나갈 수 있고, 그때 그 셀의 gate 엣지는 루프 위에 없다.
→ **측정**: 파일럿 CMFB (3-b) 루프 4개 전부에서 후보 4개 중 1개(`M1a`의 `Vip` / `M1b`의 `Vim`)가 그런 후보다.
Miller 루프 2개에서도 같다. 후보 0인 루프는 없으므로 정지가 아니라 **조용히 틀린 뷰를 만든다**(더 나쁘다).
→ **필요한 수정**: "그 CS 셀의 **gate 엣지가 루프 위에 있을 때만** 후보"라는 한정 한 줄.

**D-07. 이득 블록 출력노드와 버퍼 블록 노드 집합이 겹쳐 규칙 6의 배타성이 깨진다(`sf_pushpull_output_opamp`)**
DEC-63의 `u`는 "입력 포트 또는 **이득 블록 출력노드**"다. `M17`/`M20`이 규칙 5로 이득 블록을 시작하면
`N17`/`N20`이 `u` 자격을 얻어 묶음이 3개가 되고, `{Y; N17, N20, vout}` ⊃ `{N17; vout}`이라 노드 집합이 겹친다.
규칙 6은 "블록 노드 집합은 서로 겹치지 않는다 … 겹치면 `review_needed`"라 했다.
→ **측정**: J12-a 기대는 묶음 **1개**, 내 산출은 **3개**(겹침 2건).
→ 뿌리는 D-08이다. DEC-63에 "R(u)끼리 겹치면 큰 쪽만 남긴다" 같은 해소 규칙이 없다.

**D-08. DC 역할(바이어스 전류원 / diode 기준 / 신호 소자) 유도 절차가 계획 어디에도 없다**
용어집은 "KCL·미러·`equal_vgs` 관계로 유도한다" 한 줄뿐이고, 알고리즘이 없다. 그런데 이 값이
**규칙 5의 stage 시작 예외**, **K8 측면 주입**, **DEC-65 방향별 최대 전류**, **DEC-17 tail 주인**의 입력이다.
→ **측정**: 내가 쓸 수 있는 유일한 구조 규칙(gate가 diode 넷이거나 gate 전용 미구동 넷이면 바이어스 전류원)으로는
`sf_pushpull_output_opamp`의 `M6·M8·M9·M11·M14·M16·M17·M20`이 전부 '신호 소자'가 되고 **규칙 5 예외가 한 번도
걸리지 않아 그 회로가 stage 16개로 쪼개진다.** 같은 이유로 **K8 발동이 0**이 되어 **J12-d 기본안(M17·M20 = K8)이
규칙으로 재현되지 않는다.** K2가 "`M17`~`M6`, `M20`~`M14` 공유 VGS"라 적었지만, `equal_vgs` 쌍의 상대(`M6`·`M14`)도
바이어스가 아니어서 전파가 시작되지 않는다.
→ **순환 확인**: DC 역할 = 바이어스면 → 규칙 5 예외 → `N17`이 블록 출력노드가 아님 → K8 성립.
DC 역할 = 신호면 → 블록 출력노드가 됨 → K8의 "k가 어떤 이득 블록의 출력노드도 아니다"가 깨짐. **둘 다 자기정합적**이라
규칙만으로는 갈리지 않는다.
→ **필요한 수정**: DC 역할 유도 규칙을 N3.2나 6a design에 절차로 쓸 것. (이것 하나가 D-07·D-13의 뿌리다.)

**D-09. 규칙 9(c)의 "블록 출력노드"를 블록 없이 판정하라는 문장이 자기모순이다**
규칙 9(c): "CS로 시작하지만 **출력노드** 임피던스 등급이 낮은 블록" + "**이 판정도 블록을 입력으로 쓰지 않는다 --
순방향 경로만 쓴다**."
→ 출력노드는 규칙 6이 "stage 안에서 신호가 마지막으로 도달해 다음 stage 시작 셀의 입력 단자 또는 출력 포트로
넘어가는 노드"로 정의한다. 즉 **블록 없이는 계산할 수 없다.**
→ **측정(두 읽기)**: 읽기 A(블록을 쓰지 않고 순방향 CS의 drain을 전부 후보로) → **파일럿 5 · folded 2 · nmcnr 2 발동**
(캐스코드 source 노드 `N1a2a`·`X`·`Y`·`NodeF1` 등이 "낮음"이다 — 캐스코드 gate가 그 뷰 교류접지라 source 단자가 gm 차수다).
읽기 B(블록을 먼저 만들고 그 출력노드만) → **9회로 전부 0**. **읽기가 사이징 대상 4회로 중 3회로의 정지 여부를 가른다.**
→ **필요한 수정**: "블록을 입력으로 쓰지 않는다"가 **diode 미러 갈래에만** 걸리는 말임을 명시하거나, 9(c)를
규칙 6 뒤에 배치한다고 한 줄.

**D-13. 같은 합류 노드를 N3.7 다입력 블록과 DEC-81 (a) 복합 블록이 서로 다르게 판정하고, 우선순위가 없다**
N3.7 (a)는 "분기·합류 … 는 DEC-81의 복합 블록 묶음으로 계산한다(`계산 규칙 있음`)"이고, 같은 절 뒤쪽의
"신호 입력 단자가 서로 독립인 입력을 받는 병렬 셀은 **다입력 블록으로 `기록만`**(항상 DEC-59 정지)"이다.
"(a)를 먼저 판정한다"는 문장은 **(a) 대 (b) 측면 주입**에만 걸려 있고 다입력 블록과의 순서는 없다.
→ **측정**: **`ngcc_3stage_ff`의 `Vout`**(M7·M13·M14 합류)과 **`sf_pushpull_output_opamp`의 `Y`**(M10·M15 합류)가
**두 조건을 동시에** 만족한다. `기록만`으로 읽으면 DEC-81의 **발동 회로가 사라져** DEC-81이 library에서 영구
미검증이 되고, (a)로 읽으면 J12 ratify 뒤 계산 대상이 된다. **`ngcc_3stage_ff`는 DEC-81 분기의 발동 회로로 들어온
회로이므로**(U-34) 이 순서가 그 회로의 존재 이유를 살리거나 죽인다.
→ **덧붙여**: `Vout`의 구동 종류가 내 측정에서 **전압 구동**(배출이 gate뿐)이 아니라 **전류 구동**(배출 없음, 종단)
으로 나왔고, (a)의 합류 노드 조건 "전류 구동이거나 블록 출력노드"는 만족한다. 단 **미러 갈래를 적용하면 `M7`의
입력 `NX`가 '앞 블록 내부 노드'가 되어 합류 경로가 3개에서 2개로 줄어든다** — DEC-81 묶음 경계가 이 한 갈래로
바뀐다(J12 ratify 항목에 이 의존을 적어야 한다).
→ **필요한 수정**: "(a) 분기·합류를 다입력 블록보다 먼저 판정한다"는 한 줄.

### S2 — 한 줄 결정으로 닫히는 것

**D-06. DEC-71 기둥 열거 정의가 병렬 엣지 처리를 말하지 않는다**
"노드-단순 경로(같은 노드를 두 번 지나지 않는 경로)"로 확정했고 244(엣지-단순 trail)를 기각했다. 그런데
**같은 두 노드 사이에 소자가 여럿일 때**(파일럿 `vdd`–`Vx`의 M6/M7 등) 그 경로들을 따로 셀지 말지가 안 적혀 있다.
→ **측정**: 따로 세면 **파일럿 62**(= 정본값), 합치면 **41**. `ngcc_3stage_ff`도 **9 대 6**.
→ **필요한 수정**: "병렬 엣지(같은 두 노드 사이의 서로 다른 소자)는 서로 다른 기둥으로 센다"는 한 줄.

**D-11. 구동 종류 '상속'과 '우선순위'의 적용 순서가 없다**
용어집은 "상속·혼합으로 전류 진입이 붙은 노드도 최종 구동 종류는 위 우선순위가 가른다"고 적었지만,
상속을 먼저 하고 우선순위를 다시 적용하라는 **순서**가 없다.
→ **측정**: 상속 뒤 우선순위를 다시 적용하면 파일럿 `Voc` = **전압 구동** → 9(a) 0. 적용하지 않으면 `Voc` = 전류 구동
→ `M37a`가 **9(a) `기록만`**. 계획 본문이 예고한 값(9(a) 전부 0)은 앞의 읽기에서만 나온다.

**D-12. pass 묶음 출력 단자의 구동 종류가 규정되지 않았다**
용어집의 구동 종류 갈래는 "신호 셀 drain / 신호 셀 source / 입력 포트 / 앞 stage 출력노드"뿐이고, pass 묶음은
"2단자 통과 경로라 방향이 없다"고 따로 규정돼 있다.
→ **측정**: 파일럿 `Vg15`·`Vg25`가 **어느 갈래에도 안 들어 `undefined`**. 세 읽기의 결과:
(a) 세지 않음 → `undefined` → `M15`/`M25`가 stage 판정을 못 받는다(현 상태, 정지),
(b) 문면 그대로 pass 소자의 drain 단자를 전류 진입으로 → **전류 구동** → `M15`/`M25`가 **규칙 9(a) `기록만`**,
(c) 묶음 반대편(`Vop1`/`Vom1`, 전압 구동)에서 전파 → **전압 구동** → `M15`/`M25`가 정상 stage 시작(파일럿 stage 9개).
용어집이 "신호 넷인데 구동 종류가 없는 노드가 남으면 안 된다"고 못박았으므로 (a)는 배제되어야 한다.
→ **필요한 수정**: pass 묶음을 지나 들어오는 신호의 구동 종류를 한 줄로 정할 것(기본안 (c)).

**D-14. CD 병렬 셀 합류를 N3.7 다입력 블록과 DEC-63 버퍼 묶음이 다르게 판정한다**
`pushpull_follower_buffer`의 `vout`에 `M1`(입력 `A`)·`M2`(입력 `B`)가 합류한다. 입력 넷이 서로 다르므로
N3.7 문면으로는 **다입력 블록 `기록만`**(항상 정지)이고, DEC-63으로는 R(vin) = {A, B, vout}·합류 1개라
**`계산 규칙 있음` 버퍼 블록**이다(J12-a 측정 기대와 일치).
→ **측정**: 이 회로는 DEC-59가 "CD 셀·버퍼 묶음의 검증 발동 회로"로 들여온 회로다. 다입력 블록으로 읽으면
**그 회로가 들어온 이유가 무효가 된다.**
→ **필요한 수정**: "N3.7의 병렬 셀 판정은 이득 블록에만 적용하고 버퍼 블록은 DEC-63이 판정한다"는 한 줄.

**D-16. 규칙 1 (4)의 적용 순서(고정점 여부)가 없다**
술어 조건 (0)이 신호 넷을 입력으로 쓰고 결과가 교류접지 집합을 늘려 신호 넷을 줄인다.
→ **측정**: 9회로 전부 2패스째 추가 발동 0이라 **현 library에서는 결과가 같다**. 그래도 규칙에는 적어야 한다.

### S3 — design 소관 / 문서 수치 갱신

**D-10. 계획이 인용한 실측 수치 4건이 stale하다**
(i) "파일럿 CG를 순방향 제한 없이 세면 9" → 내 값 **7**(`M57`/`M64`가 diode 제외 규칙으로 빠진다).
(ii) "`pushpull_follower_buffer`는 루프 (4) 1개로 정지한다"(DEC-59 `기록만` 구분의 근거 사례) → 확정 폐경로 정의로
재면 그 회로의 폐경로는 **0**이라 정지하지 않는다. **근거 사례를 다른 회로로 바꾸거나 사유를 바꿔야 한다.**
(iii) N6.2 6a의 "`ports`가 없는 folded·nmcnr … **5/8 회로에서만** 측정" → `ports`·`supply_nets`가 **9/9** 있어
조건문 자체가 성립하지 않는다(그리고 library는 9다).
(iv) 규칙 8의 폐경로 기대값 36/18/1/0 → 내 값 **10/9/1/0**.

**D-15. GB0가 제약 '값'의 형식을 규정하지 않는다**
파일럿 `mirror_ratio_error_mV`는 `value`가 없고 `value_from_spec`만 있다. 로드 게이트 목록에 이 형식이 없어
통과/거부가 규정되지 않는다(내 구현은 통과시켰다).

**D-17. DEC-81 "경로별 기여"가 6a 완료 조건인데 절차는 6c design이 정한다**
N6.2 6a는 "복합 블록 묶음 판정 결과와 **경로별 기여**를 제출"을 요구하고, DEC-81은 "묶음 판정의 나머지 규칙
(합류 노드 선정 절차, 묶을 블록 집합 유도, 합류 노드가 여럿일 때의 묶음 경계, **경로별 기여 기록 형식**)은
**6c design이 정한다**"고 적었다. 6a가 6c 산출을 완료 조건으로 요구한다.
→ **필요한 수정**: 6a 조건을 "합류 노드·묶음 후보 목록까지"로 낮추거나, 기록 형식만 6a로 끌어올린다.
