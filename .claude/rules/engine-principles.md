### A. 엔진의 목적과 계산 방식
1. **물리 정합이 먼저, 그다음 gm/ID 손계산 (O-200).** 물리 정합이 최우선이다 -- 물리적으로 말이 안 되는 안은 계산이 아무리 쉬워도 고르지 않고, 물리 경계를 수치 분해능·판정 허용오차로 정하지 않는다. '손계산'은 계산량을 아끼라는 비교 기준이 아니라 계산 방식이다: 엔진은 SPICE를 다시 만드는 것이 아니라 gm/ID 방법론을 손계산 수준의 빠르기로 구현한다(불필요하게 SPICE식 정풀이를 엔진에 넣지 않는다). SPICE 복제가 아니라 gm/ID 손계산(LUT 조회·닫힌 식·θ 고정)으로 빠르게 최적점을 찾는다. 손계산 오차는 감수하고 SPICE(오라클)로 최종 확정한다. 무거운 계산은 피한다. 물리적으로 말이 안 되는 동작점은 무의미하다. 주파수 양(GBW·PM·극·영점)의 손계산은 LUT의 C 열(CGG·CGD·CGS·CGB·CDD·CSS)을 기본으로 쓴다 -- C를 빼는 것은 근사가 아니라 정의 위반이다(O-179).
1a. **새 문제는 gm/ID 원본의 접근법부터 (근본원칙, 사용자 지정 2026-11-08 O-270 "근본원칙 새로운 문제를 만나 방법을 찾기전에 반드시 gmid원본문서의 접근방법을 참고하고, 개선된 방법이 있을때만 그걸 사용해.").** 새 문제(출발값·바이어스점·사이징 순서·정합·L 선택 등)의 방법을 찾거나 권고·계획·design을 쓰기 전에 원본 `skills/analog-gmid-design/references/gmid_sources/`(Jespers 2010, Jespers & Murmann 2017; 회로 일반은 Razavi 2001)의 해당 접근법을 먼저 찾아 쪽 번호와 함께 근거로 붙인다. 원본 방법을 기본으로 쓰고, 다른 방법은 **원본보다 개선됨을 근거(물리·정확도·속도·엔진 제약)로 보일 때만** 쓴다 -- 그때는 원본 방법과의 비교를 함께 적는다. as-built 구조나 판정 결과에 맞춰 방법을 지어내지 않는다. 원본에 해당 접근이 없으면 '원본에 없음(찾은 범위)'을 적는다. agent 브리핑에 항상 넣는다.
2. **오차 범위 규칙 (O-173, O-178·O-179 개정).** E-0 물리 관문(KCL·KVL 자기 정합·선언 영역·실현 가능 = 오차 크기와 무관하게 fail-closed). E-1 = 엔진은 가드 없이 손계산으로 판정하고 front 점의 최종 합격은 언제나 oracle이다. 정의 동일성 관문을 먼저 두고, 활성 제약의 oracle 여유가 [0, 분해능] 밖이면 (점, metric)별 문턱 이동 Δ를 secant로 갱신해 닫는다(멈춤: 옮긴 metric의 oracle 진전 ≤ 분해능 / E-0 실현 불가 / 사용자 선언 반복 상한, 새 상수 없음). e_m(엔진 대 SPICE 수치 차 통계)은 두지 않는다. 엔진 결함 = E-0 위반·정의 위반·닫기 비수렴, 판정 뒤집힘은 기록. E-2 정밀화는 E-0 위반·손계산 꼴 천장·닫기가 바꾼 전력·면적 > 선언 bin(오차의 대가가 크다는 표지)·stall일 때만, 전·후 첫 풀이 여유·|Δ|·닫기 비용 실측이 완료 조건. **SPICE와 수치가 같은가는 판정·지적 기준이 아니다**(정의 동일성은 기준).
3. **DC/AC 분리.** 스윙·ICMR·헤드룸은 DC 양(DC 풀이), 이득·GBW·PM·잡음은 동작점 소신호.
4. **계산 틀은 질문에 맞춘다.** 설계점·탐색은 θ 고정(gm/ID), 정해진 회로를 흔드는 분석은 W·바이어스 고정 KCL.
5. **θ 기저 (O-127).** θ 독립 성분은 KVL 고리에서 종속 성분을 뺀 것.
6. **물리 정합 최우선, 가장 일반적인 형태부터.** 제한은 물리 근거가 있을 때만.

### B. 엔진 구조
7. **graph 단일 정본.** 필드마다 writer 하나, 같은 입력 → 필드 하나(G0~G7), 같은 정의 = 필드 하나(정의가 다르면 축을 적고 나눔), 재사용은 graph reuse·S3 graft만(새 cache·memo·sctx 슬롯·사본 금지), 정본 자리가 없으면 멈추고 보고. 세부는 상위 `fpga/CLAUDE.md` '★graph 단일 정본'.
8. **코드는 언제든 재작성 가능 (O-153·O-165·O-169).** as-built 엔진의 구조·자리·이름·동작은 근거·본보기·보존 대상이 **아니다**. 엔진 인용은 두 용도만: (1) 엔진 밖 사실(PDK·ngspice·LUT 값) (2) 재작성 범위(지울/바꿀 코드·소비자 목록). 자리·writer·입력·순서·판정은 원칙(정의·층·graph 규칙·물리)에서 유도한다. as-built 동작과 계획이 다르면 '계획이 틀림'이 아니라 '재작성 범위 항목'이다. 덧대서 복잡해지면 재작성. '지금 있다/승인됐다/바꾸는 비용'은 유지 근거가 아니다. **엔진 읽기를 지시하는 브리핑에는 이 용도 제한을 항상 붙인다.**
9. **만들면 배선(절대원칙).** 만든 것이 원래 경로를 대체하지 않으면 만들지 않는다. 배선이 안 되면 사용자 승인을 받는다.
10. **fail-closed.** 우회·skip·광범위 except는 타당성 검토 뒤에만.

### C. 값과 회로
11. **상수 발명 금지.** 값은 선언·PDK·LUT·spec에서 유도하고 근거를 참조한다(숫자를 박지 않는다). **PDK 이식성(O-197)**: PDK 값은 PDK가 바뀌어도 그대로 쓸 수 있어야 한다 -- 계획·design·엔진·test는 PDK 양을 역할 이름(예: MIM 최소 폭·배열 간격·감싸기, MIM 면적 밀도)으로만 쓰고, 특정 PDK의 값·규칙 번호·파일 줄은 PDK 선언(pdk_decl) 한 곳에만 둔다. PDK를 바꾸면 선언만 바꿔 동작해야 한다.
12. **일반화.** 회로·소자 이름·매직넘버를 규칙에 쓰지 않는다. 일반성은 library·heldout 회로 전수로 잰다(n/N).
13. **논문 값 그대로 인용 금지.** 확정 값은 사용자 지정분만.
14. **회로 해석은 연결과 원문만으로.** analog-grammar 태그는 근거가 아니다. 원문은 `assets/{library,heldout}/sources/`(쪽 + 로컬 PDF 경로).
15. **topology connectivity는 사용자만 수정.** 정정은 대기열(`wt/_drafts/topology_correction_queue.md`)에 쌓았다가 "한꺼번에 반영" 지시 때 일괄, 정해진 반영 시점은 지킨다.
16. **held-out 회로는 spec 조정에 쓰지 않는다** (DEC-98, U-75·U-76).
