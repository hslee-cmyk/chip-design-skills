# 보고 5묶음 (원칙 26)

> 정본. 2026-11-12 CLAUDE.md 개정(docs/01-plan/features/claude-md-restructure.plan.md)으로 옛 CLAUDE.md 원문을 그대로 옮겼다(의미 변경 0).
> ask_gate 파서(`.claude/hooks/ask_gate_rules.py`)는 아래 `26. ` 줄과 하위 목록을 그대로 읽는다 — 형식을 바꾸면 게이트가 따른다.

26. **보고 5묶음** -- 권고·결정 질문이 들어가는 모든 보고에 다섯 묶음을 다 담는다. 표의 칸은 '실측(경로)'·'agent 인용'·'해당 없음(근거)' 중 하나다. **'안 함'이 있으면 묻기 전에 먼저 확인한다.** 확인 전 사실은 'agent 인용'으로 표지하고 근거로 쓰지 않는다.
    1. **bkit 단계표**: 계획 | design | 검증 | 승인 | test | code | 구현 gap | 감사. 안 한 단계는 '안 함', 순서 위반은 '순서 위반'으로 적는다.
    2. **단계별 점검표**: graph 단일 정본 / G-10 블록 재계산 / 블록 안 재계산(cProfile·중복 인자) / 새 필드 소비자(≥ 1 또는 출력 전용 선언) / 구조·파일 분할(tests/structure) / 회로 이름 0 / fail-closed / 상수 발명 0 / DC·AC 분리 / 계획 먼저 / 작성자 ≠ 검증자 / 일반성 n/N / 만들면 배선. 코드 변경이 없는 항목은 '해당 없음(근거)'.
    3. **원래 취지와 다름**: 바뀌는 결정·문언 목록. 없으면 '없음'이라고 적는다.
    4. **권고 실측 출처**: 내가 직접 잰 것과 agent 결과 인용을 나눠 경로와 함께 적는다.
    5. **권고 확인표 10항목**(권고마다): ① 지적 사실 직접 재확인(원 파일·계획 기본 규칙(DEC)·엔진 기본값, 원칙 22) ② 계획 전체 grep ③ 원칙 전수 ④ 대안 비교표 + ⚠ ⑤ 실현 가능성 실측 ⑥ 열린 결정 상호작용·design 영향 ⑦ 원래 취지 ⑧ 원문 쪽 + 로컬 PDF ⑨ 물리·회로이론 검증(원칙 21, O-171) ⑩ 결정 간 모순 점검(원칙 20, O-209 -- 권고안이 새 결정·기존 결정(O·DEC·U)과 모순되지 않는지 권고 작성자가 아닌 점검자가 전수 대조한 기록. 이 칸은 해당 없음·agent 인용만으로 둘 수 없고 점검 기록 경로를 실측(경로)로 적는다. 모순이 남은 안은 권고하지 않는다).
